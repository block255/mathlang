# 围栏与整体 —— 两个概念必须切割

> **2026-10-24 定。** 触发线：B2 实测（数学段里的中文比正文笔画细）→「文本为什么会被判进数学结构」
> → 一路问到底：「每个符号是不是该在自己的 `$` 围栏里」→「在 β 与 μ 之间打一个加号，源码变成什么」
> →「那不就变成多项式是一个整体了吗」。
> **结论：要切割。** 围栏（`$…$`）是**排版上下文 + 存储记账**；整体（对象）是**编辑语义的单位**。
> 它俩现在混着，混着的地方就是 B2 的病灶。

---

## 一、两个概念

| | **围栏** `$…$` / `$$…$$` | **整体（对象）** |
|---|---|---|
| 本质 | **排版上下文**的边界 ＋ 存储序列化的记账 | **编辑语义**的单位：一个原子 |
| 谁读它 | `Math.tex`（渲染）· md 文件 · AI · 导出 | `caret_sites` / `visible_atoms` / `smart_delete` / `hit_map` / `selection_range` |
| 粒度 | 一段（n 个原子） | 一个原子（一个字形 ＋ 它挂的上下标/参数） |
| 会不会变 | 随上下文变（中文进出时） | 只随内容变 |
| 用户看得见吗 | 看不见（除非主动打开源码视图） | 看得见：光标停在哪、选中了什么 |

**平权（《整体设计》§三 第 0 条）要求的是"整体"这一列恒等于"一个原子"**，
它**从来没有**说"一段围栏 = 一个整体"。

⇒ `$\alpha\beta+\mu\varepsilon\theta$` 里是 **1 个围栏、6 个整体**（原子的数目），两列各说各的，不矛盾。

---

## 二、判据（写给以后的我 / 下一个会话 / AI）

> **围栏只允许出现在两个位置：渲染上下文的边界、存储序列化的边界。**
> **任何"决定一个字符归谁"、"决定什么是对象"的地方，都不许读围栏。**

按这条回头看 B2，一句话就能定性：`_commitText` 里**没有任何地方该知道围栏**，
可事实上它由"落点是否在围栏内"决定了字符归属 ⇒ 泄漏。

★ 附带一条等价性口径：`$\alpha\beta$` 与 `$\alpha$$\beta$` **不**等价（排版上下文、widget 数、导出形态都不同），
但**编辑行为必须等价**（同样的原子、位点、删除、选择）。
**平权要求等价的是语义，不是存储。**

---

## 三、概念混着的危害（每条都点名现象或代码）

1. **字符归属被围栏决定 ⇒ 字体跟着变（B2 本体）**
   光标在 `$…$` 里打汉字 ⇒ 汉字被追加进 tex ⇒ 由 `Math.tex` 的字体链渲染
   ⇒ 与正文不是一套字体、字重更细。用户视角是"同一行里两种字"，实现视角是"两个渲染器"。
   ★ 而且它不是"判错"，是**根本没有判据**（打字路径上没有按字符类型分流的规则）。

2. **手感随一个看不见的边界变化**
   同一串按键，落在段里和落在文本里效果不同：
   段里打 `+` ⇒ 进 tex（渲染）；文本里打 `+` ⇒ 纯字符（不渲染）。
   用户无法预测"下一个 `+` 会变成什么"—— 因为判据不在他能看见的东西上。

3. **围栏一动，文档语义就动（做"开段"之后更危险）**
   一旦按证据自动开/合段，每多插一对 `$` 都可能改变位点序列、选择单位、删除行为、命中盒
   ⇒ 一次判据变更牵连整个编辑语义（本仓已有先例：`Alt+=` 空壳被"平权"否掉）。

4. **跨工具往返两套理解**
   外部工具（与我们的切段器）按 `$…$` 读成 n 个数学段；我们内部按"原子"读。
   两套理解同时存在时，"这段文字是什么"没有唯一答案（`块模型与md往返.md` 的 R2–R4 就是栽在这类模糊上）。

5. **"整体"事实上没有定义，只在复制出口打补丁**
   现在唯一需要"把一段当一个整体"的地方只有 **复制/剪切**（`clipboardSlice` 补 `$…$`、
   括号配平、结构参数补全）。这说明"整体"并没有被建模，只是在出口补。
   ⇒ 切割之后这一处**保留**，但要说清它的语义是"源码的最小自洽单位"，不是"对象"。

6. **守卫失去抓手**
   一个行为到底属于"围栏"还是"原子"，测试写不出稳定期望。
   本仓已经因为"两份判据打架"栽过两次（`smart_wrap` 自己扫 `$` vs `math_spans`；
   `leaf_pairing` 的盒 ↔ 原子错位）。判据混着，守卫就只能钉住现象而不是语义。

## 四、落点：哪些切干净了、哪些还要切、哪些保留

### 4.1 ✅ 已经切干净（围栏不参与）

| 行为 | 实现 |
|---|---|
| 位点 | `caret_sites`：`\alpha|\beta|\mu` 之间各有位点 |
| 删除 | `smart_delete`：按原子删（删空留壳 / 整块回收） |
| 选择 | 乙口径：双击 = 字形 ＋ 它挂的上下标 |
| 命中 | `hit_map` + `leaf_pairing`：点哪个符号落哪个偏移 |
| 剪贴板 | `clipboardSlice`：按原子边界配平 |

### 4.2 ⬜ 还要切（本批之后的活）

| 泄漏点 | 现状 | 目标 |
|---|---|---|
| **打字归属**（步 1） | 光标在围栏里 ⇒ 打的字一律进 tex（汉字也进） | 归属由**字符类型**决定：中文 / 全角标点 = **断点**；围栏不参与 |
| **证据开段**（步 2，待定） | 打字**完全不建**数学上下文（打 `a+b` 就是纯文本） | 打**强证据**（`\命令` / `^` `_` / 关系符）⇒ 若旁边没有上下文就开一个 |

### 4.3 ✅ 保留（这是围栏的本职，不是泄漏）

| 位置 | 为什么保留 |
|---|---|
| "公式之前 / 之后"两个位点 | 进入 / 离开这个排版的唯一入口 |
| 复制 / 剪切出口补 `$…$` | 源码的最小自洽单位（存储层语义） |
| 行间块 `$$…$$` 是一个**块** | 它是**用户造出来的块**，不是围栏泄漏；平权原文就把"一整段行间公式"列为同一层原子之一 |

## 五、实测数据（2026-10-24，探针；用完即删）

### 5.1 打字（走**真实平台文本通道**，逐字符，与敲键盘同一条路）

| 输入 | 结果 |
|---|---|
| `$\alpha\beta\mu\varepsilon\theta$` 的 β\|μ 打 `+` | `$\alpha\beta+\mu\varepsilon\theta$`（**围栏不变**，就插了一个字符） |
| 纯文本 `当ab时` 的 a\|b 打 `+` | `当a+b时`（**不开上下文**） |
| 空文档打 `a+b-c` | `a+b-c`（纯文本，不建公式、不切段） |
| 空文档打 `当a+b` | `当a+b`（纯文本） |
| `$a+b$` **里**打 `都` | `$a+都b$` ← **B2 的来源** |
| `$a+b$` **之后**打 `都` | `$a+b$都`（落文本层 ✓） |

⇒ **打字路径上没有任何"按字符类型分流"的机制**（`_commitText` = 自动展开 → 守门人 → 插入）。
"切割"只存在于另外两条路：**粘贴/导入**（`planSmartWrap`）与**行内公式里按 Enter**（`_splitInlineMathOnEnter`）。

### 5.2 切段器的证据表（`planSmartWrap`，与粘贴共用同一份判据）

| 输入 | 判断 |
|---|---|
| `a+b` | **不包** ⇒ 运算符**不是**证据 |
| `加减乘除 加减 都在这里` | 不包 |
| `DeepSeek 的 PDF 和 Ctrl 键` | 不包 ⇒ 纯英文单词绝不包 |
| `那么当a+b大于0时，有` | 不包 |
| `a^2+b` | 包 ⇒ `$a^2+b$`（`^` 是证据） |
| `\alpha\beta` | 包 ⇒ `$\alpha\beta$`（`\命令` 是证据） |
| `x=1` | 包，且因"整行只有这个式子"升级成行间块 |
| `那么当a+b>0时，有 \forall` | 包 **2** 处 ⇒ `那么当$a+b>0$时，有 $\forall$` |

⇒ **判据从来不是"字母算不算数学"**，而是"**强证据 ＋ 连续数学字符 run**"。
一个字母永远不会自己开段；运算符连开段的资格都没有。

## 六、本批（批 4）要做什么

### 6.1 批 4a —— **不带行为变更**，可独立验收（建议先做）

| 项 | 做法 | 验收 |
|---|---|---|
| **C1 行内分式加大** | 行内（`MathStyle.text`）`\frac` 在**渲染期**换成 `\dfrac`（源码不动），偏移同步映射并在 `injection_map` 登记那 1 个字符 | 行内分子分母 15 → 21 px；行间块不变；点得动 |
| **C2 空绝对值竖线** | 空 `\left|{}\right|` 目前**没有占位垫** ⇒ 竖线按最小尺寸（y = −3.1..16.9），而 CJK 是 0..20 ⇒ 看着"矮一截、浮上去"。先探明位点表里有没有内容槽：有 ⇒ 注占位垫；没有 ⇒ 抬"空定界符"的最小高度到当地行盒 | 空竖线与有内容的竖线同高；空槽有落点 |
| **B2 渲染层（兜底）** | 数学段里的裸中文用**与正文同一套字体**渲染 | 同一行里中文字重一致；导入的历史文档也不"细"了 |

> C1 的"中间档"（0.81，行高只 +18%）**不可用**：只能靠 `{\large\frac…}` 这种 hack，
> 而 `\large` 不在结构命令表里 ⇒ 会多出幻影原子 ⇒ 命中表判死（本仓踩过四次）。⇒ 走 `\dfrac`（1.0 档，行高 +68%）。

### 6.2 批 4b —— **新增行为**：步 1「中文 = 断点」

在数学上下文里打**中文 / 全角标点** ⇒ 上下文在这里结束，字符落到文本层（`\text{…}` 参数里打中文**照旧留下**）。
要先给出四条边界情形的对照表再动代码：

1. 行内公式里打中文（光标在原子之间）；
2. `\text{…}` 参数里打中文；
3. 行间块 `$$…$$` 里打中文（关块另起一段？待定）；
4. 选区替换命中中文时。

### 6.3 批 4c —— **待定**：步 2「证据开段」

口径（已讨论，未拍板）：

- **只有强证据能开段**：`\命令`（含面板插入）· `^` `_` `/`（这三个已经是 auto-expand 入口）· **关系符**（`= < > ≤ ≥ ≠`）
- **运算符（`+ - × ÷`）不算证据** —— 它们不能开段，只能留在已开的段里
- **关系符开段需要两侧都有数学字符**（`a+b>0` ✓；`价格 > 100` ✗）
- **打字时只开行内，绝不自动升级成行间块**（升级只在粘贴/导入或用户按 Enter 时发生）
