# 数语引擎 · 块模型与 md 往返规则（v0.2，2026-10-14 · S2-1 定稿）

> **定位**：S2 的地基。`lib/core` 只是这份规则的直译；R0–R8 每一条都对应一条单元测试。
> **上游**：`整体设计.md` 原则 1/3、§七分页模型；`技术选型与风险.md` 4.0（文字流内数学）。
> ⚠️ **本文取代** `整体设计.md` §六 的旧草案（"块对象树 + inline 数组"）—— 那个草案会引入一份与缓冲区并存的树，等于把 4.0 架构的好处还回去一半。

## 〇、v0.2 修订要点（2026-10-14 与用户逐条讨论后）

1. **R1 修正**：v0.1 写"空行是硬边界"是**错的** —— 空行只在块**外**是边界；`$$` / 代码块**内部**的空行是内容。→ 块边界**不是一个规则清单，而是一个状态机**。
2. **`Enter` 语义定为 A（空行分段）**：`Enter` = 新块（写入 `\n\n`），`Shift+Enter` = 块内硬换行（行尾写两个空格）。
   理由：md 会把连续行**合并成一个段落**，"什么都不写"的直接后果是**往返坏掉**（我们看到的 ≠ Typora 打开的）。
3. **FlowUnit 粒度修正**：v0.1 把"段落 / 引用"整块当 1 个 FlowUnit → 多硬换行的段落必然超页、天天弹告警。→ 改为**按源行拆**。
4. **有序列表编号**：写入**真实序号** `1. 2. 3.`（人 / AI 读文件自然），插入删除后**在提交点重排**。

## 一、一句话

**真相只有一条 md 字符串；「块」不是第二份数据，而是这条字符串上的「行区间视图」。**

## 二、三层（+ 页）结构

```
L0 真相   buf : String                        ← 唯一事实来源（md + LaTeX 源）；编辑只改它
L1 行     line[i] = [start, end)              ← 按 '\n' 切，纯函数
L2 块     blk[k] = { type, lineFrom, lineTo } ← 相邻行按 §四 规则合并；type 由行首标记推断
L3 页     page[j] = { flowFrom, flowTo, y }   ← 按 FlowUnit 高度贪心装箱（S2-4）
```

**五条铁律**

1. **只有 L0 可写**；L1 / L2 / L3 都是**纯函数派生 + 缓存**，任何时刻都能从 L0 完整重建。
2. **行首标记的唯一真相也在 L0 里**（`# `、`- `、`$$`）—— UI 改块类型 = 改这一行的行首标记。
3. **往返无损是自动的**：没有第二个模型，就不存在"序列化走样"。
4. **失效范围最小**：改哪个行区间，就只失效哪些行 / 哪些块（这是"打字只重绘一个公式"能成立的根据）。
5. ★ **任何环节都不得 trim 行尾空格**（R8 的硬换行标记就是两个尾随空格；trim 一次就把用户的硬换行全吃掉）。

## 三、块类型与往返规则（唯一真相表）

| 块类型 | L0 里的写法 | 用户怎么产生 | 往返 |
|---|---|---|---|
| 正文段落 | 连续非空行，无行首标记 | 直接打字 | 无损 |
| 标题 1/2/3 | 行首 `# ` / `## ` / `### ` | `Ctrl+1/2/3` | 无损 |
| 无序列表项 | 行首 `- ` | `Ctrl+Shift+8` | 无损 |
| 有序列表项 | 行首 `1. ` `2. ` … | `Ctrl+Shift+7` | 无损 |
| 引用 | 行首 `> ` | `Ctrl+Shift+9` | 无损 |
| 代码块 | 单行 ` ``` ` 围栏包围 | `Ctrl+Alt+C` | 无损 |
| **行间公式（单行）** | `$$` + 一行 + `$$` | `Ctrl+Alt+E` | 无损 |
| **行间公式（多行环境）** | `$$` 内包 `\begin{aligned}` … | 面板模板 | 无损 |
| 分隔线 | 单行 `---` | 插入菜单 | 无损 |
| **手动分页符** | 单行 `<!-- pagebreak -->` | `Ctrl+Enter` | 无损（**各 md 工具渲染时不可见**） |

**为什么把行首标记留在 L0**：它让"用户不写标记"（原则 3）与"存储是标准 md"（原则 1）**同时成立**——用户只按快捷键 / 菜单，标记由软件写入；但文件丢进任何 md 工具都能正确显示。

## 四、块边界规则（R0–R8 · 定稿）

> ★ **块边界不是"规则清单"，而是状态机**：只有状态处于「段落 / 列表 / 引用」时，空行才构成边界；
> 一旦进入 `$$` 或代码块状态，**直到配对结束符之前，一律不看边界规则**（否则公式里的空行会把公式切成两块）。

| # | 规则 | 内容 |
|---|---|---|
| **R0** | 归一化（**仅导入时**） | 剥 UTF-8 BOM；`\r\n` / `\r` → `\n`。**此外一个字符都不改**（不重排、不美化、不 trim） |
| **R1** | 空行 | **仅在「段落 / 列表 / 引用」状态下**是块边界；`$$` 与代码块**内部不算** |
| **R2** | 标题 | 行首 `#`…`######` + 空格 → 单行成块（4–6 级按 3 级渲染）；**可打断段落**（前一行非空也是边界） |
| **R3** | 段落 | 连续满足「非空 + 无行首标记 + 不在围栏内」的行 → 一个段落块。块内的单个 `\n` 是**软换行**（渲染成空格） |
| **R4** | 列表 | 连续 `- ` / `n. ` 行 → 一个列表块；**列表项**内可含**续行**（缩进 ≥2 空格且不是新标记）；**项之间不空行**；v1 只支持一层嵌套 |
| **R5** | 公式块 | `$$` 行 → 配对 `$$` 行（含两端）；**同行闭合**（`$$x=1$$`）也算一块；**未闭合 → 吞到文末** |
| **R6** | 代码块 | ` ``` ` 围栏 → 配对围栏；未闭合同 R5 |
| **R7** | 分页符 / 分隔线 | 单行成块；分页符**不占高度 + 强制换页**；两者**都可打断段落** |
| **R8** | 硬换行标记 | 行尾**两个空格**（或 `\`）→ 与下一行同块但**必须真换行**。★ **不得 trim 行尾空格** |

**输出侧写入约定**（用户按一个键 → 往 L0 写什么；这是 R2–R4 在"我们自己的文件"上的具体化）

| 用户动作 | 写入 L0 |
|---|---|
| `Enter` 新块 | `\n\n`（块间**空一行**） |
| `Shift+Enter` 块内硬换行 | 行尾 `  `（两个空格）+ `\n` |
| 新列表项 | `\n`（**不加空行**，否则 md 变成"松散列表"，段间距会变） |
| 切换块类型 | 只改这一行的**行首标记** |
| 插入结构（面板点「分式」） | 插入 `\frac{}{}`（**连花括号一起写**），光标移进第一个槽 |

**几个容易忽略的推论**

- **多个连续空行 = 一个边界**，不产生空块。
- **未闭合的 `$$` / 围栏**在**打字过程中**是常态 → 告警**只在提交点跑**（失焦 / 光标离开 / 粘贴完成），否则用户刚敲下 `$$` 就被红字骂。
- 导入遇到我们不认识的结构（表格 `| a | b |`、4 空格缩进代码、`> >` 嵌套引用）→ **原样保留成普通文字** + 进「问题清单」，**绝不丢内容**（原则 5）。
- **已知偏离**：不支持 setext 标题（`标题` + 下一行 `===` / `---`）与缩进代码块；`---` 一律按**分隔线**处理。我们**产出永不生成**这两种写法。

## 五、分页单元（FlowUnit）—— 块是「语义」，FlowUnit 是「不可再分」

> `整体设计.md` §七 原话是"块是原子，不允许被切成两半"。对**长列表**这会变成"一项超一页就无解"，
> 对**多硬换行段落**会变成"必然超页、天天告警"，所以把两个概念拆开：**块**是语义单位，**FlowUnit** 才是分页原子。

| 块类型 | 拆出的 FlowUnit | 为什么是这个粒度 |
|---|---|---|
| 标题 / 公式块 / 代码块 / 分隔线 | 整块 = **1 个**，**不切**；超页 → 溢出告警 | 切在公式中间是灾难 |
| **段落** | **每个源行 = 1 个** | 长段落 / 多硬换行段落要能自然跨页 |
| **引用** | **每个源行 = 1 个** | 同上 |
| **列表块** | **每个列表项 = 1 个**（含其续行） | 列表项是一体的，且通常不长 |
| 分页符 | 特殊：**强制换页**，自身不占高度 | — |

切在**源行边界**上，视觉上就是正常的换行位置，用户不会觉得被"切断"。

**分页算法（S2-4 实现）**：按 FlowUnit 顺序累加高度，超过页内容高 → 开新页；FlowUnit 自身高于一页 → **黄色溢出告警，不切断**（原则 5：静默失败必须可见）。

## 六、编辑操作 → 失效范围（这是"打字只重绘一个公式"的根据）

| 操作 | L0 改动 | 失效范围 |
|---|---|---|
| 段落内插入 / 删除一个字符 | 该行的一个区间 | 该行 + **所在块**重解析 + 该块重新测量 → **只重绘该块** |
| 回车拆块 | 插入 `\n\n` | 该行 + 该块 |
| 切换块类型 | 改 / 加 / 删**行首标记** | 该行 + 该块 |
| 面板插入结构（点「分式」） | 插入 `\frac{}{}` | 该行 + 该块 |
| **列表项增删 / 移动** | 行首序号 | 该列表块 → **重排序号**（normalize，提交点跑） |
| 插入 / 删除分页符 | 增删一整行 | 该块 + **其后所有页重算分页**（只在明确动作时发生，代价可接受） |

★ **normalize 的边界**（对齐《技术选型与风险.md》5.1 提交规则）：列表序号重排、未闭合 `$$` 报警、空 `{}` 回收 —— **一律只在提交点跑**（失焦 / 光标离开 / 粘贴完成 / 明确动作），**绝不逐击键跑**。

★★ **S2-4 的硬约束（由 §八-2 实测确定，不是偏好）**：
每一个 FlowUnit 的 widget **必须按「位置」缓存复用**（源文本没变 → 复用同一 widget 实例）。
否则每次 `setState` 都会重建 + 重排整篇：N=25 时**空帧就要 91 ms**（缓存后 2.8 ms，**32×**）。
缓存分桶的键必须是**位置**（如 `tag/i`），**不能跨容器复用同一实例** ——
flutter_math_fork 的 `Math` 内部有被记忆化的 `Line(key: GlobalKey)`，同一实例放两处会直接抛
`Multiple widgets used the same GlobalKey`。

## 七、S2 明确不做

1. **行内富文本**（`**粗体**` / `*斜体*` / 链接）：S2 段落先**把标记原样当文字渲染**，留到后续阶段。
2. 列表嵌套 > 1 层、表格块、图片块。
3. `aligned` / `matrix` / `cases` **内部**编辑 —— 那是 S3；**S2 只保证整块正确测量、可翻页、不被切断**。
4. 撤销栈的持久化（S2 只在内存内做撤销）。

## 八、待验证（交给 S2-2 / S2-3 实验）

1. ✅ **已实测通过（2026-10-14 · 见《技术选型与风险.md》§十一）**：
   `Text.rich` + `WidgetSpan(alignment: PlaceholderAlignment.baseline)` **一行代码同时解决**了
   「自动折行 + `$...$` 不被拆开 + 基线对齐」—— 18/18 个公式完整落在单行盒内，高结构只让行高 **+1.5 px**。
   → **S5 的折行只剩"超长单公式"这一件事**（实测宽 750 px > A4 内容区 657.6 px 时横向溢出）。
2. ✅ **已验证（2026-10-14 · 见《技术选型与风险.md》§十二）**：
   **`Offstage` 离屏测量与真实渲染的高度完全一致（0.000 px，25/25）**，两者成本也基本相同
   → 分页**不需要"先测量一趟、再渲染一趟"**，直接**"渲染即测量"**。
   而真正的瓶颈是"**每次 setState 重建整篇**"（空帧就要 91 ms，N=25）
   → **必须做单元级 widget 缓存**（按位置分桶），空帧降到 2.8 ms、增量降到 12.4 ms。
3. **"打字只重绘该块"是否真的只重绘**（用 S1 的 8 ms/帧 探针做回归）。
