# 数语引擎 · S2 实验结论汇总（2026-10-14 定稿）

> **状态（2026-10-25）**：**历史实验记录**（S2 地基证据），不是现行规格；现行规格/待办见 [`../README.md`](../README.md)。

> **一句话结论**：**S2「A4 页面与分页」四个子步全部完成** —— 真相是一条 md 字符串、块是它的行区间视图；
> 渲染投影用 `Text.rich` + `WidgetSpan`（**换行与基线对齐是免费的**）；分页 = 离屏测量 + 贪心装箱；
> 而**打字不掉帧的关键是「单元级 widget 缓存」**。
>
> 本文是**给 S3 用的决策摘要**：只留「结论 + 由实验直接确定的约束 + 代码地图」。
> 证据细节见《技术选型与风险.md》§十一 / §十二；过程记录见《开发日志/2026-10-14S2页面与分页.md》。

## 一、四步的结论

| 步 | 做了什么 | 结论 |
|---|---|---|
| **S2-1 块模型与 md 往返** | 定 R0–R8；落 `lib/core` | 真相 = 一条 md 字符串，**块 = 行区间视图**（不是第二份数据结构）→ **往返无损是结构性保证**，不靠转换代码 |
| **S2-2 行内投影** | 落 `lib/render`；实测折行与基线 | ★ **自动折行 + `$...$` 不被拆开 + 基线对齐，一行代码同时解决**；18/18 个公式完整落在单行盒内；高结构只让行高 +1.5 px |
| **S2-3 分页成本** | 三方案对比 → widget 测试 | ★ **瓶颈不是"选哪种测量方案"，而是"每次 `setState` 重建整篇"**；★ **单元级 widget 缓存**把空帧 91 → 2.8 ms（**32×**） |
| **S2-4 A4 分页** | `lib/layout` + `lib/editor` | 真文档 22 块 / 23 流单元 → **自动分 4 页**；分页符、超页告警、页眉、字号全部跑通 |

## 二、★ 硬约束（都是实测出来的，不是偏好）

1. **单元级 widget 缓存**：每个 FlowUnit 的 widget **按位置池化**；源没变 → 复用**同一实例** → `Element.updateChild` 整棵子树跳过。
   不做的话每次 `setState` 都重建整篇（N=25 空帧 **91 ms**）。
2. **测量树与渲染树各用各的池**：共用一个池会让两棵树互相挤掉对方的实例 → 两边每帧都全量重建。
3. **同一个 widget 实例绝不能同时出现在树的两个位置** —— flutter_math_fork 会把 `Line(key: GlobalKey)` **记忆化**
   （`syntax_tree.dart:547/563`），同一实例放两处直接抛 `Multiple widgets used the same GlobalKey`。
4. **分页不需要"先测量一趟、再渲染一趟"**：`Offstage` 测出的高度与真实渲染**完全一致（0.000 px，25/25）**，成本也相同
   → **渲染即测量**。
5. **超页的块不切断**：高于一页的 FlowUnit **单独占一页** + **页下黄色告警**（原则 5：静默失败必须可见），告警文案带具体高度。
6. **块间距挂在"块第一个 FlowUnit"的 `leadingGap` 上**，且**在页首丢弃**（与 Word 一致）。
7. **不得 trim 行尾空格**（硬换行标记就是两个尾随空格）；`$$` / 代码块**内部**的空行不是块边界。
8. **页面几何**：A4 210×297mm、边距上下 20 / 左右 18mm → 内容区 **657.6 × 971.3 px**
   （1mm = 96/25.4 px）；**页眉占用正文高度**（`bodyHeight = contentHeight − headerHeight`）。
9. **打字时序**：第 N 帧文字**立刻**显示（新内容已在缓冲里）、第 N+1 帧页边界落定 → **打字零延迟、分页晚一帧**。

## 三、性能账（widget test · debug VM · 一整帧）

| 场景 | 数值 |
|---|---|
| 空帧（什么都不改，N=25） | 缓存关 **91 ms** → 缓存开 **2.8 ms** |
| 打字（只改 1 个单元，N=25） | 缓存关 89 ms → 缓存开 **12.4 ms**（release 通常再快 2–3.5×） |
| 空帧 N=100 | **6.1 ms**（O(1)，与文档长度基本无关） |
| 冷布局（新元素，N=25 / N=100） | ≈ 43 / 159 ms（**打开文档时一次性**） |
| 单公式重绘（S1 实测，release） | **8 ms/帧** |

> ⚠️ 冷布局那几个数在多次跑之间**抖动较大**（114 / 130 / 162 ms 都出现过，因同跑的测试不同）；
> **缓存开的数很稳**（2.8–7.3 / 12.4 ms），而它们才是决策依据。

## 五、已知限制 / 留给后面（记账，不是遗漏）

1. **分页目前是全量测量**：打开文档时对全部 FlowUnit 跑一次冷布局（100 单元 ≈ 159 ms）。
   → 后续可做**单遍分页 RenderObject**（布局即分页）或虚拟化。
2. **插入/删除整行会让其后所有单元的 widget 重建**（子节点匹配是按索引的）。单元缓存只在"同一位置内容不变"时生效。
3. 行内富文本（`**粗体**` / `*斜体*` / 链接）目前**原样当文字渲染**；列表只支持一层嵌套；表格 / 图片块未做。
4. `hit_map.dart` 与 `visible_atoms.dart` 是**为 S3 准备的接口**，目前尚无产品调用方（`visible_atoms` 有单测）。
5. 页眉只支持单行文本；页码画在纸张**外**（属界面，不进文档）。

## 六、S3 起点

S3「公式编辑」要做的四件事（依据《技术选型与风险.md》5.1 / 5.1.1）：

1. **提交规则**：面板插入时**连花括号一起写**（机器永无歧义）+ 上下文启发做出槽 + **`Tab` / `→` 显式出槽**。
2. **位点表与邻接**：引擎给了 `EquationRowNode.caretPositions`（位点表），**但没给邻接关系** ——
   分子↔分母、矩阵行列的邻接表要自己建。
3. **结构感知删除**：用 `visible_atoms.dart` 的**原子边界**做 smart delete —— 先删内容、空了再删结构，
   "手感像删字符，又不会留下半个坏公式"。
4. **空槽可视化**：虚线占位框 + 当前槽高亮（用户"看得见位点"才敢点、敢 `Tab`）。

**已有地基**：`projection.dart:snapCaretInTex`（位点吸附）· `visible_atoms.dart`（原子边界）·
`hit_map.dart`（点击 → 源偏移，S1 已三验命中）· `InlineMathText`（`\cursor{}` 注入可用）·
`DocBuffer`（一维光标 + 撤销，天然适配位点序）。
