## 一、词汇（一条一条钉住，别再混）

| 词 | 是什么 | 出处 |
|---|---|---|
| **视觉行** | 屏幕上看得见的一行字。**基准里没特殊说明的"行"都是它** | 〔用户〕只读基准开头「无特殊说明的行为视觉行」 |
| **段** | Enter 切出来的单位。**一个段至少一个视觉行**；段内用 `Shift+Enter` 切出更多视觉行 | 〔用户〕只读基准 6 |
| **段内行** | 段里被 `Shift+Enter` 切开的一行，行距 = **行盒 27.2**（没有段距） | 〔实测〕 |
| **行盒** | 一行文字自己的高度 = 字号 × 行距（默认 16 × 1.7 ≈ **27.2 px**） | 〔实测〕 |
| **段间距** | 相邻两段之间让开的那一截（默认 ≈ **11.2 px**，= 字号 × 0.7），是**下一段的段前距** | 〔实测〕 |
| **一行（段）占的高度** | **行盒 + 段间距 = 38.4 px** | 〔实测〕 |
| **空行** | 内容为空的视觉行 = **一个空段** ⇒ 有高度 38.4、能承接光标、退格能删 | 〔用户〕只读基准 3；〔实测〕 |
| **段落分隔符** | 两段之间那**唯一一个**零高度的位置（Markdown 的 `\n\n` 里**第二个**换行符）｜**不是行、不是光标位** | 〔用户〕2026-10-28 拍板；`core/paragraph_break.dart` |
| **常驻行** | 文末最后一个 `\n` 之后那一格（EOF）：常态存在、能承接光标、**退格删不掉** | 〔用户〕只读基准 3 最后一句 + 第 4 条 |
| **硬换行** | `Shift+Enter` ⇒ 存成"行尾两空格 + `\n`"（R8）；**只在光标两侧都有字时成立**，行首/行尾等价 Enter | 〔用户〕只读基准 6 补句 |

★★ **两个 11.2 别混**：**行间距**是行盒内部的 leading（16 → 27.2 里那 11.2），
**段间距**是段前距。数值撞在一起是巧合（`1.7 − 1 = 0.7`），**概念不同，不许"顺手统一"**。

★ 旧稿 §一.2 写"空行是结构、不是内容" —— **错**，已改：空行是内容（一个空段）。
★ 旧稿 §一.3 写"第 1 个空行只有段距" —— 2026-10-28 改成准确说法：
  **第一个空行是段落分隔符（不是行）**；文首 / 文末没有分隔符，每个空行都是真行（见 §二.3）。
★ 旧稿 §一.4 / D3 写"点击只移光标、文档不变" —— 保留结论（点击不写文档），但理由变了：
  那一行**本来就在**（见 §五 的尾换行不变量），不需要"点一下造出来"。

## 二、一把尺子（几何：本轮唯一的新知识）

### 1. 行顶 y 的唯一公式

```
行顶 y = 槽顶 + 段间距 + k × 38.4 + 行内内缩(3.6)
```

* `行内内缩 = (行盒 − 光标条高) / 2 = (27.2 − 20) / 2 = **3.6**` —— 文本层把光标**垂直居中**放在行盒里。
  空行 / 文字行 / 文末行必须用**同一个**内缩，否则就是用户说的"光标在这儿、打出来的字低一截"。
* `段间距` 只在"上一段之后"出现一次；**页首不留段前距**（与 Word 一致）。

### 2. 实测对照表（探针逐点，2026-10-28）

| 文档 | 光标在 | 实测 y |
|---|---|---|
| `甲⏎` | 甲行末（偏移 1） | 99.0 |
| `甲⏎` | 文末下一行（偏移 2 = EOF） | **137.4** = 99.0 + 38.4 |
| `甲⏎⏎` | 偏移 2（段距那一格） | 126.2 = 99.0 + 27.2 |
| `甲⏎⏎` | 偏移 3（EOF） | 137.4 |
| `甲⏎⏎⏎` | 偏移 3 / 4 | 137.4 / 175.8 |
| `A⏎⏎<!-- pagebreak -->⏎⏎B⏎` | 分页符行首（偏移 3） | **137.4**（与文末同一把尺子） |
| `A⏎⏎⏎<!-- pagebreak -->⏎⏎B⏎` | 偏移 3 / 4 | 137.4 / 175.8 |

### 3. "行表"怎么数（**文末 / 文首 / 段间三样，这是关键**）

一个单元之后有 n 个空行（行首 `run[0..n-1]`），后面跟着"下一个位置" `next`
（下一段的第一个字符 / **分页符行首** / **文末 EOF**）：

* **段与段之间**（后面还有下一段）⇒ 行表 = `run[1..] + [next]`：**`run[0]` 是段落分隔符**
  —— 零高度、**不是行、不是光标位**（§二.4），因为那一行由**下一段自己**占
  ⇒ 对应 `blank_runs.extraBlankHeight(n) = (n-1) × 行高`。
* **文末**（后面没有下一段）⇒ 行表 = `run + [EOF]`：**每个空行都是一行**，
  最后再加"待写行"（EOF）⇒ 对应 `blank_runs.trailingBlankHeight(n) = n × 行高`。
  ★ 2026-10-28 之前这里也 skip 了第一个 ⇒ **高度表与行表两套口径**，症状就是
  "光标站在文末下一行上按 Enter 不动"（已修，见 §七）。
* **文首**（前面没有上一段）⇒ 行表 = `run`：同样每个空行都是真行
  ⇒ 对应 `leadingBlankHeight(n) = n × 行高`。
* 判据本体是一个纯函数：`blank_runs.blankRowStart(atDocStart:, atDocEnd:)` → 段间 `1`、文首文末 `0`。
* 〔实测〕依据：`A⏎⏎B` 里在偏移 2 打一个字 ⇒ 那字变成**上一段的段内行**（27.2）**并把 B 并进同一段**；
  在偏移 3 打一个字 ⇒ 落成**新段**（38.4）—— 所以段间的"行"只能从 `run[1..]` 起算。

### 4. 段落分隔符：**有语义、没像素**（2026-10-28 定，本轮的地基）

Markdown 里一段的结束是**两个**换行符：第一个终止最后一行（行终止符），
第二个才是**段落分隔符** —— **它不终止任何一行**。于是：

```
数据行数 = `\n` 个数 + 1（最后那个空串是"常驻行"）
有高度的行数 = 数据行数 − 段落分隔符个数（段间恒为 1，文首文末为 0）
```

★ 为什么它**不能承接光标**（〔实测〕2026-10-28，`A⏎⏎B`）：

| 项 | 实测 |
|---|---|
| 分隔符那一格被画在 | **126.2** = 上一行行盒底(122.8) **+ 3.6** |
| 下一段真实行顶 | **133.8** |
| 差 | **11.2 = 段距** ⇒ 光标条(20 高)悬在缝里、压着下一行上沿 |

而且**在那儿打字会毁数据**：`A⏎⏎B` 在分隔符处插 `x` ⇒ `A⏎x⏎B` ⇒ `x` 成了 A 的段内行，
**B 被并进同一段**（段距消失、往上跳 11.2）。

⇒ 结论（〔用户〕2026-10-28 原话「段间距从设计上来说没有理由能够承接字符，
不然基本单位就很容易错乱」）：
**它不是位置。所有"产生光标"的路径都不许产生它**：

| 入口 | 处理 |
|---|---|
| `←` `→` | 一步跨过去（`math_nav.nextCaretOffset` / `prevCaretOffset` 调 `skipParagraphSeparator`） |
| 点击 | 不进落点表；那一格**归下一段**（段距 = `leadingGap`，挂在下一段、页首丢弃）⇒ 落下一段行首 |
| `Enter` / `Shift+Enter` | 行首/行尾的 `Shift+Enter` 等价 Enter（它原来正是最大的一处产生者） |

★★ **这里原来的错**：2026-10-26 的全域守卫写的是「每个偏移**至少**有一根光标」——
**那条命题本身就是错的**。分隔符零高度、没有行盒，而"每个偏移都必须有"逼着渲染层给它编一个 y
（只能画进段距）⇒ 用户看到的「段间距能当一个容器行把光标放进去」。
**用实现迁就一条错的断言**，这就是那次返工的根。守卫现在改成「每个**视觉行**一个光标」。　

## 三、Enter：只有一条规则

```
行内（光标前后都有字）        ⇒ `\n\n`（把一行切成两段，行数 +1）
行末、且下一行还有字          ⇒ `\n\n`（先分段，再给中间那一行留空行）
其余（空行上 / 行首 / 行末 / 文末）⇒ `\n`  （行数 +1）
```

* **行末按 Enter 时换行符插在"下一行行首"**（`行尾 + 1`），光标才会落到**新造出来的那一行**上
  〔用户〕只读基准 1「按 enter 可以让光标下一行」。插在本行行末的话，屏幕上看不出光标在动。
* **空行上按 Enter 不挪落点**（挪了就跳过一整行）。
* ★★★ **2026-10-28 改口径：`Shift+Enter` 只在"光标两侧都有字"时成立**——
  行首 / 行尾**完全等价 Enter**〔用户〕只读基准 6 补句：「shift enter换的是段内的行
  （光标两侧有文字时可以，否则等价enter)」。
  为什么行首行尾不行：硬换行的载体是"行尾两空格 + 换行"，它造出来的那一行在行首/行尾必然是**空的**，
  而 **"段内的空行"在 Markdown 里不存在**（空白行就是换段）。实测（2026-10-28）：
  行尾按 Shift+Enter 得到 `甲␣␣⏎⏎`，那个空行正是**段落分隔符**（零高度）⇒ 光标被塞进段距、
  打字还会把两段并成一段。**旧结论「空行上 `Shift+Enter` ≡ `Enter`」被这条吸收了。**
* 两条通道（**键事件** / **平台文本通道**）都汇到 `EditViewState._enter()` —— 规则只有一份。
  `NewBlockOnEnterFormatter` 因此**不再挂默认链**（它只看得到平台文本的差分，看不见行结构）。

## 四、退格

| 场景 | 行为 | 出处 |
|---|---|---|
| 非文末空行行首 | 删掉这个空行，光标回到**上一行的边界** | 〔用户〕只读基准 3 第二句 |
| 上一行有字时 | 光标落在它**行末**（不是留在被删那一格） | 〔用户〕只读基准 2「光标回到 A 行末」 |
| **文末永久空行** | **不删**，只把光标退回文末那一行的行末（字节一个不变、不进撤销栈） | 〔用户〕只读基准 3 最后一句 |

## 五、存储：**非空文档一律以 `\n` 收尾**（本轮新增的地基）

* **为什么**：光标是整数偏移。"文末行末"与"文末下一行行首"**只有在文末行有行终止符时**才是两个不同的整数。
  没有它，那一行只能靠"把光标画在上一行行末、却宣称它在下一行"来假装 —— 一打字就露馅。
* **怎么做**：`DocBuffer` 的不变量 —— 任何编辑只要结果少了行终止符、且这次编辑**碰到了末尾**，就补一个
  （由 `Edit.eol` 记录，撤销/重做精确）；`loadDocument` / 会话恢复 / 导入都走 `normalizeDocumentText`。
* **代价**〔用户〕2026-10-27 拍板「行，可以加这个换行符」：文件多一个 `\n`（任何 md 工具/渲染器**看起来一模一样**）；
  末页**保留一行**（不画墨）给永久空行。
* ★ **快照（`savedText`）必须走同一条归一**，否则缓冲区比快照多一个 `\n` ⇒ 外壳以为文档永远是脏的
  ⇒ 实测**自动保存死循环**（一次全量测试因此卡住 10 分钟）。

## 六、鼠标点击落点

〔用户〕只读基准 7（原话）：「点击到文末下方的空白时 / 那里本来就有空行 ⇒ 落那个空行行首 /
没有 ⇒ 向上找最下面一个存在的空行的行首 / 都没有 ⇒ 文末下一行那个空行的行首」。

★★★ **2026-10-28 用户第三次纠正：三级在"文末下一行是常驻行"（基准 4）下合并成一条。**

因为那条常驻行**本身就是一个空行**（空段、占一行、能站光标）、而且**是最下面那一条** ⇒
"向上找最下面一个存在的空行"永远有答案，就是它 ⇒ ② 与 ③ 是同一件事。

| 情形 | 落在 |
|---|---|
| 点在**某一空行上** | 那一行的行首（按行切分的子槽各自处理） |
| 点在**两段之间的空隙**里 | **下一段行首** —— 段距是下一段的段前距（`leadingGap` 挂在下一段、页首丢弃）⇒ 那一格的归属从设计上就是下一段。〔用户〕2026-10-28 拍板 |
| 点在**所有行下面那片白里** | **最下面那一行**：末页 = 文末下一行（EOF）；分页原页 = 分页符行首（它就是原页的待写行） |

* ★ **这不是新结论**：2026-10-27 那轮（`d788b26`/`2dffb43`/`e299dc0`/`fdff5c1`，"文末下一行是**真行**、
  一行一个行盒、一把尺子"）的代码注释里就写着「它就是这个位置：最后一行之后那一格（= `buf.length`）」。
* ★ 2026-10-28 上午我把它当成"**不是**空行"（定义成"只有存出来的才算"）⇒ 于是"向上找"扫到
  **两段之间**那一行，而那一行没有自己的行（只占段间距）⇒ 光标被画在"槽顶 + 3.6"的间距里。
  用户原话：「点下部空白，光标落在文末那行上面的间距处」⇒ 撤回"扫全篇"，落点回到"最下面那一行"。
* ★ **末页与分页原页同一套**：原页最下面那一行本来就是**分页符行首**，所以统一之后原页行为不变；
  批 47 那条「原页点白就落分页符行首」成为本条在"原页没有更低的空行"时的特例。
  用户 2026-10-28：「用户自己根本就看不到分页符，分页符对于用户来说没有任何定位功能」——
  分页符只是"这一页到此为止"，它的行首是原页唯一的"待写行"，不该被当成特殊落点来讨论。
