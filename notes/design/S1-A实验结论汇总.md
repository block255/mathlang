## 一、编辑内核选型 → **决定：自研（架构 A）**

| | **A 组（自研）** | **B 组（appflowy_editor 6.2.0）** |
|---|---|---|
| 结论 | ✅ **采用** | ✗ **淘汰** |
| 核心模型 | **一维字符缓冲区 + 渲染投影** | 树 + Delta 的富文本块 |
| 一票否决项 | 全部通过 | **编译不兼容**：Flutter 3.47 新增的 `TextInputClient.onFocusReceived` 该包未实现；且 pub 上 **6.2.0 已是最新版**，无版本可升 |
| 与目标架构同构性 | — | ❌ **不同构**（树 + `LinkedList<Node>` + Delta ⇒ 采用它等于放弃"数学与文字同权"） |
| 工程代价 | 零新增依赖 | 一次引入 **44 个依赖**；自定义块的选区内务极重（参照 divider："一条线"222 行） |
| 块高可测（问 1 ★） | 完全可控 | 机制存在（`Node.key` 是 GlobalKey，10 个块组件都用它作 key）但**运行时未能验证**（被编译阻塞） |

**淘汰三条理由各自独立成立**：编译不兼容 · 模型不同构 · 依赖体量。

## 二、★ 问 0「流内数学映射可行性」→ **四子项全部通过（+ 打字延迟）**

| 子项 | 结果 | 关键证据 |
|---|---|---|
| ① 同行混排 + 基线对齐 | ✅ | 一行内「中文 + `$x^2+1$` + 中文 + `$\frac{a}{b}=\sqrt{2}$` + 中文」正确渲染；分式是横线上下结构 |
| ② 光标画进数学内部 | ✅ | 引擎内置 `\cursor{}`（默认已注册）；点「面板：分式」→ 光标自动落在**分子槽**（缓冲区 51→62、光标 @58）；再点「α」→ 渲染成 `\frac{\alpha}{}` |
| ③ 点击 → 源偏移 | ✅ | **零 src 依赖**自建命中：点分子 `a` → **22**、分母 `b` → **25**、`√2` 里的 `2` → **35**（三处全中预测值；光标真的落进对应位点） |
| ④ 性能（debug / **release**） | ✅ | 10 行 **65 ms** / 25 行 **160 ms** / 100 行 **559 ms** / 100 行纯文字 **97 ms** |
| ⑤ **打字延迟**（单公式重绘） | ✅ | **8 ms/帧**（debug 28 ms）→ **在 60 Hz 一帧预算 16.7 ms 之内** |

## 三、★ 由实验直接确定的 S2 设计约束（这几条是硬约束，不是偏好）

1. **必须按页渲染**：一帧渲染 100 行 = **559 ms**（release）→ **绝不能整篇一帧渲染**。A4 一页 ≈ 25 行 ≈ **160 ms 一次性**，可缓存 → 翻页/首次渲染可接受。
2. **打字时只重绘"变化的那一个公式"**（实测 8 ms/帧）→ 不能整页重排。
3. **"滚动列表里放公式"必须避开 item 级 RepaintBoundary**（用 `ListView(addRepaintBoundaries: false)` 或自建滚动容器）——否则触发 `RenderBox was not laid out: RenderRepaintBoundary` 断言（已用 A/B 实验定位：换成 `SingleChildScrollView + Column` 即消失）。
4. **源偏移必须自己词法化得到**：引擎的 `range` / `caretPositions` 是**渲染空间坐标**（只覆盖渲染出的原子，**不含 `\frac{}` / `^` / `_`**），单字符叶子的区间甚至是**反的** `[pos+1, pos)`。已实现「**可见原子扫描器**」——**它就是 S3 需要的"位点表"雏形**，并顺带给出原子边界（支撑"按结构删除"与行内选区）。
5. **位点命中 = 渲染叶盒 + 两级过滤**：
   - 装饰盒（根号分隔符等）→ 判据「矩形必须落在 Math 控件边界内」（其 `localToGlobal` 尺寸会失真）
   - 我们注入的 `\cursor{}` 光标条 → 判据「宽度 ≥ 2px」
   - 之后"叶盒序 ↔ 可见原子序"严格一一对应（引擎保证 `GreenNode.children` 顺序 = 光标访问顺序）
6. **行内公式对齐：默认 `baseline`，保留 `middle` 回退**。实测高结构（`\sum` 带上限 / 嵌套分式 / 矩阵）下两种模式**行高完全相同 54.0 px**、都无断言；`baseline` 是排版上正确的语义，故选它，但把对齐方式做成"每处可配 + 全局默认"。

## 四、工程资产与操作纪律

**新增可复用资产**

| 资产 | 用途 |
|---|---|
| `app\lib\spike\inline_math\inline_math_page.dart` | 问 0 全套探针：一维缓冲区/渲染投影/位点命中/性能隔离实验/打字延迟/高结构对齐对比 |
| `app\lib\spike\kernel_appflowy\kernel_appflowy_page.dart` | B 组实验页（**故意不被 `main.dart` import**；将来该包与 Flutter 对齐后可直接启用） |
| `scripts\serve_web.js` | release 产物预览服务器：`node serve_web.js <端口>`（默认 57136，目录 `app\build\web`） |

**必须遵守的两条操作纪律（都是踩过坑换来的）**

1. ★ **语义树一开，CDP 坐标点击就失效**：Flutter 的语义 DOM 覆盖层会把点击退化成"点该元素中心"（点三处不同位置返回同一个局部坐标）。解决：注入
   `flt-semantics, flt-semantics-container, flt-semantics-host { pointer-events: none !important; }`
   → **语义树可读 + 坐标点击精确**，两者兼得。（另：热重启后语义树需重新启用。）
2. ★ **release 基准测试必须先预热再取数**，并且第一轮数据要先用**内部自洽性**过一遍（本次第一轮出现过 `100行纯文字=9320ms`、比含公式还慢 15 倍的假数据；复测即正常）。曾怀疑"后台标签 rAF 节流"，**实测 rAF 间隔 4 ms（~250fps）→ 排除**。
3. 附：**状态栏文字变长会让工具栏 `Wrap` 重排**，开关坐标随之平移 → **每次点击前重新取坐标**（本次盲点坐标点到了隔壁按钮）。
