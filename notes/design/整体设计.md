## 一、一句话定位

**一个"看不见数学编码"的数学文档编辑器**：点符号就能写出公式，文档以 A4 分页呈现，一键导出**图片式 PDF（内嵌 md 附件）** 与**每页一张的图片集**；底层用标准 Markdown + LaTeX 存储，因此其它工具与 AI 都能直接读写。

## 二、要解决的痛点

| 市面现状 | 我们的做法 |
|---|---|
| 好用的要付费（Typora 等） | 自用为主，不设付费墙 |
| 要学 LaTeX 语法 | **符号面板 + 模板插入 + 占位符跳转**，数学编码永不出现 |
| 只能电脑 | **Windows 桌面已发布**；Web 仅开发用；Android/iOS 在路线图（历史计划：Web / Android / 桌面 / iOS） |
| 换行对齐不方便 | 按 A4 页宽排版；多行推导用 `aligned` 模板按等号对齐 |
| 导出不给力 | **图片式 PDF（内嵌 md 附件）** + **每页一张的图片集** + md/txt 原样导出 |
| 符号面板缺失、快捷键不能改 | 分类面板 + 全套可自定义快捷键 |

## 三、设计原则（冲突时按序号优先；★ **第 0 条「平权」压过其余五条**）

> ### 0. ★★★ **平权**（最高原则 · 用户 2026-10-16 / 10-18 反复钉，2026-10-21 再次确认"最重要就是这条"）
>
> **一条可见流里的一切对象地位相同**：一个汉字、一个字母、一个 `≥`、一个分式、一整段行间公式，
> 都是**同一层原子** —— 同一套光标、同一套选择、同一套删除、同一套点击。
> **没有"模式"，没有"进入/退出"，没有"特殊区域"，没有"高级区/低级区"。**
> 数学不是"另一种东西"，它只是这条流里的字符被渲染成了二维。
>
> 四条硬推论（都已是既有口径，**别再重开**）：
> 1. **对象必须由内容产生**：不许"先造空壳再进去写"（那是方程域思路）⇒ `Alt+=`（行内空壳）**撤掉**，
>    行内公式必须由内容产生；行间公式能空壳，只因**它是块**（块本来就能是空的）。
> 2. **不许造用户没写的字符 · 不许按"看起来像"分流**：`a>=` ⇒ `a$\ge$`（只有 `≥` 升格，`a` 仍是文字）；
>    不给结构补"合成原子"；不因为"这行像公式"就当成块。
> 3. **不许实现细节泄漏成地位差异**：同一段文字不能因为块类型不同而命中盒 / 选择行为不同
>    （`doc_view.dart` §7.3 把命中盒一律撑满文本栏，注释原话："这是实现细节泄漏，必须消除"）。
> 4. ★★ **围栏不是对象边界**（2026-10-24 定，见 [`围栏与整体.md`](围栏与整体.md)）：
>    `$…$` 只是**排版上下文 + 存储记账**，**不许**参与"决定一个字符归谁"或"决定什么是对象"的判据。
>    一串符号共处一段围栏是对的（`$\alpha\beta\mu\varepsilon\theta$` = **1 个围栏、6 个原子**）；
>    而 `$\alpha\beta$` 与 `$\alpha$$\beta$` **编辑行为必须等价**（排版/性能/导出可以不等价）。
>    ⇒ 违反它的现行例子：**打字时"光标在围栏里 ⇒ 打的汉字一律进 tex"**（B2 的根因）。
>
> ★ **原则 2 是它的推论，不是独立愿望**：用户为什么永远不用看数学编码？
> **因为数学不是另一种东西**，没有什么"另一种表示"值得展示。原则 1 / 3 / 4 / 5 是它的地基与兜底。

1. **文档格式 = Markdown + 标准 LaTeX**（唯一事实来源）：纯文本、可版本管理、任何 md 工具能打开、**AI 可直接读写**（这是"AI 对接"最实在的形态）。
2. ★ **用户永远不需要看数学编码**（★ 第 0 条的推论）：数学只以**渲染形态**出现，编码是存储细节。仅保留一个**默认关闭**的「高级：查看源码」开关（给你、老师、我排查问题用）。
3. **结构由"块类型"表达，用户不写 Markdown 标记**：标题就是标题块、列表就是列表块；`#`、`-`、`**` 都不需要用户敲，底层序列化成 md。
   ★ 平权口径：块类型是**段落语义**，不是"给文档分级" —— 顶栏下拉只有 **正文 / 标题 1–3**，
   列表 / 引用 / 代码块**不设入口**（用户原话："我们是平权，**没有代码块的思维**"）。
4. **一份内容三处一致**：编辑时的分页预览 = 导出的 PDF 页 = 图片集的一张图。
5. **静默失败必须可见**：渲染不了的命令、溢出一页的块、解析失败的行，都要有提示或「诊断清单」，绝不悄悄吞掉（沿用流水账「未识别通知」的成功经验）。

## 五、核心交互流程（历史草案；现行编辑模型见 §三 与《位点与结构导航》）

1. **新建 / 导入**：空白 A4，或导入 `.md` / `.txt` → 自动解析并渲染
2. **打字**：直接输入；回车新块；工具栏或快捷键切换块类型（标题/列表/引用/代码）
3. **写公式**（关键路径）：
   - 打开符号面板 → 点「分式」→ **就地插入公式卡片**（渲染成上下结构 + 两个占位框）
   - 光标已在第一个占位框 → 继续点符号或敲字母 → **实时渲染**
   - `Tab` 跳下一个占位，`Shift+Tab` 回上一个
   - 点卡片外任意处 → 收成普通渲染态；要改再点它
   > ⚠️ **2026-10-13 修订**：以上"公式卡片"流程是**旧方案**。新目标见文首修订块 —— 符号面板点「分式」时，实际动作是**把 `\frac{}{}` 插进一维缓冲区、并把光标偏移放进分子槽**；用户感知仍是"上下结构就地出现"，但**没有卡片、没有进出边界、删除按结构感知**。
4. **多行推导**：插入「对齐公式块」（`aligned`）→ 逐行填，`&` 处自动对齐
5. **分页**：内容自动流入下一页；也可手动插入分页符
6. **导出**：PDF（图片式；文本式 U7 未做）/ 图片集（每页一张 PNG）/ md / txt

## 六、数据模型

> ★ **2026-10-14 修订：本节旧草案（"块对象树 + inline 数组"）已废弃** —— 它会在缓冲区之外再立一份树，等于把 4.0 架构的好处还回去一半。
> **现行规格见《块模型与md往返.md》**（S2-1 定稿）：真相是一条 md 字符串，**「块」只是这条字符串上的「行区间视图」**。

```
L0  buf  : String                                ← 唯一事实来源；编辑只改它
L1  line[i]  = [start, end)                      ← 按 '\n' 切，纯函数
L2  blk[k]   = { type, lineFrom, lineTo }         ← 行区间 + 类型（由行首标记推断）
L3  page[j]  = { flowFrom, flowTo, y }            ← 按 FlowUnit 高度贪心装箱
```

**「序列化 / 反序列化」这件事不再存在**：`buf` 本身就是标准 md（行内数学 `$...$`、公式块 `$$...$$`、标题 `# `、列表 `- `）——**读进来就是它，写出去还是它**，往返无损是结构性保证、不靠转换代码。

## 七、分页模型

- 页面：A4（210×297 mm），边距可设（默认上下 20 mm / 左右 18 mm）
- 排版：块按顺序流入页面；**块是原子**，不允许被切成两半
- 溢出：单块高于一页 → 黄色告警（提示拆分），不切断
- 手动：可插入分页符块
- **页眉**：每页顶部一行可编辑文本（作业写姓名/学号）；新建文档时可用文件名自动填充
- v2+：跨页拆分长公式、页眉页脚、页码、图注
- ★ 分页结果同时决定 PDF 分页与图片集张数（原则 4）

## 八、导出

| 目标 | 方案 | 文字可搜索/复制 | 备注 |
|---|---|---|---|
| **PDF（现行 v1.1）** | 每页渲染成图 + 内嵌 `.md` 附件 | ❌（PDF 内不可搜索） | 文本式 PDF（可搜索）未做，见 U7；应用内正文仍可选中 |
| **图片集** | 每页 `RepaintBoundary → toImage` → PNG（**默认 2×**，可选 1×/3×） | — | 命名 `page-01.png`… |

| 可打印 HTML（备选） | 内嵌 KaTeX + 字体，浏览器「打印成 PDF」 | ✅ 且公式矢量 | 质量最高，代价是多一步打印操作 |
