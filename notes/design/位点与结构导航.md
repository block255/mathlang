## 一、四个概念的正名（★ 先统一语言，否则后面全在打混仗）

| 概念 | 定义 | 落在哪 |
|---|---|---|
| **偏移 offset** | L0 字符串下标 `0..length`。★ **唯一真相**，光标就是一个整数 | `DocBuffer.caret` |
| **可见原子 atom** | 渲染出来、用户**看得见**的最小单位。`\alpha` = 1 个原子；`\frac` **不是**原子（结构命令，不渲染成字符）；`{` `}` `^` `_` **不是** | `visible_atoms.dart` |
| **槽 slot** | 一个结构命令的**一个参数位**。`\frac{□}{□}` = 2 槽；`\sqrt[□]{□}` = 2 槽；`x^{□}` = 1 槽 + 主行位点。**槽是位点的分组容器** | 本文 §三 |
| **位点 caret site** | tex 里**一个合法的光标插入位置**（源空间偏移整数）。位点表 = 全部位点的**有序扁平表** | 本文 §二 |

★★ **最容易混的一点**：**位点是扁平的一维序列，槽只是它的分组**。
这就是 5.1.1 "二维光标是伪问题"的确切含义 —— `DocBuffer` 的一个 `int` 同时表示
"在文档的第几个字符"和"在某个槽的第几个位置"，两种看法，同一个整数。

**推论（架构不必改）**：`DocBuffer` 一行代码都不用动，S3 全部是"从 tex 算出位点表 → 决定这个整数往哪跳"。

## 二、位点表

### 2.1 定义

```
sites(tex) : List<int>      // 严格递增；每个元素是一个合法的光标插入偏移
siteInfo[i] : { slotPath, indexInSlot, geom? }   // 该位点的元信息（邻接表要用）
```

**★ 位点 ≠ 每个字节**。这是本节的核心，反例：

```
tex = \frac{a}{b}
       0123456789...
```
- `7`（分子 `a` 之后）是位点 ✅
- `9`（分母 `b` 之前）是位点 ✅
- **`8`（`}` 与 `{` 之间）不是位点** ❌ —— 往那儿插字符会得到 `\frac{a}x{b}`，语法坏掉
- `\frac` 命令名内部（`1..5`）都不是位点 ❌

### 2.2 构造规则

以 `visible_atoms` 的有序原子表为骨架，再加两类位点：

| 来源 | 产出位点 |
|---|---|
| **每个可见原子的 `start` 与 `end`** | 原子两侧各一个位点（相邻原子的 `end == start` 自动合并） |
| **空槽**（`{}`、`{ }`、`\sqrt{}` 的参数位为空） | 该槽内**唯一**一个位点（= `{` 之后的位置） |
| **结构末尾** | `tex.length`（"走出这段数学"的位点） |
| 结构命令名内部 / `{` `}` `^` `_` `&` 自身 / 语法夹缝（如 `}{` 之间） | **不产出** |

**`slotPath` 怎么来**：对 tex 做一次**配对扫描**得到结构树（`{`…`}` 配对、`^`/`_` 吃掉后随的
`{…}` 或单原子、`\frac`/`\sqrt`/`\begin{env}` 各自的参数位），每个位点记下它落在哪条槽路径上。
配对扫描**必须容忍未闭合**（打字中间态，见 2.3）。

### 2.3 半成品 tex（打字中间态）与降级位点表

打字过程中 `\frac{1}{`、`x^{`、`\begin{aligned} a &= b` 都是**常态**，位点表不能因此失效。

- **未闭合的 `{`** → 视作"槽延伸到 tex 末尾"（槽内位点照常产出）
- **配对彻底失败**（如 `}` 多于 `{`）→ 退回**降级位点表**：只用 `visible_atoms` 的原子边界 + `tex.length`
  （即"纯字符级导航"，不做槽级导航），并在状态栏给一条**非阻塞提示**
- ★ **降级必须是静默可用的**：用户不该因为少打一个 `}` 就无法移动光标（原则 5：问题可见，但不阻断操作）

### 2.4 可测试的自检性质（S3-1 的验收手段）

> **性质 P1**：位点表中每个偏移都是**语法安全的插入点** ——
> 对每个位点插入一个探针字符 `x` 后，tex 仍能被 `TexParser` 解析（已闭合的公式），或至少**不产生新的解析错误**（未闭合的公式）。

> **性质 P2**：位点表**严格递增、无重复、全部落在 `[0, tex.length]`**。

> **性质 P3**：`snapCaretInTex(tex, o)` 的输出 ∈ 位点表（对任意 `o`）——
> 即"吸附"的落点必然是合法位点（把现在的"只防切开命令名"升级为"吸附到最近位点"）。

P1 是**property test**：拿一批代表性 tex（分式/根号/嵌套/上下标/大算符上下限/矩阵/`aligned`/半成品），
自动遍历位点插字符再解析。**这条比手写快照更能抓 bug。**

### 2.5 一条待验证：位点序与偏移序是否单调同构

设计假设是"位点按**渲染阅读顺序**枚举，而渲染阅读顺序 = 源码从左到右"，
因此位点序与偏移序**一一对应且单调**。
抽查（`\frac{a}{b}` 源序 a→b ✅；`\sqrt[3]{x}` 次数在源里先于被开方数 ✅；`x_1^2` 下先上后而渲染下上 ✅；
`\sum_{i=1}^{n}` 下限源先、渲染下上 ✅）都成立，**但还没有系统验证**。

→ **S3-1 用一批样本验证单调性；若真出现反例**（渲染阅读顺序与源码顺序不一致的结构），
位点表**仍然可用**（它只是"插入位置集合"），但**邻接表以"位点序"为准、不以"偏移序"为准** —— 这一条要写进实现注释。

## 三、槽与邻接

### 3.1 槽序

**槽序 = 深度优先 · 源顺序**。例：`\frac{\sqrt{x}}{y}` 的槽序 = 分子槽 → （分子内）根号槽 → 分母槽。
嵌套槽会被 `Tab` 依次访问（与 Word 公式一致）。

### 3.2 键位映射

| 键 | 语义 | 落点规则 |
|---|---|---|
| `←` / `→` | **位点序** ±1（字符级） | 位点表相邻元素；到段首/段末则**跨段离开数学** |
| `Tab` / `Shift+Tab` | **槽序** ±1（跳过槽内中间位置） | ★ 落点见 §十-① 待拍板 |
| `↑` / `↓` | **竖直邻接**：分子↔分母、矩阵行间、`\sum`/`\int` 的上下限 | 由槽的**几何关系**推导（同父槽按 `geom` 排序取上/下）；无竖直邻居时**不移动**（与 Word 一致，不要乱跳） |
| `Home` / `End` | 当前**行**首/行尾位点 | 走 L1 行视图（`block.dart`） |

**`↑↓` 需要几何**：槽的竖直关系不能只靠语法推（`\frac` 的分子分母是上下，`x^2` 的指数是右上）。
两个来源可组合：① 语法特例表（`\frac`/`\sqrt[n]`/`\substack`/上下限 → 上/下关系明确）；
② 运行时用叶盒坐标算（`hit_map`/`leaf_boxes` 已有能力）。
→ **建议：v1 先用语法特例表**（覆盖 S3 范围内的高频结构，零运行时成本），几何法留作后续。

### 3.3 跨边界进出（★ "数学与文字同权"的关键动作）

> ★★ **通则（2026-10-15 定）：数学定界符（`$` / `$$`）对用户不可见 ⇒ 它们永远不是
> 任何编辑操作的目标。** 所有插入/删除都落在「**看得见的位置**」上。
> 这一条是原则 2「用户永远不需要看数学编码」在编辑动作上的直接推论 ——
> 删掉一个 `$` 会让"半个公式"的源码**爆出来**（用户实测抓到过，见 §11.16）。
>
> ★ **那要去掉整个公式怎么办**（2026-10-15 改口径）：**空壳本身就是一个可见对象**
> （§6.1.1 会把它画出来）⇒ 按 §4.0 的通用规则删它即可，**不需要"整段公式"这种特例**。
> 旧 §4.0 的 B2 / D2 两条（"从外面删 = 整段删"）**整表作废** —— 那是"公式块"思路。
>
> ★★ **「同权」的精确边界（2026-10-15 定，用户提出）**：
> **不可见定界符（`$` / `$$` / `{}` / `\text{}` 的边界）不构成层级；
> 结构嵌套（分子分母、被开方数、上下限、环境格）构成层级。**
> "公式块"的错**不在于"有层级"**，而在于**把 `$` 当成一层**（凭空造出"公式内 / 公式外"两个世界）。
> ⇒ 分式 / 根号**不存在**下面那种"末尾 vs 之后"的区分问题（同层、紧邻同一对象）；
> 真正需要"点的是结构外面还是里面"的，是**真层级** ⇒ 靠结构几何（《编辑地基与手感》②）。

**进出（`←` / `→` / `↑↓`）**

| 动作 | 行为 |
|---|---|
| 文字里按 `→` 到行内公式的 `$` 之前 | 光标进入**该公式第一个位点**（进槽） |
| 公式内按 `→` ★ | **一步走出**到 `$` 之后的文字（**跳过** tex 末尾那个位点，见下面「甲」） |
| 公式第一个位点按 `←` | 走出到 `$` 之前的文字 |
| 公式**之后**按 `←` ★ | 回到公式的**末尾位点**（= tex 末尾）——"我要继续改这段数学" |
| 公式内按 `↑`/`↓`（无竖直邻居） | **不移动**（不越出公式，避免误跳） |

#### ★★ 「甲」：`→` 与 `←` 是**有意不对称**的（2026-10-15 用户拍板）

**为什么**：`tex.length` 那个位点（= 收尾 `$` 所在那一格）与 `closeEnd`（公式之后）
**在屏幕上是同一根像素** —— 收尾 `$` 不可见，两者无从分辨。停在它上面有两个害处：
1. 用户按 `→` 会以为"按了没反应"（光标其实挪了，只是看不出来）
2. 在它上面断块会把公式**劈开**（`$` 配成单数 → 整行退化成源码；用户实测抓出）

⇒ **`→` 的语义是"往前走 / 出去" → 一步出公式**；
**`←` 的语义是"回去 / 进去" → 停在公式末尾继续改**。
不对称是**刻意的**，`test/render/math_nav_test.dart` 里有专门一条钉住它
（防以后有人"顺手统一"）。

★ **讨论中撤回的一条论证**：曾用"`+c` 的排版在数学里与正文里不一样"论证
"必须写进公式里"。**那是"公式块"思路，与本项目的第一原则冲突，已撤回。**
按「同权」：`$…$` 只是**渲染提示**，不是语义墙；**用户没写进公式里的东西就是文字**
（他手打 `$` 或粘贴外部 LaTeX 造成"内容在对象外"，我们**不替他猜着搬进去** ——
那会变成魔法，与"渲染是源码的忠实投影"冲突）。
⇒ 由此得到两条交互结论（已实现/已排期）：
- **默认落点在公式外侧**（从公式后面接着写 = 写文字）
- 要往公式里追加 = **显式动作**（`←` 或点最后一个字形的右半边）

#### ★★ 同一根像素上的两个位点（2026-10-15 定）

`$` 不可见 ⇒「公式末尾（tex 末尾）」与「公式之后（`closeEnd`）」**在屏幕上是同一根像素**。
它们**在数据上是两个偏移，必须分别保留**（甲、打字去向、守门人、`Tab`、选区、提交点、光标由谁画都要用它们），
但**在"删什么 / 点什么"上必须给出同一个结果**：

| 场景 | tex 末尾（**在公式里**） | 公式之后（在外面） | 判定 |
|---|---|---|---|
| 打字 | 进公式 | 进正文 | ★ 必须区分 |
| `→`（甲） | 一步走出公式 | 已在外面 | ★ 必须区分 |
| `←` | 停在末尾 | **回到**末尾 | ★ 必须区分 |
| `Enter` 守门人 | **会劈开公式** ⇒ 推到 `closeEnd` | 正常开新块 | ★ 必须区分（§11.16 二实测） |
| `Tab` | 走槽 / 最后出公式 | 不参与数学导航 | ★ 必须区分 |
| **删除（两个方向）** | 删左边那个**可见对象** | 删左边那个**可见对象** | ★★ **行为必须相同** |
| 光标由谁画 | 数学段注入 `\cursor` | 文字段画零宽条 | ★ 必须区分 |
| §6.5 范围高亮 | 整段淡范围 | 不高亮 | ★ 必须区分（**把区分变可见的正规手段**） |
| 失焦提交点 / normalize | "仍在段里" | "已离开该段" | ★ 必须区分 |
| 拖选端点（⑤） | 选区**含**公式 | 不含 | ★ 必须区分 |

**规律（推广到所有不可见定界符，含裸花括号组）**：
> **删除与点击不区分；方向性语义区分；可见范围负责让人看懂。**

> **点屏幕定位**（§五）与此**共用同一套位点表** —— 鼠标与键盘最后都落到"一个位点"上，
> 这是"同权"在代码上的体现（也是 S1 问 0 ③ 的延伸）。

## 四、结构感知删除（smart delete）

**目标手感**：像删字符一样干脆，但**永不留下半个坏公式**。

### 4.0 ★★ 通则：删除的目标 = 「与光标**同层**的、紧邻的那一个渲染对象」（2026-10-15 定，用户提出）

> **「同层」= 光标所在槽的那一层** —— 位点表（§二）已经给出槽路径，**不需要新判据**。

| 同层紧邻的是 | 删除目标 |
|---|---|
| **原子** | 那个原子（`\alpha` 一次删光；裸参数 `b^2` 的 `2` **连 `^` 一起走**，见 §4.1.1） |
| ★ **结构**（分式 / 根号 / 大算符 / 环境 / 上下限） | ★ **整个结构，含它的内容** —— 在这一层上它就是一个对象 |
| ★ **算子 + 它的作用域**（`\sin 2x`、`\sum_{i=1}^{n}a_i`） | **整个操作对象**（作用域表见 §4.7） |
| ★ **同层什么都没有**（空槽） | ★ **只移动**（等同方向键）—— 空槽**不是**可删对象（用户 2026-10-15 拍板） |
| **空公式**（主行没有内容，只有 `$$`） | **空壳是一个可见对象**（§6.1.1 画出来）⇒ 删掉整个空壳 |
| **不可见定界符** `$` / `$$` / `{}` | ★ **不属于任何层、不是对象** ⇒ 永远不是删除目标 |

★ 这条通则**同时覆盖**公式内、公式外、文字里三种情形，不需要按位置写特例。

**由来（两段实测）**：

1. 用户实测「光标在分式**后面**（不是分子分母里）按退格 → 只删掉了收尾 `$`，`\frac{}{}` 的编码爆出来了」
   ⇒ 暴露出 §3.3 原先只写了"公式首"、**"公式尾"从来没写**，实现只好掉进字节级兜底。
2. ★ 用户实测「点分式**整体**后面按删除 → 只删了分母里的 `b`、出现空位框，**没有删掉整个 `a/b`**」
   ⇒ 暴露出**判据不带层级**：`_atomLeftOf` 只找"最近的可见原子"，**跨过了分式的边界**。
   **这就是"要在同一层上找邻居"的由来。**

**硬边界（= 通则的直接推论）**

| 光标位置 | `Backspace` | `Delete` |
|---|---|---|
| **公式之后**（`closeEnd`，紧贴公式右侧） | 删左边紧邻的**同层可见对象**（是结构 / 算子整体 ⇒ 整个走；删空了 ⇒ 留空壳 §4.6） | 删右边紧邻的对象（通常是文字） |
| **公式之前**（`openStart`，紧贴公式左侧） | 删左边紧邻的对象（通常是文字） | 删公式内**第一个同层可见对象** |
| **公式内末尾**（tex 末尾，收尾 `$` 之前） | ★ **同"公式之后"** —— 同一根像素必须同一行为（§3.3） | 删右边紧邻的**可见**对象（跳过收尾 `$` —— 现有实现已对） |
| ★★ **挂件的边缘那一格**（脚本 `^`/`_` 的右端；定宽 accent 的**两端**） | 见 §11.23 —— **按可见墨迹走**：`⌫` 取左邻墨迹、`Del` 取右邻墨迹；**会把挂件掏空 ⇒ 整个挂件走**（accent）/ 留合法的空组（脚本，§4.1.1） | 同左（同一根像素 ⇒ 同一行为，§3.3） |
| **公式内开头**（tex 开头） | 删左边紧邻的可见对象（跳过开头 `$`） | 删公式内第一个同层可见对象 |
| ★ **结构层位点**（结构的前 / 后边界，位于**外层**） | ★ 删**整个结构**（含内容） | 删右边紧邻的同层对象 |
| 公式**内**其余位置 / 结构**内** | §4.1 / §4.2 的规则（★ 空槽 ⇒ 只移动） | 同左 |

★★ **哪些东西正常编辑时"删不掉"（这是设计，不是缺陷）**：

| 东西 | 为什么删不掉 |
|---|---|
| 分数线、`\log`、`\sum` 这类**结构符号本身** | §2.2 位点表：结构命令名内部 / `{` `}` `^` `_` / 语法夹缝 **不产出位点** ⇒ 光标根本到不了那儿 |
| 结构里的**空槽** | 同上（空槽只有"槽内那一个位点"）⇒ ★ 空槽里退格**只移动**，不是删除目标 |
| **定界符** `$` / `$$` | §3.3 通则：对用户不可见 ⇒ 永远不是编辑目标 |

⇒ 删结构的**唯一**路径 = **§4.0 通则的"结构层位点"**（结构前 / 后边界，位于外层）——
键盘走到那儿、鼠标点到那儿（后者要结构几何，见《编辑地基与手感》②）；空槽里只有"移动"。

### 4.1 原子删除（默认行为）

光标前（`Backspace`）/ 后（`Delete`）若紧邻一个**可见原子** → **整个原子一起删**。
`\alpha` 五个字符一次删掉 —— 用户感知是"删掉一个符号"。

#### ★★ 4.1.1 例外：`^`/`_` 的**裸参数**要连 `^`/`_` 一起删（2026-10-14 实测抓出，10-15 补进规格）

> ⚠️ 本节是**规格级修正**：本文 v0.2 原话是"`x^2` 的 `2` 一次删掉"，
> 那句话**误导了实现**，导致产品里留下一个真 bug。现按实测改正。

| 情形 | 行为 |
|---|---|
| `x^2` 里删 `2` | **`^2` 整体消失**（得到 `x`）—— **不是**只删 `2` 留下 `x^` |
| `b^{2}` 里删 `2` | 只删内容（得到 `b^{}`）—— **花括号形式不受影响**，`{}` 是合法的空组 |

**为什么**：`^` 后面必须跟一个"组"。留下裸 `^` 会让引擎立刻报
`Parser Error: Expected group after '^'` —— 公式位置变成红字 `❌` 回退块。
**脚本本来就是一个整体：要么都在，要么都不在。**

**用户给出的原始复现路径**（这条比任何构造用例都值钱）：
> 「我点击根号里面的 `c` 后面，从这里删，一直点删除键，就会触发」

即：行间公式 `x = \frac{-b \pm \sqrt{b^2-4ac}}{2a}` 里，光标放到 `\sqrt` 的 `c` 之后，
**按删除键（= 退格）连按**，删到 `b^2` 的 `2` 时触发。轨迹：
`\sqrt{b^2-4ac}` → … → `\sqrt{b^2}` → **`\sqrt{b^}`**（就是这个中间态炸的）。

**实现落点**（两处都要判断，缺一处就漏）：
1. `smart_delete.dart:_removeAtom` —— 删可见原子时，若它紧跟 `^`/`_`，起点左移一字符
2. 同文件删整组 `{...}` 的两条分支（`Backspace` / `Delete`）—— 同理左移

**守门人测试**：`test/editor/edit_view_test.dart` 的
「★ 回归：行间公式里 `\sqrt{b^2-4ac}` 连按删除键（用户原始复现路径）」——
含 Backspace 连按 12 次、Delete 连按 12 次、Delete 在裸参数 `^2` 之前三条。
★ 这三条**已用"临时回退修复"验证过真的抓得住**（见 §11.15 三的同款做法）：
回退后 Backspace 那条与「Delete 在裸参数之前」那条变红并报出用户看到的那句话；
而「Delete 连按（从 `c` 后面起步）」**即使回退也是绿的** ——
它的起点在往前删到 `b^2` 时，邻居是运算符而不是 `^`，**结构性绕开了这个 bug**，
属于**假通过**，已在测试注释里明确标注（留着是因为它守另一条不变量）。

#### 4.1.2 与 §4.2 / §4.3 的优先顺序（实现按此顺序判断）

1. §4.1.1 的"连 `^`/`_` 一起删"只在**确实要删这个原子**时生效
2. §4.3「全空结构整体删」优先于原子删除
3. §4.2「槽间跨越只跳不删」优先于原子删除

### 4.2 槽间跨越（不是删除）

光标在**槽的首位点**、且前一个位点在**另一个槽内**时，`Backspace` = **跳到前一个位点**，
**不删任何内容**（与 Word/MathType 一致：结构墙要靠方向键跨，不靠退格拆）。
`Delete` 在槽末位点同理向后跨。

### 4.3 结构单元的删除：**在它自己那一层上删**（2026-10-15 改口径）

**结构单元** = 一个结构命令 + 它的全部参数槽（`\frac{a}{b}` 整体、`\sqrt{2}` 整体、`^{}` 整体）。

- ★ **删除目标是"与光标同层的对象"**（§4.0 通则）⇒ 在**结构层位点**（结构前 / 后边界，位于外层）
  退格或删除 ⇒ **整个结构连内容一起消失**（用户口径：「点分式整体后面删 = 删整体」）
- ★ **在结构内部（槽里）**：删的是**那一层的内容**；槽**空**时 ⇒ **只移动**（等同方向键），
  **绝不**因为"槽空"就**连坐**删掉整个结构（用户 2026-10-15 拍板；**撤回**我 10-15 早先提的"空槽 ⇒ 删所属结构"）
- ★ 旧判据「全空才删」（`u.allEmpty && u.end == r`）**作废**：
  它只在 **tex 末尾那一个位点**可达 ⇒ 直接造成「删不掉根号」（§11.16 六）；
  而且它**真正反对的只是"手术"**（删分数线、把分子分母并到主行），与"整体删掉"无关。**手术仍然不做**（§十-②）
- ★ 由此：**「删不掉根号」不是删除规则的问题** —— 结构层位点（`$\sqrt{}$` 的 tex 末尾）今天就能删掉整个根号；
  缺的是**那一层可达 / 可点** ⇒ 归《编辑地基与手感》**②③④**

### 4.4 降级模式

tex 配对失败（§2.3 降级位点表）时，删除**退化为字节级**：`Backspace` 删一个字符。
理由：结构树不可靠时，"按结构删"会做出用户无法预测的事；字节级虽然笨但**可预测**。

### 4.5 与 normalize 的分工

删除**允许**产生空 `{}` / 空结构；**回收只发生在提交点**（§七）。绝不逐击键回收
——否则用户删到一半，结构就被自动撤走了。

★ 但 **"空壳公式"（tex 空的 `$$`）本版不回收**（2026-10-15 定）：既然 §4.6 决定留空壳、
且 §6.1 要求把它画出来，就不该在失焦时偷偷把它收走（那会让人莫名其妙）。
`normalize` 收到的只是 **tex**，本来也够不到定界符。

### 4.6 删到 tex 空 → **留空壳**（2026-10-15 用户拍板）

在公式**内部**把内容删光（tex 变成空 / 全空白）时，**不删定界符** —— 留下 `$$` 这个空壳。

理由（用户的原话归纳）：
- **有撤回**（`Ctrl+Z`）兜着，不用怕
- 留空壳才能"删掉一个字符接着重打"（Word 也是这个行为）
- ★ **但必须配套：空公式要画出来**（见 §6.1）—— 否则 `$$` 渲染出来是**零尺寸**，
  既看不见也点不到，成了**幽灵**，只能靠"再按一次退格"清掉（用户实测遇到过"按了没反应"）

★ 与 §3.3 通则不冲突：**用户明确按了退格**（他就是要删东西），我们只是不越界去删他看不见的定界符。
★ **要去掉整个公式**：**把空壳当作一个可见对象删掉**（§6.1.1 会把它画出来）—— 走通用规则，
**不需要"整段公式"这种特例**（旧 B2 / D2 已作废）。

### 4.7 ★★ 作用域表（算子 + 它的内容）—— 2026-10-15 新增

> **问题**：`\sin` / `\log` / `\sum` / `\int` / `\lim` 这类算子**"接上值"才形成整体**，
> 而 LaTeX 语法里**那个值不属于它** —— `\sum_{i=1}^{n} a_i` 的 `a_i` 只是**主行上的下一个东西**。
> ⇒ **"一个操作对象到哪结束"必须另行定义**；这是 §4.0 通则里"算子 + 作用域"那一格的来源。
>
> **判据的根基（两条来源 + 一条修正）**
> 1. ★ **数学的优先级 / 结合力**：函数应用比加减紧；**并置乘法是一个"项"**；**写出来的运算记号 = 主运算 = 断点**
> 2. ★ **KaTeX 的原子类别**（`Ord` / `Op` / `Bin` / `Rel` / `Open` / `Close` / `Punct` / `Inner`）：
>    引擎已经把每条命令归了类 ⇒ 断点与黏结**不必我们自己猜**
> 3. ⚠️ 有一处**引擎与人读不一致**，**以人读为准**：TeX 把 `/` 归 `Ord`（所以 `a/b` 零间距），
>    但人**看得见一个除号** ⇒ 它断开。
>
> ★ 一句话记忆：**判据用"看不看得见一个运算记号"；引擎的类别只用来判"结构 / 括号 / 函数名"。**

#### 4.7.1 规则

```
【前提】只有 Op 类算子需要作用域：
        \sin \cos \tan \cot \sec \csc \arcsin \arccos \arctan \sinh …
        \log \ln \lg \exp \lim \max \min \sup \inf \arg \deg \det \gcd \dim \ker \hom
        \sum \prod \int \oint \iint \iiint \bigcup \bigcap \bigoplus \bigotimes …
        （\frac \sqrt \binom \overline \vec \hat \text (…) 的参数是【显式】的 ⇒ 不需要推断）

【起点】先吃掉【紧跟算子名之后的 ^ / _】及其参数 = 算子自己的
        上标 / 上下限 / 底数（这才是 sin²x 与 sin x² 的分水岭）

【扫描】沿【同一层】向右取最长一段；
        花括号组 / \left…\right / 环境格 = 层级边界，【不跨】
```

| 遇到 | 处置 | 为什么 |
|---|---|---|
| **可见的二元运算记号**：`+` `-` `\pm` `\mp` `\cdot` `\times` `\div` `/` `\ast` `\circ` `\cup` `\cap` `\setminus` `\land` `\lor` `\oplus` `\otimes` | ★ **停** | 手写出来的记号就是**主运算**（`\sin x\cdot y` = y·sin x） |
| **关系记号**：`=` `<` `>` `\le` `\ge` `\ne` `\approx` `\equiv` `\to` `\mapsto` `\in` `\subset` `\perp` | ★ **停** | 关系比一切算术都松 |
| **分隔记号**：`,` `;` `&` `\\` `\end` / 本层右括号 | ★ **停** | 分隔符划界 |
| **另一个算子名（Op）** | 参数**还没开始** ⇒ 它是参数（嵌套：`\sin\log x`）；参数**已开始** ⇒ ★ **停**（`\sin x\cos y` = sin x · cos y） | 两个"算子+参数"并置 = 相乘，不是嵌套 |
| 文末 | **无值** ⇒ 见 4.7.4 | 没接上值 = 没形成整体 |
| **并置的原子 / 上下标 / 包裹结构 / `\text{}` / 间距命令（`\,` `\;` `\quad`）** | ★ **黏结** | 没有运算记号 ⇒ 它们在**同一个项**里 |

★ **两条自动得到的正确行为**（不需要写特例）：

- **`\sin^2 x` vs `\sin x^2`**：`^` **紧跟算子名** ⇒ 归算子（`sin²x` = (sin x)²）；
  `^` 跟在**参数**后面 ⇒ 归那个原子（`sin x²` = sin(x²)）—— 与 TeX "上标归前面那个原子"完全一致
- **`2\sin x`**：`2` 与 `\sin x` 是**两个对象**（作用域只管算子**右边**）

#### 4.7.2 例子

| 手打 | 作用域 | 对象 |
|---|---|---|
| ★ `\sin x\cdot y` | `x` | `\sin x` ＋ `\cdot y`（= y·sin x） |
| ★ `\sin x\cos y` | `x` / `y` | 两个对象 = sin x · cos y |
| `\sin 2x` | `2x` | `\sin 2x` |
| `\sin x+y` | `x` | `\sin x` ＋ `+y` |
| `\sin(x+y)` | `(x+y)` | 括号 = **显式声明** |
| `\sin\log x` | `\log x`（嵌套） | `\sin\log x` |
| `\sin^2 x` / `\log_2 x` | `x`（`^2` / `_2` 归算子） | `\sin^2 x` / `\log_2 x` |
| `\sum_{i=1}^{n}a_i b_i` | `a_i b_i` | 整个求和式 |
| `\int_a^b f(x)\,dx` | `f(x)\,dx` | 整个积分（`\,` 不破） |
| `\int_a^b f(x)\,dx+c` | `f(x)\,dx` | ＋ `+c` 在外 |
| `\lim_{x\to0}\frac{\sin x}{x}` | 那个分式（里面的 `\to` 在花括号里，不破外层） | 整个极限式 |
| `\gcd(a,b)` | `(a,b)` | 括号里的 `,` 不外溢 |
| `2\sin x` | `x` | `2` ＋ `\sin x` |

#### 4.7.3 不变量（property test 钉死）

| | 性质 |
|---|---|
| **P1** | 每个 Op 实例**有且只有一个**作用域（或"无值"） |
| **P2** | ★ 作用域内**不含任何同层的二元 / 关系 / 分隔记号**（把规则本身变成可断言） |
| **P3** | 作用域 ≥ 1 个紧整体（"无值"单列） |
| **P4** | 同层作用域**要么不相交，要么严格包含**（嵌套） |
| **P5** | 作用域**不跨层级边界**（花括号组 / `\left…\right` / 环境格） |
| **P6** | 作用域起点 = 算子 + 它自己的 `^` / `_` 之后 |

#### 4.7.4 半成品（无值算子）与提交点

适用情形：`\sin` 在文末 · `\sin+` · `\sin\pm` · `\sin)` · `\sin,` · `\sin\cos`（前一个没值）· `\sum_{i=1}^{n}`（只有上下限）。

1. ★ **打字过程中一律静默**：作用域 = **空（无值）**，不闪告警、不变红（半成品是常态，§2.3 已定）
2. **对象就是算子自己**（含它自己的 `^` / `_`）⇒ 在它右边退格 = 删掉这个算子；双击 = 选中它
3. ★ **只在提交点**（失焦 / 光标离开该数学段 / 粘贴完成）进「问题清单」：`\sin 缺少作用的内容`
   —— **原则 5：可见、不阻断**（`$\sin$` 渲染上完全合法，会照常画出 "sin"，**不出红字**）
4. ★ **大算符（Σ / ∫ / ∏）不提示**（2026-10-15 用户拍板）：`\sum_{i=1}^{n}` 本身就是一个完整的排版对象

#### 4.7.5 毛边取值（2026-10-15 已拍板）

| 情形 | 取值 | 说明 |
|---|---|---|
| `\sin x/2` | `/` 是**可见除号** ⇒ **破** ⇒ sin(x)/2 | 与 `\cdot` 同办；★ 我们的主路径（符号面板）产生的是 `\frac`，`/` 只从**粘贴 / 手打 / 导入 md** 进来；**绝不自动改写成 `\frac`**（原则 1/2：源码是唯一真相、不许替用户改） |
| `\sin\frac{a}{b}x` | **黏结** ⇒ sin(a/b·x) | 并置就是一个项；有疑问加括号 |
| `\sin x y` | **黏结** ⇒ sin(xy) | 要 sin(x)·y 就写 `\sin(x)\cdot y` |
| `\quad` 这类大间距 | **黏结**（它不是运算记号） | 否则 `\,dx` 会被切断 |
| ★ **`\frac{d}{dx}f`（导数算子）** | **不绑**（它不是 Op 原子）⇒ 内容仍是主行对象 | **已知不覆盖**；要"整体"就用模板 / 括号 —— 诚实记录，不硬塞 |

★ **元原则（三条，缺一不可）**：① **保守可预测** ② **要精确就写括号** ③ **看得见** ——
作用域由 §6.5 画成**淡范围**，用户随时能看见"算子吞到哪"，吞错了加个括号就行。

★ **实现纪律**：开工第一步**先用探针把"哪些记号带二元间距"量出来钉成表**（同 `\\` 那次：引擎行为一律实测）；
作用域是**只读元数据**（纯函数、可单测），**绝不参与渲染、绝不改写源码**。

---

### 4.8 ★★ 必填槽 / 可选槽（2026-10-15 用户提出）

> 用户原话：「有一些符号的一些位点可能是**可以提供但不一定需要填写**的 ——
> 比如说**根号的左上角**、**求和符号的上面和下面**（有的时候在非标准的描述性语言中确实不一定非要填）、
> 以及**积分符号的积分起点和终点**（如果是不定积分的话）」。

| 类 | 例 | 位点 | 空着算不算问题 | 占位怎么画 |
|---|---|---|---|---|
| **必填** | 分式的分子 / 分母 · 根号的被开方数 · ★ **函数算子的内容**（`\sin` 后面那个值） | 提供 | ★ **函数算子缺内容** ⇒ 提交点进「问题清单」（§4.7.4） | **恒可见**（§6.1，用户 10-15 拍板） |
| **可选** | 根号次数 `\sqrt[n]{□}` · 上下限 `\sum_{□}^{□}` · 对数底数 `\log_{□}` · ★ **积分起终点**（不定积分 ⇔ 没有） | ★ **照样提供** | ★ **永远不算问题** | ★ **只在光标进入该结构时才画**（不打扰）—— ✅ **2026-10-15 用户拍板并已实现**（§11.20） |
| ★★ **挂件槽**（第三类，2026-10-15 晚用户拍板） | **脚本 `^`/`_`** · **定宽 accent 的参数**（`\hat{x}` `\bar{y}` …） | 提供 | ★ 永远不算问题 | ★★ **不画**（连"当前槽"也不画）—— 见下面 |

★★ **第三类的理由（用户的模型：挂件挂在/套在基座上，不是结构）**：
- 文本里的一个字**旁边没有格子**；给挂件画框，就是把"渲染提示"画成了"一个域"；
- 空挂件**已经有可见落点** —— 基座字符本身就在那儿（accent 则那顶帽子在），**不是幽灵**；
- 光标进去时**自己会把位置画出来**（§6.2 的自绘竖条）⇒ 不必再造一个方框；
- 光标离开后留下的空挂件，**提交点 `normalize` 会回收**（下面那条既有行为）。
- ⚠️ 但 `\sum_{i=1}^{n}` / `\log_{2}` / `\int_a^b` 的**上下限与底数**在源码里**就是脚本槽**
  —— 它们属于上面的**可选槽**，**不是挂件** ⇒ 判据必须把它们排除（两边**共用作用域表** `scope_table.dart`）。
- ⚠️ **会拉伸的 accent**（`\overline{}` `\widehat{}` …）的参数**仍照旧画框**：它们空着只剩一条线 /
  什么都没有，需要可见落点（它们与定宽 accent 是**两族**，见 §11.21.3）。

★ **位点怎么来（重要）**：**模板插入时就把 `_{}^{}` / `[□]` 写进源码** ⇒ 位点**天然存在**，
**不靠注入造位点**（注入造位点是"为显示而注入反噬数据映射"那条老坑）。
手打裸 `\sum`（没有 `_{}`）**就是没有那个位点** —— 如实按主行，不猜（§4.7 的不做魔法）。

★ 与 §4.7.4 的关系：**"无值 ⇒ 问题清单"只对【必填】内容生效**（`\sin` 缺被作用内容）；
**可选的上下限 / 次数 / 积分起终点空着，一个字都不提示** ✓。

★ 与 `normalize`（§七）的关系：提交点会把**空的脚本 / 空结构**回收
⇒ `\sum_{}^{}` → `\sum`、`\sqrt[]{x}` 里空的次数槽也走同一条规则 ✓（**既有行为正好对**，不需要新规则）。

## 五、点击命中（鼠标与触控的精细判定）

### 5.1 三段管线

```
全局坐标
  ├─ 落在文字段 → RenderParagraph.getPositionForOffset  → 字符级偏移
  ├─ 落在数学段 → hitTestMathTex(叶盒 ↔ 可见原子 zip)     → 原子左/右边界
  └─ 落在数学段但命中的是"装饰盒"（已被 leaf_boxes 过滤）→ §5.2 归属表
        ↓
   统一出口：snapToNearestSite(段起点 + 局部偏移) → 一个位点
```

★ **鼠标与键盘共用同一个出口** —— 这保证了"点哪儿"和"按几下方向键"结果一致。

### 5.2 ★ 非字符元素归属表（本文件最需要拍板的一张表）

点到**分数线 / 根号横 / 矩阵括号 / 上下限连线**时，命中的是装饰盒（渲染里存在、结构里不是原子）。
归属规则要**写死**，否则"点分数线"的行为不可预测：

| 点的位置 | 归属 | 依据 |
|---|---|---|
| **分数线正中**（横线上） | **主行**位点（分式之后） | 分数线是"分式的分界"，点它等于点"这个结构本身" |
| 分数线**左侧外部** | 主行位点（分式之前） | 左半边 = 向前 |
| **根号横**（被开方数上方的横线） | **被开方槽**的首位点 | 用户意图是"改根号里的内容" |
| **根号勾**（左侧 √ 符号） | 被开方槽首位点 | 同上（整个根号是一个结构） |
| **矩阵/`cases` 的括号** | 最近的**格**（按 y 定行、`x` 定列） | 括号是边界装饰 |
| **`\sum`/`\int` 的上下限连线** | 上限槽 / 下限槽（按 y 判上下） | — |
| **`aligned` 的 `&` 对齐处** | 该行的最近位点 | S5 细化，S3 只要求不崩 |
| 距离任何原子 > `inflate` 阈值（默认 6 px） | 取**最近位点**（左右等距取左） | 与文本编辑器一致 |
| 数学段左右外侧空白 | 段首 / 段末位点（即"走出去"） | — |

### 5.3 边界与空隙

- **两个原子之间的空隙**（如 `a b` 之间）→ 取最近位点，左右等距取**左**
- **空槽的虚线框内**（§6.1）→ **直接进该槽**，不做就近（用户已经指得很清楚了）
- **上下标小字**（`x^2` 的 `2`）→ 叶盒 `inflate` 要足够（实测调参，S3-2 定）
- **双击** = 选中一个可见原子（`\alpha` 整体、`2` 一个）→ **S3 可后置**，不影响主线

## 六、空槽可视化与编辑区视觉小规范

> 这是 S3 唯一的"UI 设计"部分 —— **它是功能，不是装饰**：用户看得见位点，才敢点、敢 `Tab`。
> 完整的界面设计（顶栏/面板/三态布局）**留到 S4 开工前**（理由见对话记录）。

### 6.1 空槽

| 状态 | 画法 |
|---|---|
| **空槽** | 槽位置画**虚线占位框**（1 px 虚线、浅灰 `#B0BEC5`、宽度 **≥ 一个正文汉字**、高度随槽类型） |
| **当前槽** | 虚线框换成**实线 + 淡蓝底**（`#E3F2FD`），与光标同色系 |
| **非空槽** | 不画框（只靠光标位置体现） |
| ★ **空公式** | tex 为空 / 全白时，**整段画一个占位**（2026-10-15 新增，见下） |

★★ **空槽占位必须"一直看得见"，与光标在不在这一段无关**（2026-10-15 改，实现在 `39ccb93`）。

原先的实现是"`caretRel < 0` → 什么都不注入"，理由是"注入会让叶盒数 ≠ 原子数 → 点不回公式里"。
**那个根因当天晚些时候就被根治了**（命中改用 `renderTex` + `renderToSourceOffset`），
而这条临时措施留了下来 —— 后果是**用户粘贴 `$\frac{}{}$` 后什么都看不见**：
光标恰好停在闭合 `$` 之后那一格，被判"不在这段里"→ 不注入 → **空分数只有 3.4 px 宽**。
规格从来没有"只在光标处画占位"这条附加条件。**空槽就该一直看得见。**

★★ **空槽占位要 ≥ 一个正文汉字宽**（2026-10-15 用户提出，实测依据）：

| | 宽度（正文字号 16 px） |
|---|---|
| 一个中文汉字 | **16.0 px** |
| `\frac{}{}`（**未注入占位**） | 3.4 px ← 就是"看着像消失"的那条线 |
| `\frac{\square}{\square}`（现在注入的占位） | **13.2 px** ← 比一个汉字窄，手机上更明显 |

空槽占位不只是"好看"：它是**点进空槽的触摸目标**（手机上尤其是），所以宽度按**正文汉字**定标。
★ 待定：撑宽分数线要用"只占宽不画"的东西（如 `\hphantom{汉}`），
但**它会不会给引擎多出一个叶盒是未测的**（多一个叶盒就会打破"叶盒数 == 可见原子数"）
⇒ **先探针实测再定**（与 §11.16 同一条纪律）。

★ 实现要点：`\cursor{}` 是**引擎注入的竖直条**，它和虚线框是两套东西 ——
虚线框要**自绘**（`WidgetSpan` 或 `\phantom{}` + 自绘覆盖层），风格要与光标一致（见 §十-④）。

#### ★★ 6.1.1 空公式必须画出来（2026-10-15 新增）

`tex` 为空 / 全空白时，**渲染一个占位字形**（复用 `\square` 那一套），使空公式
**看得见、点得进、退格删得掉**。

**为什么必须做**：§4.6 决定"在公式内删到空 → 留空壳"。
而空 `$$` 目前渲染出来是**零尺寸**（`buildCaretSites('')` 里没有任何槽可注入）
→ 既看不见也点不到 → 是个**幽灵**，用户只能靠"再按一次退格"清掉（实测："按了没反应"）。
⇒ **"留空壳"与"画出来"是一对，不能只做一半。**

### 6.2 光标

| 位置 | 画法 |
|---|---|
| 文字段内 | `InlineMathText._caretBar()`（0 宽占位 + `OverflowBox` 溢出绘制；1.5 px 宽、`fontSize × 1.25` 高，蓝 `#1E88E5`） |
| 数学段内 | ★★ **零尺寸锚点 + 自绘竖条**（2026-10-15 晚改，见 §11.23）：tex 里只注入一个 `\rule{0pt}{0pt}`（**不占一个像素的版面**），竖条由 `render/math_caret.dart` 的 `MathWithCaret` 用 `CustomPaint` 叠着画（尺寸/高度可控，与文本侧同高同色） |
| 闪烁 | 500 ms 周期（系统默认感觉）；**★ 闪烁不得触碰其它单元**（见 §八）—— ⏳ 未做 |

★ 为什么要自绘（一句话）：引擎那根 `\cursor{}` 是 **1.5 × 14 px 的实心竖条、真的参与排版**
⇒ 光标一进公式就把盒子撑高/撑宽，accent 那类装饰不跟着走 ⇒ 用户看到"帽子跟字脱开、跳了一下"。

### 6.3 选区

S3 只做两件事：**文字段内拖选** + **`Shift+←/→` 跨段到数学位点**。
高亮色建议 `#BBDEFB`（与光标同色系、透明度更高一档）；数学段内部高亮**留到 S5**。

### 6.4 字号与尺寸

沿用 `DocSettings`（正文 16 / 行距 1.7）；光标宽度、虚线框、`inflate` 阈值都**跟随正文字号缩放**，
不写死像素 —— 否则改字号后视觉会失衡（S2-4 已支持文档级改字号）。

### 6.5 ★★ 公式的可见范围（2026-10-15 新增，**排期：视觉规范批**）

**问题**：定界符不可见，而公式本身也没有任何"范围"提示 ⇒
**"光标在公式里"与"光标在公式外"画在同一根像素上**。它带来三个实际麻烦：
1. `→` 必须靠 §3.3 的「甲」**跳过**那个看不见的位点（否则像"按了没反应"）
2. 用户**分不清**自己接下来打的字会进公式还是进正文（`\frac{a}{b}x` vs `\frac{a}{b}$x`）
3. **W1**：末尾那个分式"外面"几乎点不到（公式没有可见外沿，无从瞄准）

**做法**：⚠️ **2026-10-15 晚：第一版"给整段刷淡色底"已撤** —— 用户指出那等于把"**渲染提示**"画成"**一个对象**"：`$\frac{a}{b}=\sqrt{2}$` 在他眼里是**三个对象**（分式 / `=` / 根号），**不是一整个公式**（同地位原则；也正是过闸表 §7.2 里"公式有专用底色 = 症状"）。**动机保留、手段待定**：只允许"像文本装饰 / 只在边界"的手法，不许"像卡片 / 覆盖整段"；动手前先过 §7.2 的闸（《编辑地基与手感》§六-6）
（淡色底 / 下划线，与 §6.2 光标同色系、透明度更高一档 —— 与 §6.3 的选区色系一致）。

**收益**：三件事一起解 —— 上表 1/2/3 全部消失；
而且它让"§4.0 按可见对象删"在**视觉上也说得通**（用户能看见"对象"的边界在哪）。

**与 §十-④ 的关系**：这条与"虚线框自绘""空公式占位"同属**同一批自绘覆盖层**的工作，
建议一起做（都需要从 `leaf_boxes` 拿坐标，而不改 tex）。

★ **算子的作用域也一起画**（2026-10-15 补，§4.7）：光标落在某算子的作用域里时，给**整个作用域**一个淡范围 ——
用户随时能看见 `\sin` / `\sum` 吞到哪；吞错了加个括号就行。
它与"公式范围"是**同一套自绘覆盖层、同一支画笔**（都从 `leaf_boxes` 取矩形、都不改 tex）。

## 八、性能与失效范围（承接 S2 的硬约束）

S2 的三条硬约束在 S3 依然成立（单元级 widget 缓存 / 测量树与渲染树各用各的池 / 同一实例不放两处），
S3 新增两条：

1. ★ **光标闪烁必须不触碰文档树。**
   陷阱：数学段内的光标是**注入 `\cursor{}`** 实现的 → 注入改变了 tex 字符串 →
   而 S2 的池是按**内容**判等复用的 → **光标每闪一次，当前那一个数学段必然重建**（tex 变了）。
   → 约束：闪烁只允许重建**当前那一个数学段**，**绝不能**让整篇段落进入 build。
   → 若实测掉帧（release 单公式 ≈ 8 ms，1 Hz 闪烁应当无感），备选方案 = **自绘光标**
   （用 `leaf_boxes` 拿坐标，不改 tex）→ 见 §十-④。
2. ★ **击键的失效范围 = 当前 FlowUnit**（`块模型与md往返.md` §六）：
   打字只重绘当前块；**位点表与邻接表要按段缓存**（tex 没变就不重算），
   否则每次击键都要重新词法化 + 配对扫描全文的公式。

**测试优先（S2 的方法论）**：位点表 / 邻接 / 删除 / normalize 都是**纯 Dart 纯函数**
→ 全部用**单元测试**钉住（含 §2.4 的 property test）；浏览器只当"肉眼看一眼"。

## 十一、S3-1b 输入通道实验结论（2026-10-14 · 实测）

> 目的：确定 S3-2「编辑面」的**输入设备**。
> 实验页：`app\lib\spike\ime_input\ime_input_page.dart`（实验台入口「★ S3-1b · 中文 IME 输入通道」）。

### 11.1 ★ 结论：**文本走平台文本通道，命令键走键事件**（两条通道分工）

| 通道 | 负责什么 | 实测证据 |
|---|---|---|
| **平台文本输入**（镜像输入框 / `TextInputConnection`） | **一切文本**：ASCII、中文、IME 组合、粘贴、自动更正 | 输入「中文测试abc」→ 缓冲区**一次编辑**写入 `Edit[0,33)`；中文完整到达 |
| **键事件**（`Focus.onKeyEvent`） | **命令键**：`Tab` `↑↓←→` `Backspace` `Delete` `Enter` `Home/End`、快捷键 | 合成 `Backspace` → `按键 1 次 · character=<null>` 正确到达 |

★ **这正好分工**：文本与命令走不同通道、冲突面极小 —— 与真实编辑器（CodeMirror / ProseMirror / MathLive）一致。
**S3-2 的"编辑面"按此实现，不要用键事件拿字符。**

### 11.2 为什么"用键事件拿字符"是死路（问 0 现在的做法）

- 问 0 spike 用 `e.character` 把按下的字符插进缓冲区。这对 ASCII 勉强可行，但 **IME 组合发生在 DOM / 平台层**，
  组合文本不会作为按键事件出现 → 中文拿不到。
- ⚠️ **本次没能用自动化证伪它**：`browser_dock type` 走的是**直接插入文本**（CDP `Input.insertText`），
  **完全不合成按键事件**（连 ASCII 也没让 A 路计数）→ "A 路 0 次按键"**不能**证明"IME 拿不到"。
  → 真 IME 的最终确认**留给用户手工 10 秒**（§11.4）。
- 但方向已明确：既然文本本来就要走平台文本通道（Q1 已验证），**字符输入就不该依赖键事件**。

### 11.3 Q3 换算：两次平台文本值 → **一次**替换

`lib/editor/platform_text_diff.dart`（**纯 Dart**）：公共前缀 + 公共后缀 → 一次区间替换。

★ **为什么必须是一次替换**：IME 提交、粘贴、自动更正都是**一次语义编辑**；逐字符 diff 会拆成多次插入 →
**撤销栈炸开**（用户按一次撤销只回一个字）。

测试 `test/editor/platform_text_diff_test.dart`（11 条单测）：IME 提交（`zhong` → `中`）、中文插入、粘贴、
全量替换、公共后缀不被误判、清空……外加一条 **widget 端到端**（`enterText` → 缓冲区更新）与
一条**对照**（`enterText` 不产生键事件）。

⚠️ **已知限制**：`diffPlatformText` 按 UTF-16 码元比较，**未处理代理对（emoji）边界** ——
若一次编辑的边界落在代理对中间会切出半个字符。S3-2 验收时用 emoji 试一次再补。

### 11.4 手工确认结果（2026-10-14 · **已确认 ✅**）

用户在真机上用中文输入法实测（截图证据）：

```
组合态（IME 中间态）：《shu'ru'wen'ben》 @33..47
缓冲区（唯一真相）97 次编辑：「设 $x^2+1$ 为多项式，$\frac{a}{b}$ 为常数。 shu'ru'wen'ben」
```

- ✅ **Q1 通过**：中文能到达，且**组合中间态也能到达**（`composing` 区间有效）。
- ★★ **同时暴露一个必须处理的问题**（本节最重要的产出）：
  **组合中间态会一路进入镜像文本，并真的写进缓冲区** —— 证据是上面那两行：
  日志最后一条 `#97 Edit[46,46) +「n」` **带着《组合中》标记**（即这次编辑发生在组合期间），
  且**缓冲区里此刻存着尚未提交的拼音串 `shu'ru'wen'ben`**。
  半成品拼音进了缓冲区就会被当正文渲染、被 md 解析、并污染撤销栈。

  > 真正的证据是"组合期间编辑照样落地"这一条（日志标记 + 缓冲区内容）。
  → **政策（S3-2 必须实现）**：**组合中（`composing.isValid && !isCollapsed`）不写缓冲区** ——
  只记录组合区间与组合文本（供渲染层叠加显示用）；**组合结束**（`composing` 失效或塌缩）时，
  用一次 `diffPlatformText` 相对**未被污染的缓冲区**求出**一次**提交编辑写入。

### 11.5 顺带记下的环境事实（省下一次踩坑）

1. ★ **`document.hasFocus() === false` 时，CDP 合成的键事件照样到达页面**（实测 `Backspace` 到达），
   **但真实用户的按键不会** → "人能打字"必须在浏览器**拿到系统焦点**时才算验证过。
2. 浮窗浏览器的 `visibilityState` 会变 `hidden`（S2 老坑）→ `window minimized → normal` 可恢复。
3. CanvasKit 渲染下**文字不进 DOM** → `browser_dock_wait text=` 永远超时；读界面只能靠截图或语义树。
4. `browser_dock type` = **直接插入文本**（无按键事件）；`browser_dock key` = **合成键事件**。两者用途不同，别混。
5. 点击的**视觉效果会晚一帧**：点完立刻截图可能看不到状态变化（本次就因此误判"聚焦失败"），
   要紧的状态请再补一张截图。
6. ★ **CanvasKit 会刷"Shader compilation error"并丢白帧**（2026-10-14 用户实测）：
   点击后偶发白屏、动一下鼠标就恢复。控制台特征是**一串着色器编译失败**，
   而且**每个着色器都报 `(unknown error)`**（连平凡的都不放过）→ 更像**本机 WebGL/GPU 路径不稳**，
   不是某个具体图形写错了。对策：① 先用 **release 构建**复核（debug 的 CanvasKit 更脆）；
   ② 若 release 仍复现，再考虑简化光标那层的绘制（当前是 `SizedBox(width:0)` + `OverflowBox` 溢出画）。

### 11.6 架构含义（S3-2 照此实现）

```
镜像输入框（隐藏/透明，位置跟随视觉光标）
   ↓ 平台文本值变化
diffPlatformText(旧, 新) → 一次 PlatformEdit → DocBuffer.replace(...)
   ↓                                              ↑
   光标 / 选区由缓冲区的整数偏移决定 ←─────────────┘
命令键：Focus.onKeyEvent → 位点表 / 邻接表（S3-1 / S3-3）→ 只动光标，不动文本
```

★ **镜像输入框必须跟着视觉光标走**：Web 上 IME 候选窗与组合下划线由**浏览器**画在 DOM 输入框的位置，
镜像框若停在屏幕角落，候选窗就会出现在错误的位置（MathLive / CodeMirror 都专门处理这件事）。
→ S3-2 要把镜像框定位到当前位点附近（用 `hit_map` / 叶盒坐标算）。

### 11.7 ★ 组合中间态的处理（由 §11.4 的实测逼出来的规则）

```
平台文本值变化
   ├─ composing 有效且非空（用户还在打拼音）
   │     → 不碰缓冲区；只记 { composingStart, composingText }
   │     → （可选，v1 不做）在视觉光标处叠加显示拼音串 + 虚线下划线
   └─ composing 失效 / 塌缩（选字提交 / 取消）
         → 对着**未受污染的缓冲区**跑一次 diffPlatformText → 一次 Edit → 写入
```

三条配套注意：

1. **组合期间不要跑 normalize**（提交点判定里要把"组合中"排除）—— 否则半成品 `\frac{` 会被反复告警。
2. **组合期间的光标**：视觉光标停在 `composingStart`，不随后续拼音字母右移（否则光标乱跳）。
3. **取消组合**（按 `Esc` / 点到别处）：镜像文本会回到缓冲区内容 → `diffPlatformText` 返回 `null` → 天然无操作 ✅。
   → 这条可以**单测**：先组合再取消，断言缓冲区一字未动、编辑计数为 0。

### 11.11 ★ 点屏幕定位已完成（2026-10-14）+ 三处对 S1 结论的修正

**做法**（`DocView.onTapOffset`）：
- **文字**（段落/标题/引用/列表）：`RenderParagraph.getPositionForOffset` → 段落坐标 → 经
  `projection.dart:paragraphIndexMap` 换成源坐标（因为**每个行内公式在段落里只占 1 个码元 `U+FFFC`**）
- **行内公式**：`InlineMathText.onMathTap` → `hitTestMathTex`（叶盒 ↔ 可见原子）→ **位点吸附**
- **行间公式**：单元自己的 Math 渲染盒 → `hitTestMathTex` → 位点吸附
- 命中盒用**自带 `BuildContext` 的 `_UnitHitBox`**，不用 GlobalKey

**浏览器实测**：点段落中间 → 光标落在那句话中间；点行间公式里的 `-b` 与 `\pm` 之间 →
光标画在公式内部、偏移 84（正是 `\pm` 的起始位置）✅

★★ **但这一路把 S1 的一条结论推翻了**（详细数据见《技术选型与风险.md》9.8 的修正块）：

1. **叶盒过滤的旧判据是错的**。"真原子必然落在 Math 控件边界内"**不成立** —— 数学字形本来就画出根盒之外
   （`x` 的根盒才 7px 高、字形盒 16px；`\frac` 的分母盒压在边界上，而 `Rect.contains` 下边界是开区间）。
   → 旧判据下 6 个样本只有 1 个"叶盒数 == 原子数"，而 `hitTestMathTex` 数量不等时**静默返回 null**
   → **点屏幕定位对大多数公式悄悄失效**。新判据 = **宽度上限**（失真装饰盒比根盒大几十倍：1878px vs 74px）。
2. **命中要两趟**：旧实现"外扩后第一个包含"会让**前一个盒把点抢走**（差一个原子）→ 改成**严格包含优先，落空才外扩/就近**。
3. **`\sqrt[n]{body}` 的渲染顺序与源码顺序相反**（KaTeX 的 sqrt 节点是 `[body, index]`）；
   `lexVisibleAtoms` 必须按**渲染顺序**产原子（并把 `[` `]` 当语法跳过），否则点击次数会指到被开方数。

★ **教训**：S1 的"三验命中"是**在一个特定公式上**验的，而失效是**静默**的（返回 null，不报错）。
→ 现有 `test/render/leaf_boxes_test.dart` 把它变成**9 个公式 × 3 条断言**的回归测试：
数量一致、命中可靠、并且**逐盒逐原子**验证"点左半取左边界、点右半取右边界"。

### 11.12 ★ 用户真机实测后又抓出 6 个问题（2026-10-14 · 全部已修）

用户反馈"点哪儿都没规律"—— 顺着查下去是一串**互不相同**的根因，全是实测打出来的：

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| ① | 点 `x^2` 的 x 与 2 之间 → **红字 Parser Error** | 注入点紧跟 `^` / `_` 时，裸 `\cursor` 被当成**上标基座**（`Got function '\cursor' with no arguments as superscript`） | 注入改成 `\textcolor{…}{\cursor{}}`：**自带成组** → 脚本绑在组上 ✓ |
| ② | 文本里光标蓝、公式里光标黑 | 引擎 `\cursor{}` 用 `options.color`（= 公式文字色 = 黑） | 同一个 `\textcolor` 顺带把光标染成 `#1E88E5`；两侧颜色由**一个常量**推出 |
| ③ | `\text{中文}` 里点哪都报错 | **`\cursor` 在文本模式里完全不被接受**（实测 6 种写法全 ParseException） | 把 `\text{…}` **拆成两半**，光标落在两段之间（数学模式）：`\text{中}光标\text{文}` ✓ |
| ④ | 列表项点哪儿都落在**同一个**错位置 | 列表项子树里**第一个 `RenderParagraph` 是标记那个**（`•`，1 个码元），点内容区被它夹到末尾 | 按**纯文字内容**认内容段落（剥掉所有 `U+FFFC` 再比对） |
| ⑤ | ★ 文本里点击偏移"**没规律**" | **零宽光标条也是 `WidgetSpan`，在段落里照样占 1 个码元**（只是不占宽度）→ 光标只要已在本段文字里，段落坐标就比映射表多一格 → **整体偏 1**，且偏移量随光标当时的位置变化 | `paragraphIndexMap(..., caretInText:)`：把光标那一格也算进映射表 |
| ⑥ | 鼠标悬停文本不变"工"字形 | 只有数学段设了 `MouseRegion` | `_UnitHitBox` 外层加 `MouseRegion(cursor: text)` |

★ **⑤ 是最值得记的一条**：它是一个"**自己干扰自己**"的 bug ——
为了显示光标而插入的占位符，反过来破坏了"点击 → 光标"的换算。
它同时解释了用户看到的所有"没规律"现象（偏移量随光标位置漂移）。

**守门人测试**：`caret_sites_test.dart` 现在有"**在每一个位点上注入之后都必须能解析**"
（守住 ①②③ 那一整类）；`edit_view_test.dart` 有"列表项逐格点击映射必须精确"（守住 ④⑤）。

### 11.13 ★ 镜像输入框跟随光标（S3-2 最后一件，2026-10-14 完成）

**为什么必须跟**：Web 上**中文输入法的候选框由浏览器画在 DOM 输入框的插入符位置**。
镜像框原来钉在页面顶部 → 候选框出现在错误的屏幕位置（用户实测确认）。

**做法**：`DocView.onCaretRect` 帧末上报"**光标所在那一行**"的盒子（DocView 局部坐标），
`EditView` 把镜像框 `Positioned` 到那里：

- 位置/宽度**用整行**（左边界 = 段落左边界、宽度 = 段落宽度），字号 = 正文字号 ——
  这样镜像框内部排版与文档接近，浏览器算出来的插入符位置才和我们的光标对得上
  （MathLive / CodeMirror 也是这套：**让隐藏输入框的内部布局去逼近视觉布局**）。
- 光标在**文字段**里 → `RenderParagraph.getOffsetForCaret` 直接给位置；
  在**数学段**里 → 用该段占位符的 `getBoxesForSelection` 盒定纵向；在**行间公式块**里 → 放在公式下方。
- 单元渲染盒由 `_UnitHitBox` 帧末上报（自带 `BuildContext`，**不用 GlobalKey** ——
  光标会在单元之间移动，GlobalKey 跨位置迁移会直接抛错）。

**两个实测踩坑**：
1. **单元渲染盒晚一帧才有** → 首帧算不出矩形，镜像框先用一个兜底矩形占位
   （**必须始终挂着** —— 否则平台的文本输入管道会断，中文就进不来了）。
2. **光标落在"文末空行"时不属于任何单元** → 退回"**最后一个单元的行尾**"，
   否则镜像框会跑回页面左上角，候选框又飘了。

测试：`projection_test` 有 `caretParagraphOffset` / `mathPlaceholderAt` 的纯函数断言；
`edit_view_test` 有一条"**光标下移后镜像框必须跟着下移**"（直接断言镜像框的屏幕矩形）。

★ **踩坑（用户真键盘实测抓出来的）**：`_onMirrorChanged` 一开始只在**文本变化**时才回写缓冲区
→ 而**方向键只改选区、不改文本** → **按方向键光标纹丝不动**（中文、Enter、Backspace 都正常，唯独方向键"没反应"）。
→ 教训：镜像框是"输入设备"，**文本与选区是两条必须各自同步的通道**。
`test/editor/edit_view_test.dart` 已补两条：方向键只改选区也要同步光标（且**不算一次编辑**）、`Shift+`范围选区同步 anchor/caret。

### 11.14 ★★ S3-2 输入层重做（2026-10-14 · 真人键盘实测驱动）

> **这一节推翻了 §11.13**（"透明镜像框跟随光标"）。§11.9 末尾的修订块是最初判断，
> 本节是**做出来并验过之后**的完整结论。

#### 一、为什么"透明镜像框"这条路根本走不通

**现象**：中文候选框与组合下划线位置永远对不上（旧方案反复微调镜像框位置，只能"接近"）。

**根因（实测）**：Web 引擎把「隐藏 textarea」的插入符位置交给**浏览器**去算 IME 候选框的位置，
而镜像框里装的是**原始缓冲区**（`设 $x^2+1$ 为多项式，$\frac{a}{b}=\sqrt{2}$…`）。
实测样本：

```
<textarea class="flt-text-editing">   transform: matrix(1,0,0,1, 388.181, 279.191)
  value   = 原始缓冲区（201 字符）      selStart = 29
  font    = 16px（我们的字号确实生效了）
```
它用自己的字体把 201 个字符排一遍，插入符落在**它自己的某行某列** —— 与我们在页面上画的光标
**没有函数关系**。所以"把框摆到光标那一行"永远只能近似。

#### 二、真实的机制：可用的只有三条杠杆

读引擎源码 `flutter_web_sdk/lib/_engine/engine/text_editing/text_editing.dart`：

| 消息 | 引擎实际做的事 |
|---|---|
| `TextInput.setEditingState` | `element.value = text; element.setSelectionRange(min, max)` |
| `TextInput.setEditableSizeAndTransform` | `element.style.{width, height, transform}`（`EditableTextGeometry.applyToDomElement`） |
| `TextInput.setStyle` / `updateStyle` | `element.style.font*`（CSS 字体，`EditableTextStyle.cssFont`） |

★★ **`TextInput.setCaretRect` 在 Web 上是空函数**（源码原文）：

```dart
class TextInputSetCaretRect extends TextInputCommand {
  void run(HybridTextEditing textEditing) {
    // No-op: not supported on this platform.
  }
}
```
（SDK 的 Dart 侧注释也只说它是给 macOS 放重音候选菜单用的。）
⇒ **任何"只把 `setCaretRect` 接上"的方案都是白写**。这一条我们差点照着做了 —— 是**先读源码**救回来的。

#### 三、现行做法（`lib/editor/text_input_surface.dart`）

- **平台元素里几乎什么都不装**：不组合时文本为 `''`（⇒ 插入符就在**元素原点**），
  组合时只装"正在拼的那串"；元素被摆到**光标的精确 x**。
  ⇒ 浏览器算候选框的依据 = 元素原点 = 我们的光标，**与字体、与 `$`/LaTeX 宽度彻底解耦**。
- **两条通道各归各位**（§11.1 的结论，这次才真的做到）：
  **文本**（含 IME 提交）走平台文本值；**命令键**（退格/Delete/方向键/Home/End）走 `Focus.onKeyEvent`。
  → 镜像框时代把两者混在文本通道里，所以"方向键只改选区不改文本"要靠补丁同步 —— 那是症状不是设计。
- **组合中间态**：一个字都不写进缓冲区（§11.7）；但**接进排版**（只影响渲染），
  后面的字被**真的推开**、超出行宽会折行。**行间公式块例外**（它的排版文本就是 LaTeX 源码，
  塞字符进去会渲染失败）→ 那种情况用**叠画**兜底。

#### 四、★ 真机实测抓出的三个 bug（都不是猜出来的）

| # | 现象（用户实测） | 根因 | 修法 |
|---|---|---|---|
| ① | 选中的**汉字与中文标点输入后消失**（英文正常） | Chrome 选字是**两段式**：先把组合串**换成候选词**、**仍标"组合中"**，然后才结束组合。我在第一段把基线 `_platformText` 更新成了候选词 → 第二段的 `diff('好的好的','好的好的')` = `null` → 插入空 | 基线的含义是「**缓冲区对应的那份平台文本**」（本设计恒为 `''`），**组合期不许更新** |

#### 七、性能基准（跨平台同一把尺子）

`spike/s3_edit/s3_edit_page.dart` 里加了「基准(20字)」按钮，用 `FrameTiming` 采**帧工作量**：

★ **必须把"等待"和"工作量"分开报**，否则自欺：
- 第一版基准等了 2 帧 → 60Hz 下 2 帧 ≈ **33 ms 纯 vsync 等待**，量出 `p50=45 ms` 的假数字
- 现在报 `build`（Dart 侧构建布局）与 `raster`（光栅化）的 p50/p95，**不含等待** → 才能跨平台比
- 同时报**采到的帧数**：帧数不对就说明这次测量不可信（比给个假数字好）

##### ★★ 2026-10-14 实测：debug web vs release web（同一份样本 `kEditSample` · 20 字）
环境必须一致才能比：**1434×900 视口、`devicePixelRatio = 1.0`、页面可见**。

| | build p50 | build p95 | raster p50 | raster p95 | 一帧合计 p50 |
|---|---|---|---|---|---|
| debug web（`flutter run -d web-server`，DDC/JS） | 6.3 | 13.4 | 8.4 | 10.5 | **14.7 ms** |
| release web（`flutter build web --release`，dart2js -O4） | **2.2** | **5.0** | 9.0 | 10.7 | **11.2 ms** |
| 收益 | **2.9×** | 2.7× | ≈1（噪声内） | ≈1 | **1.3×**，余量 2 ms → 5.5 ms |

**结论（这是回答"各平台手感如何"的地基）**：

1. 一帧成本 = **build（Dart 工作量）** + **raster（像素活）**，两者性质完全不同：
   - **build 随"构建模式 / 平台"变** → **这才是"我们代码的成本"**
   - **raster 与构建模式无关**（同一套 CanvasKit/WebGL 路径），**由环境决定**：显示器缩放与窗口尺寸
2. ★ 本机屏幕缩放是 **150%**，所以 `dpr=1.5` 时像素量是 `dpr=1.0` 的 **2.25 倍**，
   光栅化实测 9.0（1.29 MP）→ 17.2 ms（2.90 MP），**完全由像素量解释**。
   → **换一台 100% 缩放的显示器，光栅化直接省一半以上 —— 这比换平台的影响还大。**
3. 纯 Dart 工作量：**release web 比 debug web 快 ~3×**。注意这是 **DDC→dart2js** 的收益，
   **不是** JS→AOT 的收益；AOT（Android/Windows）还能再快（待实测）。
4. ★★ **测量方法学（差点写成错误结论）**：
   **`browser_dock resize` 会改变 `devicePixelRatio`（1.5 ↔ 1.0）**。
   我在 `dpr=1.0` 下测了 debug、在 `dpr=1.5` 下测了 release，一度得出
   "release 光栅化慢 2 倍"的结论 —— **差的不是构建模式，是画布像素量**。
   → 跨测量对比**必须同时核对 DPR 与像素量**，否则会把环境差异当成代码差异。

### 11.15 ★★★ 「注入 ↔ 坐标」：一条被验证了四遍的经验（2026-10-14 晚）

> 一句话：**凡"为了显示而注入"的东西，都会改变数据映射。**
> 这条经验（开发日志 §四-1）今天在**四个不同深度**上各炸了一次，全部由**用户实测**逼出来。

#### 一、四层问题（同一句话的四个深度）

| 层 | 问题 | 症状 | 修法 |
|---|---|---|---|
| ① | `\textcolor{#1E88E5}{\cursor{}}` 的**颜色名被当成 9 个可见原子** | 叶盒数与原子数不等 | `visible_atoms` 跳过"不参与渲染的参数"（颜色名 / 尺寸 / 间距 / `\phantom`） |
| ② | 空槽占位让**渲染盒数 ≠ 原始原子数** | `hitTestMathTex` **静默返回 null** → 点不回公式 | 命中**改用渲染 tex**（与渲染同源） |
| ③ | 光标条只有 **1.5px**，`kMinLeafWidth = 2.0` 把它的盒**过滤掉**，但它在原子表里还在 | 即便同 tex 仍差 1 → 公式内点击"被锁住" | 命中表**剔除光标条**（`atomsForHitTest`） |
| ④ | **空槽在原始源码里没有原子** | "数原子"换算法结构性地落不到空槽 → **进不去空分母** | 换算改成**按插入串反算**：偏移落在插入串内部 ⇒ 返回该**插入点**（`renderToSourceOffset`） |

★ ②③④ 的**共同教训**：`hitTestMathTex` 的判据是「**引擎叶盒数 == 传入的可见原子数**」，
不成立就**静默返回 null**（点不动、还不报错 —— S1 上过这个当）。
⇒ 以后**任何**往 tex 里注入东西的改动，都必须同时检查这条判据。

#### 二、守门人清单（改动注入时必须全过）

| 守门人 | 在哪 | 守什么 |
|---|---|---|
| 每个位点注入后**原子数恰好 +1** | `injection_invariant_test.dart` | 层 ① |
| 含空槽的公式**渲染后不出现 `❌` 回退** | `slot_mark_render_test.dart` | 注入串引擎认得 |
| 点占位框 → **回到空槽偏移** | `injection_map_test.dart` | 层 ④ |
| 光标在公式里（两种注入都生效）时**点左端/右端落到不同偏移** | `edit_view_test.dart` | 层 ②③ |
| 列表项逐格点击映射精确 | `edit_view_test.dart` | 段落坐标 ↔ 源坐标 |

#### 三、★ 假通过的教训（比 bug 本身值钱）

层 ②③ 的第一版守门人**只断言"光标动了"** —— 而公式内点击有**两条路径同时跑**：
`_handleUnitHit` 的**段落映射是粗的**（公式里每一处都映到同一个偏移），
精确落点靠 `Math` 的 `GestureDetector`。精确那一路静默失败时，光标**照样会"动"**
（被粗路径挪到那个固定位置）→ 测试"通过"，用户却看到"被锁住"。

⇒ **测试必须断言"落到不同位置"，而不是"动了没动"**。

#### 四、还没查完的尾巴（已标 skip，带精确数字）

`\frac{}{}` 这类**两个空槽**的公式里，**第二个**占位映射到 7（应为 8），差 1。
影响可控：映射后还有**位点吸附**，偏 1 字符会被吸回最近的合法位点；
单空槽场景（用户实际遇到的）另有测试覆盖并通过。
下一轮查的方向：`renderToSourceOffset` 的 `found` 里是否混进了长度不同的额外匹配，导致 shift 多算 1。

### 11.16 ★★ 2026-10-15：编辑边界三连 + `\\` 探针

> 用户原话驱动的三条：「粘贴进去直接消失了」·「右箭头到行末再按 Enter，分式被拆出编码」·
> 「光标在分式后面，删除只删掉了收尾 `$`，里面的编码爆出来了」。
> 三条是**同一族**：**数学段的边界在数据上是精确的，在视觉上却不可见。**

#### 一、粘贴 `$\frac{}{}$` "直接消失" → 光标归属有洞

**现场取到的真相**（DOM 事件探针 + `Title` 读数通道）：
```
beforeinput data="$\frac{}{}$"  inputType=insertFromPaste
input       value="$\frac{}{}$" sel=[11,11]        ← 文本**确实到了**
Dart 侧：len 223→234 · caret 67→78 · edits 4→5     ← **确实进了缓冲区**
```
⇒ 没发生的事只有一件：**画出来**。两个成因叠在一起：
1. `slot_marks` 的 `caretRel < 0 → 什么都不注入`：光标停在"闭合 `$` 之后那一格"被判"不在这段里"
   ⇒ 空分数退化成 **3.4 px** 细线（注入占位后 13.2 px）

4. ★★ **它必须"同时是结构层的点击区"**，否则只是"看起来长了" ——

### ★★ 11.22 空壳公式落在**行首** ⇒ 整行被当成行间公式（2026-10-15 晚，用户实测的 `Parser Error`）

> 用户实测：在 `$\overline{AB}$` 的**末端位**按删除键 ⇒ 页面出现
> `❌ Parser Error: Can't use function '$' in math mode`。

**这不是删除规则的问题**（删除本身是**设计如此**：点 accent 末端 + `⌫` = 整个 accent 走，
留下空壳 `$$` —— §4.6「删到 tex 空 ⇒ 留空壳」）。坏在**块模型**：

1. 用户那一行的源码 = `$$ $\hat{x}$ $\bar{y}$`（**空壳 `$$` 落在行首**，后面还跟着别的行内公式）
2. 块模型的判据原文是 `isMathFence(s) = s.trimLeft().startsWith('$$')`
   ⇒ 这一行被当成 **R5 行间公式块**（且 `isClosedMathFence` 不成立 ⇒ 按"未闭合"**吞到文末**）
3. ⇒ **整行**都当 tex 送进渲染器 ⇒ 行里剩下的 `$` 落进数学模式 ⇒ 上面那句报错

**精确复现**（转成了不变量测试）：文档 = `kEditSample + '$\overline{AB}$ $\hat{x}$ $\bar{y}$'`，
`Delete @201..207`（7 个偏移）· `Backspace @215/@216`（2 个）—— 共 **9 个偏移**删一次就炸。

**修法**（`core/block.dart`，判据**收紧**而不是放宽）：

```dart
static bool isMathFence(String s) {
  final l = s.trimLeft();
  if (!l.startsWith(kMathFence)) return false;
  if (l.trimRight() == kMathFence) return true;   // 整行 `$$`（开/闭围栏）
  return isClosedMathFence(l);                    // 同行闭合 `$$…$$`
}
```

⇒ `$$ … $`（空壳 + 后续内容）**不再算围栏** ⇒ 退回**普通段落** ⇒ 那里开头的 `$$`
按**行内空公式**渲染（§6.1.1 本来就要求把空公式画出来）✓
⇒ 顺带修好一个中间态问题：以前 `$$ x = 1`（打字打到一半）会被当成"未闭合围栏**吞到文末**"，
现在只是一个段落里有个空公式 —— **半成品输入不再吃掉后面的文档**（§2.3 的容忍原则）。

★ **规律（值得推广）**：**"看不见的定界符"一旦能被删出来，就必须检查"它出现在哪个位置会不会被别的判据误读"**。
空壳 `$$` 在中段无害，落在**行首**就撞上了块模型的围栏判据 —— 又是"多份判据"家族的第六例。

#### 四、竖条高度**随当地那一行自适应**（2026-10-15 晚用户第二轮实测）

> 用户原话：「光标确实不参与排版了，不过**还没有高度适应** —— 不管点哪都一样高，

根因一眼可算：数学段里那些行的自然高度只有 **10–11 px**（引擎自己的行盒），
而竖条用的是固定 `字号 × 1.25 = 20 px` ⇒ 在**任何比主行矮的格**里都必然捅出去。

做法：帧末除了量锚点坐标，再量**光标所在那一行的"当地字形盒"（¶ 盒）** ——
竖直上"住着"这条基线、水平上离光标最近的那一个；竖条就画在那个盒子里（上下各内缩 **8%**）
⇒ **被夹在那一行之内**，而分数线 / 根号横线本来就画在那一行的盒子**之外**
⇒ **结构上不可能相交**（这一条是可证的，已钉成 4 条测试）。
· 主行 ¶ 盒 = 16 px ⇒ 竖条 ≈ 14.7 px（与文本侧同一量级）
· 上标 / 下标（0.7 倍字号）⇒ ¶ 盒 11.2 px ⇒ 竖条 ≈ 9.3 px ✓ 自动变小
· **为什么用 ¶ 盒而不是引擎行盒**：行盒太紧（16 px 字号下只有 10–11 px），
  拿它当光标会明显偏矮、与文本侧不成比例；¶ 盒是**字形的行高盒**，正好跟着字号自适应。

### ★★ 11.24 结构几何（② 组地基表）：三批探针 + 实现（2026-10-16）

#### 一、三批探针推翻的三个"看起来显然"的方案（★ 别再想回来）

**① 按节点类型配对（第 k 个 `_FracPos` ↔ 第 k 个 `\frac`）不成立 —— 有样式依赖。**
同一个源码结构在不同 `MathStyle` 下落**不同节点**（`Math.tex` 单测，字号 16，均 `caretRel=-1`）：

| tex | `MathStyle.display` | `MathStyle.text` |
|---|---|---|
| `\sum_{i=1}^{n}a_i` | `RenderRelativeWidthColumn`（上下限在正上/正下）＋ `_ScriptPos`（`a_i`） | `_ScriptPos` ×2 |
| `\int_a^b f(x)\,dx` | `_ScriptPos` | `_ScriptPos` |
| `\lim_{x\to0}…` / `\max_{x\in S}…` | `RelativeWidthColumn` | `RelativeWidthColumn`（**两种样式都一样**） |
| `\prod_{k=1}^{m}k` | `RelativeWidthColumn` | `_ScriptPos` |

**② 源码里 `^`/`_` 的个数 ≠ `_ScriptPos` 个数。**
`\sum_{i=1}^{n}a_i` 源码有 **3** 个脚本（`_{i=1}`、`^{n}`、`_{i}`），display 下渲染只 **1** 个 `_ScriptPos`
（算子的上下限折进了算子那个节点）⇒ 必须先"把算子的上下限折进算子"，再谈对齐。

**③ accent 与 display 模式的 limits 算子共用 `RenderRelativeWidthColumn`** ⇒ 类型分不开两族，
**必须靠源码侧的种类**来认（源码里那到底是 `\overline` 还是 `\sum`）。

#### 二、渲染侧的结构承载节点名单（**实测，不是猜的**）

| 源码结构 | 渲染节点 | 盒的语义 |
|---|---|---|
| 分式族 | `RenderCustomLayout<_FracPos>` | 整个分式（含分数线与 2×1.9 内边距）—— `\frac{a}{b}` = **19.8 × 28.7** |
| 根号 | `RenderCustomLayout<_SqrtPos>` | 整个根号（含勾、横线、次数槽、**我们的尾垫**）—— `\sqrt{2}` = **34.1 × 16.0** |
| 脚本 | `RenderCustomLayout<_ScriptPos>` | 基座 + 该基座上的全部脚本（`x^{2}` = 28.0 × 13.8） |
| accent（拉伸族 + 定宽族） | `RelativeWidthColumn` | 装饰 + 内容（`\overline{AB}` = 37.6 × 13.5、`\hat{x}` = 16.0 × 11.1） |
| **带上下限的算子** | `RelativeWidthColumn` / `_ScriptPos` | ★ **只含算子 + 它自己的上下限，不含被作用的内容**（`\sum_{i=1}^{n}a_i`：算子 0..33.6、内容 36.3..） |
| 环境 | `RenderEqnArray`（`cases` / `aligned`）/ `RenderCustomLayout<int>`（`pmatrix` / `substack`） | 整个环境（不含 `\left` 的括号） |
| 堆叠族 `\overset` `\underset` `\stackrel` `\xrightarrow` | `RelativeWidthColumn` | 装饰 + 内容 |

**不在这张名单里的（都是装饰 / 定界符，不是结构）**：
- `_RenderLayoutBuilderPreserveBaseline` —— 根号那张矢量图、`\left(` `\right)` 的括号、`cases` 的大括号、
  `pmatrix` 两侧括号全走它。★ 早期把它当结构 ⇒ `\sqrt{2}` 报"对象 1 ≠ 节点 2"的**假失败**。
- `RenderFittedBox` —— 装饰矢量图的**缩放壳**：`\sqrt{2}` 里它自己只有 34.1 × 17.3（正常），
  真正失真的是它的子节点 `RenderPictureVectorGraphic`（**2133 × 1080**）⇒ **几何一律取外壳**。
- ★ **`\overbracket` / `\underbracket` 没有节点**（语料问出来的）：它们的装饰也是矢量图，
  但引擎**不建** `RelativeWidthColumn`。
- `\boxed` `\cancel` `\fbox` `\pmb` `\angl` `\operatorname` `\mathrm` `\text` —— 也没有节点（语料全过）。

#### 三、对齐规则（最终采用）

> **源码侧的结构对象（前序）↔ 渲染侧的结构承载节点（前序），按位置 zip。**
> 只对 **有节点** 的对象 zip（`\sin x` 这类没有节点，不能占位次，否则错位）；
> 并**断言"数量相等 + 类型相容"**，不一致就在 `mismatch` 里说明白。

**源码侧结构对象的枚举判据（不新写判据，全部来自既有地基表）**：

| 来源 | 产出 | 关键规则 |
|---|---|---|
| `scope_table.operatorScopes` | 算子对象（含上下限与作用域内容） | **带上下限**（`limitsEnd > 算子名末尾`）才有节点 |
| 区域表 `regions` 的内容项 | 分式 / 根号 / 环境 / accent / 堆叠 | accent **没有槽**，所以只能在内容项里枚举 |
| 区域表 + `^`/`_` | 脚本对象（基座 + 脚本） | ★ **同一基座上连续的 `^`/`_` 合成一个对象**（`x_i^2` = 1 个）；★ 算子的**上下限折进算子** |

#### 四、矩形：节点盒 ∪ 叶盒并集 ∪ **子结构矩形**（自底向上）

- 有节点 ⇒ 起点是**引擎的节点盒**（准确、含内边距与装饰）；
- 没有节点（`\sin x`、`\left(…\right)`）⇒ 只能靠**叶盒并集**；

#### 六、★ 顺带抓出的两个**既有缺陷**（**都不在 ② 里修，已记账**）

   这就是"替他决定内容属于数学还是文本"，与"渲染是源码的忠实投影"直接冲突。
2. **§3.3 通则**：`$` 不可见 ⇒「公式末尾（tex 末尾）」与「公式之后（`closeEnd`）」
   **在屏幕上是同一根像素**，而**删除 / 点击必须给同一个结果**。
   点空白却落到公式**内部**，等于在"同一根像素"上给了**第三种答案**。

★ 由此得到 ③ 的正确形状（**不是新设计，是既有规格的直译**）：

> **空白落点规则（两侧共用一条）**：
> 点击落在**任何可见内容之外** ⇒ 落点 = **同一维缓冲区里离它最近的位点**，
> 且**优先"段末 / 行末"**（与文本一致）；
> **只有**落在**真层级内部**（结构嵌套：分子 / 分母 / 上下限 / 环境格）时，
> 才允许"就近归到那一层"。
>
> —— 这正是 §7.1 那句「**顶层无墙、内部有层**」在**点击**上的样子。

⚠️ 待探针分辨的一点：**行内**公式右侧的空白，究竟是被**文本段落**（`RenderParagraph`）
还是被**数学控件**接走的 —— 两者走的是**两套兜底**，修法不同（前者要改映射、后者要改 `hit_map`）；
上面第 2 条探针（横向逐像素扫描）就是为分辨这个设计的。
