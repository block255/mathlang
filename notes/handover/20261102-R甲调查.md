## 三、R-甲1 / R-甲2：探针与根因

### 3.1 方法

纯 Dart 直接调用真函数，复刻 `EditView._applyAutoExpand` 的两步：

```dart
final ex = planAutoExpand(doc: doc, caret: doc.length, typed: '^',
    triggers: TriggerSettings.defaults());
final trimmed = doc.replaceRange(ex.from, ex.caret, '');   // 先去掉括号对
final r = applySymbolInsert(doc: trimmed, caret: ex.from,
    selStart: ex.from, selEnd: ex.from, tex: ex.tex, template: ex.template);
```

### 3.2 结果（`\n` 按字面打出）

| # | 输入（Shift+6 之前） | `mode` | 落盘后 |
|---|---|---|---|
| A | `$\lim_{x\to\infty}$($\frac{…}{2020}$)` | mergeIntoMath | `$\lim_{x\to\infty}$` **`\n`** `$(\frac{…}{2020})^{}$` |
| B | `ln($\frac{1+x}{x^{2}}$)` | wrapNewInlineMath | `ln` **`\n`** `$$(\frac{1+x}{x^{2}})^{}$$` |
| C | `前($\alpha$)` | wrapNewInlineMath | `前` **`\n`** `$$(\alpha)^{}$$` |
| D | `$a$($b$)` | mergeIntoMath | `$a$` **`\n`** `$(b)^{}$` |
| E | `($\alpha$)`（文首） | wrapNewInlineMath | `$$(\alpha)^{}$$`（无换行，但**已是行间块**） |
| F | `x($\alpha$)` | wrapNewInlineMath | `x` **`\n`** `$$(\alpha)^{}$$` |
| G | `$\lim_{x\to0}$($\frac{1}{x}$)` | mergeIntoMath | `$\lim_{x\to0}$` **`\n`** `$(\frac{1}{x})^{}$` |

A/G 与用户会话文件里的那一行**逐字一致**：
`$\lim_{x\to\infty}$` + `\n` + `$(\frac{\sqrt[x]{a_{1}}+……+\sqrt[x]{a_{2020}}}{2020})^{2}$`。

### 3.3 根因（两层，都在同一条链上）

1. **`_planScript` 的合并分支返回的是"已经带围栏的完整行内公式"**
   （`auto_expand.dart`：`tex: '\$($soleTex)$slot\$'`），而 `_applyAutoExpand` 把它
   当成**裸 tex** 交给 `applySymbolInsert`（`edit_view.dart:793`）。
2. `applySymbolInsert` 的语义是"裸 tex + 光标在哪"（`symbol_insert.dart:89`）：
   - 光标**紧贴**公式 ⇒ `_mergeRegion` 走 `mergeIntoMath`；`planInsert` 规则 ①b
     （载荷自带 `$` ⇒ 推出 tex）把它推到公式之后；接着规则 ⑤（左邻是 `$`、载荷以 `$` 开头）
     **补一个换行**（`insert_guard.dart:343–358`）⇒ 公式掉行（A/D/G）。
   - 光标**在正文**里 ⇒ 走 `wrapNewInlineMath`，`_shell()` **再包一层 `$`**
     （`$$(\frac…)^{}$$`）⇒ `_isBlockSyntaxLine` / `isClosedMathFence` 认成**行间块**
     （`block.dart:343`）⇒ 补换行 + 按 `MathStyle.display` 居中（B/C/E/F）。
     ⇒ 用户看到的"像被干到行间"是**字面意义的**：文档里真的成了 `$$…$$`。

### 3.4 为什么守卫没抓住

`script_base_bracket_test` 的 ⑤/⑤b/⑧ 只断言 `planAutoExpand` 的 `ex.tex` / `ex.from` / `ex.caret`
—— **计划层是对的**（`$(\alpha)^{}$`），坏的是"计划 → 落盘"这一步。
仓库里没有一条"Shift+6 之后文档长什么样"的端到端守卫。

### 3.5 归属

- **是 `5cf11fd` 引入的**：该分支之前，括号里含整段公式时 `planAutoExpand` 返回 `null`
  （守卫 ⑧ 的"改前返回 null"就是证据），不会走这条链。
- **不是基线/降档/字体问题**：A/G 的公式在**下一行**，B/C/E/F 在**另一个块**（居中）；
  "不共基准"是跨行/跨块的结果。§12.0 撤回的那次探针"测不准"也就说得通了 —— 它测的是两个不同的行。

### 3.6 ★★ 同一分支的第三个问题：括号种类被写死成圆括号

`5cf11fd` 的合并分支里，重建那段公式用的是字面量
`tex: '\$($soleTex)$slot\$'`（`auto_expand.dart`）—— **`(` `)` 是写死的**，
并没有用 `_matchedOpenBefore` 找到的那对括号的**实际字符**。

| 输入（Shift+6 前） | `planAutoExpand` 返回的 `tex` |
|---|---|
| `前 ($\alpha$)` | `$(\alpha)^{}$` ✓ |
| `前 [$\alpha$]` | **`$(\alpha)^{}$`** ← 方括号变圆括号 |
| `前 {$\alpha$}` | **`$(\alpha)^{}$`** ← 花括号变圆括号 |
| `前 [$\frac{1}{x}$]` | `$(\frac{1}{x})^{}$` |
| `前 [$\alpha$]` + 撇 `'` | `$(\alpha)^{\prime}$` |

⇒ 影响 `^` `_` `'` 三条入口（撇也走 `_planScript`）。
**补接缝但不同时修这里，会比现在更糟**：现在至少还有"换行/行间"这个显眼症状，
修完接缝后会变成"同一行、看着正常、但 `[]`/`{}` 被悄悄换成 `()`"——静默改内容。
守卫 `script_base_bracket_test` ⑤/⑤b/⑤c/⑤d/⑤e/⑧ **只覆盖了圆括号**，所以没抓到。

### 4.1 结果（真 `clipboardSlice`，用户原句）

文档：`11.求极限 $\lim_{x\to+\infty}$ ( $\frac{\sqrt[x]{a_{1}}+……+\sqrt[x]{a_{2020}}}{2020}$ ) $^{x}$ ,其中…`

| 起点 | 出参文本 | 结果 |

| `cases` 内部起选 | `$x+y=1\\x-y=3\end{cases}$` | **孤立 `\end`**（无 `\begin`） |

### 4.2 根因（三条规则各自漏在哪）

| 规则 | 现在的判据 | 漏的地方 |
|---|---|---|
| ③ 控制词吸附 | 只处理"切在**词中间**"（`\f|rac`） | **切在命令之后（参数 `{` 上）不吸附** |

| 参数补全 `_completeArgs` | 只在片段**以 `\` 开头**时才补 | 起点在参数里时片段不以 `\` 开头 ⇒ 永远不触发 |
| 环境 `_completeEnvs` | 只补"片段自己打开的 `\begin`" | 起点在环境内部时，`\end` 成为孤立尾巴（注释写"台账登记"，**台账里没有**） |

### 4.3 归属

- **与 `5cf11fd` 无关**：上面的复现用的是**未合并**的原句；缺口的触发条件是"选区端点落在结构内部"。
- **与 `91d8aa0` 有关**：拖选端点第一次能精确落进结构内部，这个旧缺口才第一次可达
  （快照 §12.1 的 ★★ 注已经说对了，§12.3 的"最可能是合并引入"说错了）。

### 4.4 守卫为什么没抓住

`clipboard_slice_test` 的"全域"用例（`4 份语料 × 每一个 (i,j)`）只断言
**`$` 个数是偶数**（`clipboard_slice_test.dart:116–139`）；`{...}{...}` 花括号是平衡的、`$` 也是偶数
⇒ 断言全过。**结构完整性**（命令参数齐、环境配平、不以 `}`/`]` 开头）没有任何断言。

## 六、待拍板的修法（**未动代码**）

### 6.1 R-甲1 / R-甲2

| 方案 | 做法 | 结果 | 代价 |
|---|---|---|---|
| **甲（推荐）** | 合并分支返回的 `$…$` **不再走 `applySymbolInsert` 的建壳路径**：`_applyAutoExpand` 认"已带完整围栏"时直接做区间替换；邻接围栏时补**一个空格**（不是换行）；**重建时用找到的那对括号的实际字符**（`[`/`{` 不许变 `(`） | A/G ⇒ `$\lim…$ $(\frac…)^{2}$`（同一行、两段公式）；B/C/F ⇒ `ln $(\frac…)^{2}$`（同一行、行内）；`[...]`/`{...}` 保真 | 文档里多一个空格；两段公式仍是两段 |
| 乙 | 同上，但**并进左边那段公式**（`$\lim…(\frac…)^{2}$`） | 同一行、**零间隙**、一段公式 | 语义上把极限和分式并成一段（多数情况下正是想要的，但不是所有场景） |
| 丙 | 回滚 `5cf11fd` | 回到"打 `^` 是字面字符" | 反馈 17·补 的现场又坏掉 |

> 甲的判据要覆盖四种邻居：左 `$`（行内）/ 左 `$$`（行间）/ 左 文字 / 文首；
> 右对称。守卫应为**端到端**（`planAutoExpand` → `applySymbolInsert` → 文档），
> 而不是只测计划层。

### 6.2 R-甲3

| 方案 | 做法 |
|---|---|
| **甲（推荐）** | `clipboardSlice` 补一条**起点侧吸附**：起点落在"命令参数 / 可选参数 `[...]` / 环境内部" ⇒ 向前扩到命令首（`\frac` / `\sqrt` / `\begin`）；`[...]` 参与配平；`_completeEnvs` 补起点侧（孤立 `\end` ⇒ 向前找 `\begin`） |
| 乙 | 只补 `\frac` / `\sqrt` 两种形状（快照原话），不动环境与 `[...]` | 
| 丙 | 不管起点，改成"复制前沿用可见原子边界"（选区端点先吸到原子边界） | 

> 无论哪个方案，**守卫要升级**：把"`$` 偶数"换成**结构完整性**全域断言
> （每个 (i,j)：无孤立 `\end`、每个 `\frac`/`\sqrt` 参数齐、片段不以 `}`/`]` 开头）。

### 6.3 接缝的三种做法（2026-11-02 讨论，未拍板）

| 做法 | 加字符 | 动围栏 | 备注 |
|---|---|---|---|
| **甲 空格** | **+1 个空格** | 不动 | 空格是可见内容 ⇒ 与平权推论②"不许造用户没写的字符"冲突（虽然最省事） |
| **乙 合并围栏** | **0** | 把**紧贴**的左/右行内公式并进来 | 只移动 `$`，不动可见字符；但改变文档形态（与 §4.2 同类），且接缝处的字距改用"一段公式"的算法 |
| 丙 原样相邻 | 0 | 不动 | **不成立**：`$a$$b$` 在 Markdown 里与 `$$…$$` 歧义，扫描器会当成行间块 |

★ **乙为什么在原则上更对**（用户 2026-11-02 指出）：围栏**不是**操作/语义边界
（平权推论④），所以把两段相邻行内公式合成一段，**编辑语义不变**，只是存储少一对 `$`。
反过来，甲要往文档里塞一个用户没打的空格——可见字符变了。
★ 乙的代价：合并会**多改一处**（左邻公式的收尾 `$` 被卷进来），且
`$\lim…$` + `$(\frac…)^{2}$` ⇒ `$\lim…(\frac…)^{2}$` 属于**文档形态**变更，
与 §4.2「括号并进公式=不做」是同一类决定，**必须用户拍板**，不能当纯 bug 修。

### 6.4 纯正文括号 `(x+a)` 的现状（2026-11-02 探针）

| 输入（按 `^` 前） | 落盘 | 说明 |
|---|---|---|
| `前 (x+a)` | `前 $(x+a)^{}$` | **不是字面 `^`**：整对括号搬进数学（`x`/`a` 变数学斜体）；单层壳，没有 R-甲1/2 的毛病 |
| `前 (x+a)` + `_` / `'` | `$(x+a)_{}$` / `$(x+a)^{\prime}$` | 同一条路 |
| `前 ($x$ + 1)` | 字面 `^` | 混着正文 ⇒ 合并会改字体/吃空格，按 §3.4 护栏放过 |
| `前 （x+a）`（全角括号） | 字面 `^` | `_matchedOpenBefore` 只认 ASCII `)]}` |
| `前 (x+a) `（括号后隔空格） | 字面 `^` | 判据要求紧贴 |

★ `(x+a)` 的"搬进数学"是 §3.4 **已拍板**的口径（括号 = 看得见的边界 ⇒ 整对当基座），
而且是**内容中立**的：不能因为"看起来不像数学"就区别对待（平权推论②）。

| **`\text{}` 的定位** | **只换字体的透明包装**（方向键透明、⌫ 不留幽灵）；★ **我们自己从不生成它**——`lib/` 里的 `\text{` 只出现在渲染期临时拆组，**不落盘** | 台账 批 36 · 2026-10-24 快照 §9.27 |
| **中括号** | 行内顶层 `[ ]` 按**文本字体**、结构槽/行间按数学字体 —— 字体粗细被当成**可见**问题 | 台账 批 30 |

⇒ 两条冲突：
1. 若在 `(x+a)` 上生成 `\text{…}`，就是**编辑器开始生成 `\text{}`**，推翻"我们自己从不生成它"；
2. 要决定"哪些字符进 `\text`、哪些进数学"，就是**按内容/字形分流**（推论②禁区）。

★ 同时，"括号里不改内容"这条护栏的**理由要收窄**：
- **字体变化**本身，在 B2-b 已按语境接受（结构槽/行间）；行内顶层则按批 18 **拆段** ——
  两条都不是"字体 = 内容"的一刀切。
- 真正站得住的"改内容"只有两种：**空格丢失**（数学模式空格无意义，`(x + a)` 会少一个可见间隔）
  与**结构变化**（混合 / 两段 / 空段并进去会改变字符归属）。
- ⇒ `(x+a)` 的纯文本升格**不属于**这两种（没有空格、结构不变）⇒ §3.4 的护栏本来就不该拦它；
  现状（升格、变斜体）是自洽的。
- 若要让 `(x+a)` 保持正文字体，只能改**大口径**（"纯文本括号要不要升格"），不能靠 `\text{}` 补丁；
  而改大口径会让 `(-1)` 一起退回字面 `^`（反馈 17 回潮）。

### 6.6 升格时的空格：位点表里确实会多出"同像素两站"（2026-11-02 探针）

用户问："直接包成数学区段但不处理原空格，会不会出现幽灵位？" —— **会，但不是屏幕上的假光标。**

| 探针 | 结果 |
|---|---|
| `lexVisibleAtoms("x + a")` | `x[0,1) +[2,3) a[4,5)`（空格不产原子） |
| `buildCaretSites("x + a").sites` | **0,1,2,3,4,5**（每个空格**两侧各一站**） |
| `buildCaretSites("x+a").sites` | 0,1,2,3 |
| `buildCaretSites("(x + a)^{}").sites` | 0..7, **9,10**（空格两侧成对） |

⇒ `caret_sites.dart` 里"空白既不产出内容、也不产出位点"说的是**词法**；
**位点发射按内容项边界**，所以空格被夹在两个位点中间 ⇒ **同一根像素上两站**。

后果（三层，轻重不同）：
1. **`→` / `←` 不会卡住**：`math_nav._invisibleBetween` 把空格算"不可见"，同层就跳过
   （`caret_same_pixel_sweep_test` 走的是"导航停靠点"，所以它是绿的）。
2. **点击 / 吸附仍可能落在空格前或后**：两次看起来一样的打字会得到**渲染相同、存储不同**的
   结果（`xb + a` vs `x b+ a`）。
3. **⌫ 删不到空格本身**（空格不是原子）：它只会被"删空整段"时的 `rest.trim()` 一并回收
   （`delete_reclaim.dart`）⇒ 中间态会攒下删不掉的隐形字符。

★ **旧口径其实已经表过态**：2026-10-17 用户拍板"数学段里按空格 ⇒ 插 `\ `"，
原话理由是"**不会出现存了裸空格、渲染时被丢掉的状态**（裸空格在数学里只是词法分隔符）"
（`edit_view.dart:1345`）。⇒ **裸空格在数学里本来就是想避免的状态**；
升格把正文空格原样搬进去，正好制造它。

⇒ 升格时必须处理，四个选项：

| 选项 | 结果 | 评价 |
|---|---|---|
| **甲 转 `\ `（★ 用户 2026-11-02 拍板）** | `(x + a)` ⇒ `$(x\ +\ a)^{}$` | **不是代价**：空格键在数学里本来就插 `\ `（2026-10-17 口径），升格走同一条路；空隙可见、可删、无同像素位点、复制出去也是合法 TeX |
| 乙 丢掉空白 | `$(x+a)^{}$` | 渲染与"保留"相同，但把用户打的空格**从存储里抹掉**（复制成文本时不保留）；没有必要 |
| 丙 保留裸空格 | 现状 | 同像素两站 + 删不掉的隐形字符（10-17 已经想避免的状态） |
| 丁 含空格不升格 | 字面 `^` | `(x+a)` 与 `(x + a)` 行为不一致 |

★ 于是升格规则定为：**括号内容整体搬进数学；空白一律转 `\ `；括号种类保真。**
宽度确实比文本空格宽（`\ ` = 0.667em），但这是"数学里的空格"既有的形状，属于意图内。

★ **中文搬进去也不是问题**（用户 2026-11-02 确认）：`前 (中文)` ⇒ `$(中文)^{}$` 可接受，
与 **B2-b 撤案**（结构槽/行间接受数学字体）是同一条口径。
与批 18"行内顶层中文拆段"**不冲突**：那条只管**在数学段里打字**这个动作；
升格是"用户按了指数键、显式把这对括号改成数学语境"，不是偷偷判定。
⇒ **不加 CJK 护栏**，升格保持内容中立。
