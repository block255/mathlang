## 一、先看现场：**"多段同行"**是这份卷子的主形态

`test_data\2020-2021期中编辑.md` **第 42 行**（三对 `$`，逐字符拆开）：

```
11.求极限 $\lim_{x\to+\infty}$ ( $\frac{\sqrt[x]{a_{1}}+…+\sqrt[x]{a_{2020}}}{2020}$ ) $^{x}$ ,其中…
          └──── 第 1 段 ────┘    └───────────── 第 2 段 ─────────────┘   └第 3 段┘
```

`test_data\2025-2026期中编辑.md` **第 11 行**（两对 `$`，中间是本该属于公式的 `(cosx)`）：

```
3.求极限 $\lim_{x\to0}$ (cosx) $^{\frac{1}{sinx\cdot tanx}}$
          └─ 第 1 段 ─┘  ↑正文↑  └──── 第 2 段（以 ^ 开头）────┘
```

**这两行说明什么**

1. **第 3 段 `$^{x}$` 自己内部"没有基座"** —— 它的源码以 `^` 开头。TeX 靠"左边有什么"来决定挂给谁，
   而这一段**左边什么都没有**（`$` 是围栏，不参与排版）⇒ 它被渲染成一朵**贴在文本基线附近的小指数**。
2. **视觉上那个"基座"是正文里的 `)`**（`Q2：是哪个正文？`⇒ 就是**这一行里、`$` 外面的那个普通字符 `)`**，
   它属于**文本层**，不在任何公式里）。
3. 所以 **反馈 20「`)^x` 位置偏低」不是渲染 bug**：那个指数从来没有挂到过括号里的分式上，
   它挂在"一个高度只有 20px 的正文括号"旁边；分式在**另一段公式**里、高度 100+px。
   **要它抬高，得让 `)^{x}` 和分式处在同一个公式里** —— 那是"文档形态"，不是排版。

> ⇒ 18 / 19 / 20 的定性都受这一条影响：**先分清"文档被拆碎了"和"排版算错了"**。
> 18 是**真的排版问题**（见 §二 R5），20 是**文档形态**。

### 3.1 切割原则（最高，管一切"什么是对象"）

> **只看看得见的三样：墨迹、挂件、显式成对边界。凡是"要推断才知道从哪儿到哪儿"的，一律不当整体。**

| 档 | 判据 | 例 |
|---|---|---|
| **原子** | 一团墨迹，没有挂件 | `x` `2` `+` `\sin` `\ln` `s`（三字母里的一个） |
| **对象** | 墨迹 + **挂上去的**挂件；或**画出来的**成对边界 | `a^2` `\lim_{x\to0}` `\int_a^b` `\log_2` `\frac{a}{b}` `\sqrt[3]{x}` `\left|x\right|` `(-1)^2` |
| **层** | 容器**画出来的**边界内部 | `\frac{□}{□}` 的分子、`cases` 的一格 |

- **作用域不算对象**：`\lim` / `\sin` / `\log` / `\int` 的"操作对象到哪儿结束"是**语义推断**（无墨迹边界）⇒ 不作数。
- 已有的两条口径是它的两个不同方向，**从现在起算同一件事**：
  - 批 36：`\text{…}` **自己不画东西** ⇒ 不是墙（透明）；
  - 批 10：`\sum` 的"整体"**横跨一大片** ⇒ 不当整体。
- **围栏不是对象边界**（平权 推论 ④，[`../design/围栏与整体.md`](../design/围栏与整体.md)）—— 同一条原则。

### 3.2 删除粒度 ≡ 双击粒度（一条判据，两处用）

- **删一次 = 双击能选中的那一块** = §3.1 的"一个对象"。
- "整体"（跨对象）**只由选区产生**：双击（一个对象）· 三击（行间块 = 整块 / 其余 = 整行）· 拖选。
- ⇒ 代码后果：**撤掉"函数算子作用域整块删"这一档**（含 `kStackedOperatorCommands` 那个补丁与 `_endsWithPlainCloser`
  那个补丁 —— 它们都是为了堵这一档的洞；撤掉后**结构性成立**，不用补）。
  `scope_table.scopeEndingAt` 从"删除判据"降级为诊断用（表保留）。

### 3.3 `sin` / `ln` 一律原子化（用户 2026-11-01 拍板）

- 我们自己**不提供** `\sin \cos \tan \ln` 的入口（面板与词触发器都不加）；
- `sin2x` 源码就是 `s i n 2 x` **五个原子**；打完 `n` 打 Shift+6 ⇒ `n^{}` ⇒ 屏上 `sin²`，**与 `\sin^2` 同形**；
- **外来的 `\sin`**（粘贴/导入）是一个命令 = 一团墨迹 = **一个原子**，挂件照旧可挂 ⇒ 已适配，不改；
- 编辑器只做**编辑与渲染**，不做计算 ⇒ 二者语义差别不影响任何可见结果。

### 3.4 基座规则（R4 的修法口径）

| 光标前 | 现在 | 应为 |
|---|---|---|
| 字母 / 数字 / 汉字 | 那个字 ✓ | 不变 |
| `)` `]` `}`（**正文里**，且有配对开括号） | 无 ⇒ 字面 `^` ❌ | **整对括号当基座**：`(-1)` ⇒ `(-1)^{}` |
| 紧跟一对 `$…$` 的收尾 `$` | 无（`prev == '$'`）❌ | **并回原段**（§四-1） |
| 数学段里的 `)` | `)^{}` ✓ | 不变 |
| 其它（`+` `=` 空格…） | 无 ⇒ 字面 | 不变（正文里 `^` 就是个字符） |

|---|---|---|
| `x^{2}` **内容末**（`2` 之后 `}` 之前） | bs@4 ⇒ 删 `2` | 留 `x^{}` |
| `x^{}` 空槽 | bs@4 / bs@3 ⇒ 都删 `^{}` | 留 `x` |
| `x` | bs@1 ⇒ 删 `x` | 公式删空 ⇒ `reclaimEmptiedMath` **自动回收** |
| `x^{2}` **对象之后**（tex 末位） | bs@5 ⇒ **一下删光 5 字符** | — |
| `(-1)^{2}` tex 末位（**今天**） | bs@8 ⇒ 只删 `)^{2}` | ★ **留下 `(-1`（残括号）** |

- 结论：**打字过程中退格次数与打入键数一一对应**（打 `^` `2` 两下 ⇒ 删也两下）；"一下删光"只发生在**对象之后**那一格 = 双击粒度。
- ★ `(-1)^{2}` 那个残括号是**今天**的行为：因"对象"只承认 `)` 是基座。新基座规则（整对括号是基座）下对象 = `(-1)^{2}` ⇒ 一下删干净，**顺带修掉**。

**★ 搬家范围 ≠ 对象范围**（实测：正文 `sin` 打 `^` ⇒ `from=2`，只把 **`n`** 搬进公式 ⇒ `si`（正文字体）+ `$n^{2}$`（数学斜体 n）⇒ **三个字母断成两种字体**）。

> **口径**：**搬家**按"**视觉连续的一段**"（光标前那一整串连续字母数字一起搬 ⇒ `$sin^{}$`）；
> **删除**仍按"**对象**"（公式里 `s` `i` `n` 还是三个原子）。
> 混在一起才会两头不讨好：搬家为了字体不断开，删除为了粒度不糊。

**其它（确认不是新增负担）**：跨段 `→`/`←` 不多按（批 15「甲」：tex 末位与公式之后同像素）；撤销仍一步（一次 `replace`）；想改上标里的字要先进去（与 `\frac` 里改分子同构）。

### 3.5 空槽里打空格（反馈 21）—— ⏳ **待拍板**

**2026-11-01 实测（20px）**：同一个 `cases`，第二行内容 空 / 3 个普通空格 / 3 个 `\ ` ⇒ 宽 **42.4 / 42.4 / 82.4**
⇒ **普通空格在数学模式里宽度 = 0**（Δ=0.0），`\ ` 每个 **13.3 px = 0.667 em**。
⇒ 所以"框跟着空格变宽"在物理上不成立，除非让空格**真的有宽度**。

| 选 | 行为 | 代价 |
|---|---|---|
| **甲** | 空格**算内容** ⇒ 框消失（判据从 `trim().isEmpty` 换成"零长度"或"只有填充空格"） | 格子里天然带着填充空格（`& a &`），要能区分"引擎塞的"与"用户打的"；且空格子会**不再恒定 1em** ⇒ 列宽随内容变，与 D3 冲突 |
| **乙** | 空槽里打的空格**被吃掉**（不进缓冲区） | 与"空格是普通字符"不一致；按了没反应 |
| **丙** | 只让空格**看得见**（淡色标记），判据不动 | 不解气 |
| **戊 ★（用户 2026-11-01 提议）** | 填充垫宽度从**固定 1em** 改成 `max(1em, 空格数 × 0.667em)`（系数 = 实测 `\ ` 宽） | **纯渲染**、不动缓冲区、不动判据、不动 D3 ⇒ 框按空格数**正确变宽**。★ 已量：注入的垫子个数在"空 / 3 空格"时**相同**（都是 1 个 `\rule{1em}{0pt}`，只是后面多出零宽空格）⇒ "变形"来自**几何**（`_envFillPlan` 对位 / `cellRect`），**不是注入** ⇒ 下一步量那一处 |

## 四、两个"入口"提议（⏳ 待拍板，直接影响 18/20 的定性）

### 4.1 「并回原段」是什么

现场：光标在 `$\alpha$` 的收尾 `$` **右边一格**，按 Shift+6。

- **现在**：`^` 落进正文 ⇒ 变成 `$\alpha$^`（字面字符，且公式已经关掉了）；
- **提议**：把**那一段重新写一遍**，把 `^{}` 接在它最后一次内容后面 ⇒ `$\alpha^{}$`，光标落进 `{}`。
  一次 `replace` = **一步撤销**，不新造公式、不往正文里插字符。

> 为什么它能顺带修好"希腊字母后面挂不上"：面板插 `\alpha` 时是插成 `$\alpha$`（自成一段），
> 光标正好停在那段的收尾 `$` 后面 ⇒ 命中这条。

### 4.2 「括号并进公式」是什么

现场：光标在**正文**里，左边刚打了一个 `(`（或右边马上有个 `)`），然后点面板的结构模板（分式/根号/求和…）。

- **现在**：模板**自建一段壳** ⇒ `(` + `$\frac{}{}$` + `)` —— 括号留在正文，公式夹在中间。
  以后再打 `^`，指数只能挂到**正文那个 `)`** 上（R5/§一 的成因）。
- **提议（窄口径）**：只在这两种紧贴情况下，把括号**一起搬进公式**：`$(\frac{}{})$`、`$(\frac{}{})$`。
  - **只影响"新造的"**；**不动任何已有文档**（已拆碎的照旧，要合并另立项）。

> **为什么我把它列为"待拍板"而不是直接做**：它会把"插模板"这件事从"插一小段"变成"重写一整段"，
> 改动面在 `applySymbolInsert` 的建壳分支；而且如果你其实喜欢现在这种"公式嵌在正文里"的写法，就不该改。
