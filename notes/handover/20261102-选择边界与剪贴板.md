## 一、讨论过程（按转折点，含被推翻的判断）

### 1. 起点：三条现场

用户 2026-11-01 23:5x 拖选公式的一部分复制，得到：

```tex
$x]{a_{1}}+……+\sqrt[x]{a_{2020}}$                 ← `\sqrt[` 丢了
${\sqrt[x]{a_{1}}+……+\sqrt[x]{a_{2020}}}{2020}$   ← `\frac` 丢了
$x+y=1\\x-y=3\end{cases}$                          ← 孤立 `\end`（探针复现，非用户原样）
```

### 2. 第一层：复制和删除是「半粘连」

- `clipboardSlice` 一份实现，服务三家：复制拿 `text`，剪切/删除拿 `start..end`
  （删除还会再过 `expandPackedBaseInDoc` + `reclaimEmptiedMath`）。
- **幂等探针**：6482 个区间，`clipboardSlice(slice)` 与 `clipboardSlice(原区间)` **全一致**
  ⇒ 当前剪切与退格删的是同一段（但这是"碰巧一致"，没有守卫）。
- 结论：粘连在「算范围」，不粘连在「拿走什么」——复制拿文本，删除拿区间。

### 3. 第二层：删除侧也会留残片

用户追问「删除不能往外扩，是不是会留残片」。探针（真 `clipboardSlice`，删后模拟）：

| 选区 | 实际删的 | 删完 | 性质 |
|---|---|---|---|
| `\frac{a}`（从命令开头选） | **右扩到 `\frac{a}{b}`** | `$+x$` | 多删（本可只删这 8 个字符） |
| `{a}`（分子连花括号） | 不动 | `$\frac{b}+x$` | 残片：`\frac` 只剩一个参数 |
| `{a}{b}`（两个参数） | 不动 | `$\frac+x$` | 残片：一个参数都没了 |
| `x]`（可选参数收尾） | 不动 | `$\sqrt[{a}+y$` | 残片：`[` 和 `{` 都没关 |

⇒ 删除不是"不往外扩"，是**"只往右扩、不往左看"**：右边过度、左边为零。
右扩有时必要（单删 `\sqrt` 会留 `[x]{a}`），有时多余（`\frac{a}` 本可只删选区）。

### 4. 第三层：把「对象内部」从几何改成**所有权**

用户用四个例子校准：

| 选区 | 判断 |
|---|---|
| `a1`（根号参数里的一个字） | **不扩** |
| `x`（根号的次数） | **不扩** |
| `cos²t+sin²t`（括号内的平方和） | **不扩**，不许带括号和左边的 `asint` |
| 整个分子 / 整个分式 | **不扩** |
| 图 1：`a1` 拖到 `a2`（跨过两个根号的参数） | 扩到**分子**，不许到分式 |
| 图 3：`√a1+√a2`（跨过根号、但两端在壳外） | **不扩** |

⇒ **判据是"端点有没有切进对象内部"，不是"跨没跨过某个可见结构"**。
图 1 与图 3 都跨过根号，区别只在端点落在**壳内**还是**壳外**。

### 5. 第四层：探针量「分式左缘那个像素」

`\frac{a+x}{a-x}`，真渲染 + 真 `hitTestMathTex`：

- 合法位点：`[0, 6, 7, 8, 9, 11, 12, 13, 14, 15]`
  —— **0 = 分式开头，6 = 分子内容开头，5（`\frac` 与 `{` 之间）不是位点**。
- 公式内部点最左，只能落到 **6**；**0 点不到**（0 的像素在公式外侧）。

★ **由此钉死 `{...}{2}` 的成因**（比"起点侧没规则"更准）：

1. 拖选从 **6**（分子开头）到分式末尾（15）——屏幕上看就是"分子+分母都选中了"；
2. 片段花括号**计数 −1**（分子那个 `}` 多出来）；
3. `_balanceWithin` 往左挪，**挪一个字符**到 `{`（偏移 5），计数归零，停。

⇒ **真正缺的是 `\frac` + `{` 两个字符的"所有权"，规则只数了个数。**

### 6. 第五层：表的现状实测

文档 `$$\begin{pmatrix} a & b \\ c & d \end{pmatrix}$$`，选中两格：

- **复制** → 剪贴板 `$a & b \\ c & d$`：**没有 `\begin/\end`**，还被包成**行内**；
- **粘进同一矩阵** → `mathTex`、`planInsert` 不认 `&`/`\\`（moved=false）→ 原样插
  ⇒ `\begin{pmatrix} a & b \\ a & b \\ c & dc & d \end{pmatrix}`（从光标处"流"进去）；
- **粘进另一个矩阵** → `\begin{pmatrix} a & b \\ c & dx & y \\ z & w \end{pmatrix}`（顶成两行）；
- **粘进正文** → `asIs`，`$a & b \\ c & d$` 当行内公式 ⇒ `[公式不完整]`；
- **粘进行内公式** → `$aa & b \\ c & d+b$` ⇒ 同样坏。

⇒ 复制缺壳、粘贴零单元格感知，"像 Excel"只是碰巧。

### 7. 第六层：行列式非方阵 → 壳不能带源类型

从 4×4 行列式抠一个 2×3 的局部块，**它不是行列式**（代码里也存在
`EnvStyle.det` 强制方阵：`env_resize.dart:111`）。
⇒ 局部表用**中性壳** `bmatrix`；只有**整张表**被完整选中时才保留原类型。

### 8. 第七层：`cases` 不是两格

- `cases` 模板：`\begin{cases}\\ \end{cases}`——**没有 `&`**；预置例子用逗号
  `x,\ x\ge 0` / `-x,\ x<0` ⇒ **一行一格**。
- `aligned` 模板：`\begin{aligned}&=\\&=\end{aligned}`——**带 `&`**，`&` 是等号对齐点
  ⇒ **一行两格**。
- 带 `&` 的 `cases` 只可能来自外部文档（如 2026-10-24 的
  `\begin{cases}1,&x\in Q\\&\end{cases}`）；本编辑器里打不出 `&`（会被转义成 `\&`）。

### 9. 第八层：复制查片段、删除查剩余

- **复制**问"这段东西**自己**成不成立"；
- **删除**问"删掉之后，**剩下的**还成不成立"。

同一把尺子，量两个对象。分岔点：`a^2` 选 `a` → 复制 `$a$`（片段完整）；
删除剩 `^2`（`^` 无主）→ 扩成 `a^2`。**用户确认删除用这条原则。**

### 10. 第九层：剪切取「删除」的单元

剪切 = 复制 + 删除。若复制拿 `a`、删除删 `a^2`，用户会**静默丢掉 `^2`**。
⇒ **删什么就复制什么**：剪贴板 = 实际删掉的那一段。用户确认。

### ★ 本轮被推翻的判断（留痕）

1. 「分式左缘与分子左缘是同一个像素」——**错**：是两个位点（0 与 6），探针与截图都证明；
   分式的分数线两头超出分子分母，天然有结构专属像素。
2. 「壳带源类型（行列式还是行列式）」——**不成立**：行列式必须方阵，矩形局部块不行。
3. 「`cases` 一行两格」——**错**：我们的模板是逗号一格，`aligned` 才是两格。
4. 「起点侧没有规则」——**不准确**：规则动了（`_balanceWithin`），但按**计数**挪到了错误的地方。

## 三、定稿口径

### 3.1 完整 = **结构完整**

> 壳有主 + 命令参数齐 + 环境成对。

**壳**：`{` `}` `[` `]` `^` `_` `\begin` `\end` `\left` `\right` `&` `\\`

**主人**：

| 壳 | 主人 |
|---|---|
| `{` | 紧挨在前、需要参数的命令（`\frac` `\sqrt` `\text`…）；没有命令 = 它自己那一组 |
| `}` | 配对的 `{` |
| `]` | 它的 `[` |
| `^` `_` | 前面的底 |
| `\end` | 它的 `\begin` |
| `\right` | 它的 `\left` |
| `&` `\\` | 所在环境 |

- **普通括号 `(` `)` 不算壳**（普通打的括号不要求强行成对）。
- **围栏 `$` `$$` 不算壳，也不扩**——`$` 是零宽记账，不参与选区边界。见 §七（2026-11-03 追加口径）。
- 「在对象内部」≠「切开了对象」：选 `a1` 在根号里，但没碰壳 ⇒ 不扩。

### 3.2 复制（查**片段**）

> ★ 2026-11-03 追加（§七）：选区**不因 `$` 扩**；`$` 只在**载荷编码**里出现
> （数学 run 包 `$`、文字 run 原样；已含的 `$` 不重复包）。

- 片段完整 ⇒ **不扩**；不完整 ⇒ 扩到**最小完整单位**：
  - 表（matrix 家族）→ **高亮那一带**（端点吸到格边界；★ **不是外接矩形** —— 拖选是线性的，见 §9.1）；
  - `cases` → 碰到的那几**行**（一行一格）；
  - `aligned` → 整行（一行两格）；
  - 其它 → 对象 / 层（**“段”不在其列**，见 §七）。
- 表的壳：
  - **局部表** → 中性 `bmatrix`（行列式非方阵问题）；
  - **整表** → 保留原类型。
- 表粘贴：
  - **粘进表内**：剥壳取格；当前格 = 左上角；**整格覆盖**；超出边界**裁剪**并给状态栏说明；
  - **粘到外面**：形成 `bmatrix`；**行内 / 行间看落点**（落正文按行内）；
  - 参差行（只有导入/粘贴才有）按**最大列数补空**；
  - 光标停在 `&` / `\begin` 上（不在任何格里）→ 算**最近的那一格**。
- `cases` / `aligned` 的片段是**整块环境**，不是"局部表"；粘进表内 = 嵌套一个环境，不参与格分配。

### 3.3 删除（查**剩余文档**）

- 删完结构成立 ⇒ **照删**；不成立 ⇒ 扩到最小单位。
- **不套用复制的右向补全**（`\frac{a}` 不再被补成整段）。
- 删格：删每格**内容**，`&` / `\\` 保留（留空），**一步撤销**。
- ★ 2026-11-03 追加（§七）：**`$` 是零宽记账**——删可见内容不删它；
  行间块只剩空白 ⇒ 算空、回收；行内只剩空白 ⇒ **不算空**、保留。跨段时 `$` 保留。

### 3.4 剪切

- 取**删除**的单元；剪贴板 = 实际删掉的那一段（按 §七 的载荷编码）。

### 3.5 不扩的例子（用户校准）

`a1` · `x`（根号次数）· `cos²t+sin²t` · 整个分子 · 整个分式 · `√a1+√a2` ·
`a1 + √a2` 这种完整子式——**全部不扩**。

### 3.6 哪些环境算「表」

- **算**：`matrix` / `pmatrix` / `bmatrix` / `Bmatrix` / `vmatrix` / `Vmatrix`；`array` 若出现也算。
- **不算**：`cases`（行单位，一行一格）· `aligned`（行单位，一行两格）。

## 七、围栏不参与选区（2026-11-03 追加）

> **这一节推翻了本批 §三 里的一条旧口径**（“一端在段内 ⇒ 扩到段边界”）。
> 起因是用户对 T2(2) / T5 两个现场的追问：「为什么选区要被 `$…$` 制约？
> 我们从来没说过选区只能依附 `$…$`，按平权也不该这样。」

### 7.1 触发：两条真实源码

- **T2(2)**（`20261102作业编辑.md:136`）：
  `$y_{截}$=$asint(co s^{2}$t+$sin^{2}$t)=asint`
- **T5**（`:230`）：
  `...=$\lim_{t\to+\infty}(\frac{\alpha sint}{t^{\alpha-1}}$-$\frac{cost}{t^{\alpha-2}}$)`

屏幕上是一个式子，源里是**一串 `$…$` + 中间的正文**。用户高亮的是看得见的字符，
复制/删除却从“左边那段的 `$`”扩到“右边那段的 `$`”——多拿了 `\lim(`、`asint(`。

### 7.2 查到的约束来源（以及它为什么错）

- 来源是 `clipboardSlice` 的「① 段级配平」：为了让**剪贴板产物**自洽（`$` 成对）。
- 这是**产物编码**的需要，却被实现成了**扩选区**：`start/end` 既当“复制什么”又当“删什么”。
- 后果：`$\alpha\beta$` 与 `$\alpha$$\beta$` **编辑行为不等价**（同一个可见选区，
  一个在段内、一个跨段）——**直接违反平权推论④**。所以这不是“平权要求这样”，
  而是旧实现留下的墙。

### 7.3 结论

1. **选区只按可见流**：`$` 是零宽记账，和 `{` `}`、命令名同级；用户看不见它，
   它不参与“选区边界”。
2. **`$` 的处理移到作用时**：
   - **复制**：载荷编码——按源里的 span 把选中范围切成“数学 / 文字”交替的 run；
     数学 run 包 `$`，文字 run 原样；选区已含的 `$` 不重复包。
   - **删除**：删**可见字符**；`$` 留下（内容空了再回收）。跨段时 `$` 保留
     ⇒ 结果等价于“一次替换整段”，不是多次编辑。
   - **剪切**：删除区间 + 同一编码。
3. **分类继承源**：数学 / 文字只看源里的 `$`，不看字形（推论②）。
4. **边界归编辑器**：公式内部的命中到不了 `$`（`hitTestMathTex` 只给内容坐标）；
   从正文侧起选落在边界上时，由编辑器按确定规则归边——用户不需要避让。
5. **视觉不变量**：粘贴结果 = 高亮那段；对象完整性仍可补（只补对象，**不补 `$`**）。
6. **回收**：行间块只剩空白 ⇒ 算空、连围栏回收；行内只剩空白 ⇒ **不算空**、保留
   （空白是没被选中的内容；`\ ` 有宽度，裸空格零宽但仍是源里的字符）。
7. **跨段粘贴**：照既有“语境归一”——粘到正文原样（保留 `$` 对）；粘到数学里
   剥掉所有成对 `$`（文字 run 就地变数学；10-23 实测 `x+中文+y` 与
   `x+\text{中文}+y` 逐像素同尺寸）。不需要新规则。
8. **“段”从“最小完整单位”里去掉**：单位只有 对象 / 层（+ 表的矩形 / `cases` 的行）。
9. **撤回一个错误说法**：我此前把“删除会变成多段编辑”当成用户要接受的后果——**错**。
   用户眼里就是一 A1 二 B2 三 C3 连续的一段；多段只是实现，不该出现在口径里。

### 7.4 现状与影响

- 现有 `clipboardSlice` 仍按旧口径**扩到 `$` 边界**（本批已落地的复制就是它）；
  删除也沿用段归一。
- ⇒ 这次是**口径变更**，不是补丁：复制 / 删除 / 剪切都要按 §7.3 改；

## 九、表批 A 的两处修正（2026-11-03 晚）

### 9.1 ★ **拖选是线性的，"矩形"是错的**（推翻了 §3.2 与 §8.3 的说法）

用户 2026-11-03 指出：「我们的拖选并不是矩形的，跨行时是**从起点到该行落点**那一条带」。

- **现象（改前）**：3×3 里从 `b` 拖到 `e`，屏幕上高亮的是 `b c` + `d e`，
  而"外接矩形"实现会把没高亮的 **`a`、`f`** 一起复制走；**删除更糟——会把 `a`、`f` 的字清掉**。
- **口径（更正）**：单位是**高亮那一带** ——
  `(r0,c0)` = 第一个被碰到的格、`(r1,c1)` = 最后一个；
  覆盖 = 行 `r0` 的 `c0..行尾` ＋ 中间整行 ＋ 行 `r1` 的 `0..c1`。
  端点各自**吸到所在格的边界**（这是"扩到最小完整单位"，不是扩成矩形）。
- **实现**：`env_table.dart` 的 `cellsCovering` → **`cellsSpanning`**（`CellRect` → `CellSpan`），
  `cellsIn` / `cellsPayload` / `cellClearPlan` / `coversAllCells` 全跟着这条语义。
- **代价**：载荷可能**参差**（`b→d` 得 `b&c` / `d`）——§3.2 本来就写了"参差行补空"，
  补空留给**粘贴**，复制照实带走。
- **守卫**：`table_clipboard_test` 「横跨两行 ⇒ 高亮那一带（不碰 `a`、`f`）」·
  `table_delete_test` 「b→e ⇒ 清 `b c d e`，`a`、`f` 一个字都不许动」。

### 9.2 ★ **局部表片段粘到正文：不再造矩阵**（用户拍板）

- **规则**：载荷是我们补的**中性壳**（= 局部片段的标记）且落点在**正文** ⇒
  按行落成**行内公式**：`&` → `\ `、`\\` → 换行，状态栏说一句
  "表格片段已按行落成文字（n 行）"。
- **不变**：整表复制保留原类型（`bmatrix` / `pmatrix` / `vmatrix` …）⇒ 粘到正文**仍然是那个矩阵**；
  落点在**数学里**照旧走"归一成 tex"（`A=\begin{bmatrix}…\end{bmatrix}` 这种是合理形态）。
- **实现**：`paste_context.dart` 新增 `PasteApply.tableLines` + `_tableRowsText`；
  `edit_view.pasteText` 加一档。
- **守卫**：`test/lang/table_paste_text_test.dart` ·
  `table_flow_test` 「局部片段粘到正文 ⇒ 按行落成行内公式」。

### 9.4 ★★ 中性壳从 `bmatrix` 换成 **`matrix`**（用户实测打回）

- **现场**：用户整表复制（他那份表本来就是 `bmatrix`）粘到正文 ⇒ 变成三行文字，不是矩阵。
- **根因**：局部片段与整表**都**用 `bmatrix` 当壳 ⇒ 剪贴板里分不出"整表还是片段"。
- **修法**：局部片段的壳改成 **`matrix`（不带括号）**，整表仍保留原类型
  ⇒ `matrix` = 片段、其它 = 整表。`paste_context._tableRowsText` 只认 `matrix`。
- **代价**：局部片段粘进**公式**时是个无括号的矩阵（可接受）；源表本身是 `matrix` 的整表
  复制出来也会被当成片段（罕见，`matrix` 只有"粘进来的片段"才会出现）。
- **守卫**：`table_paste_text_test`「整表（bmatrix，用户那份就是）⇒ 照旧 asIs」·
  `table_clipboard_test` / `table_delete_test` / `env_table_test` 的载荷期望同步改成 `matrix`。

### 9.5 ★★ 粘进表内：**落格**（用户实测：一粘就把表拆散）

- **现场**：局部片段粘**进**表里 ⇒ 原来把 `\begin{matrix}…\end{matrix}` **原样插进格子**
  ⇒ 外面那张表被拆散，屏幕上是"一堆散字 + 一个新矩阵"。
- **修法**：`PasteApply.tableCells` —— 剥壳取格、当前格为**左上角**、**整格覆盖**、
  **超界裁剪**（状态栏："已粘进表格（2 行 × 2 列；超出表格边界的部分已裁剪）"）。
  只改格内容，`&` / `\\` 与壳原样保留 ⇒ 一次 `replace`、**一步撤销**。
- **实现**：`env_table.cellGridOf` / `cellWritePlan` / `cellNear` + `paste_context._tableCellsDecision`
  + `edit_view` 一档。
- **`cases` / `aligned` 载荷不参与格分配**（口径：整块环境 ⇒ 粘进表内 = 嵌套一个环境）。
- **守卫**：`test/lang/table_cells_paste_test.dart`(6)：左上角落 2×2 / 超界裁剪 /
  从中间格起向右下铺 / 不在表内不走落格 / cases 不分配 / 裸载荷也能切。

### 9.6 ★★ 格框：**按光标偏移定格子**，不按像素猜（用户："只有第一列画了框"）

- **现场**：点矩阵/行列式里的**空格子**，只有第一列的格子画得出虚线框。
- **探针（插桩 `math_caret`）**：`at=Offset(54.7, 16.8)`、`colBand={0: 14.7..34.7, 1: 54.7..74.7}`、
  却判成 `cell=(0,0)` —— 锚点 x **正好等于第 2 列左缘**，而 2026-10-24 那条
  「正落某列左缘（≤ +1.5px）⇒ 归左边那一列」把它往左让了一列 ⇒ 框画在左边那格 /
  （第一列没有更左的）就画不出来。
- **根因**：`a&b` 里"左格末尾"与"右格开头"是**同一个像素**（`&` 零宽）⇒ 像素判据只能二选一。
- **修法**：由**光标偏移**定格子 —— `env_table.cellAtOffset(tex, rel)` 给 `(行, 列, 环境序号)`，
  `doc_view` 算好传给 `MathWithCaret.caretCell`，`math_caret` 直接用它（有格子就不再走像素判据）。
- **守卫**：`test/editor/env_cell_frame_test.dart`(3) —— 全空 2×3 点六格、只填第一行的 4×6
  点下面三行的每一格、**行内** `$…$` 矩阵的四格，都要出框；**改前红**（点 (0,1) / (1,1) 无框）。
- ★ **补齐（同一晚）**：上面最初只接了**行间块**那条路径；行内 `$…$` 矩阵走 `inline_math_text`，
  仍用像素判据 ⇒ 列 > 0 照旧不画框（探针：行内 (0,1) `frames=0`、(0,0) `frames=4`）。
  现在 `inline_math_text` 也用 `s.tex + rel` 算 `cellAtOffset` 传下去。

### 9.7 ★★ 环境命中要**有边界**（用户："点两个矩阵中间点不到"、"x 过了加号把右边那个也粘进来"）

- **根因（一句话）**：`envCellHitAt` 没有"点在环境里吗"的检查 —— `envCellHitIn` 对任何点都返回
  **最近的一格** ⇒ 两个环境之间的空白、块外面的空白**全被吸进格子**。
  - 行间块（整块是一个 widget）⇒ 点两矩阵之间被吸进前一个矩阵的最后一格（实测 `EnvCellHit(1,1,尾)`，caret=39）；
  - 拖选终点越过 `+` ⇒ 终点被吸进第二个环境的第一格 ⇒ **右边那个矩阵也被粘进来**。
  - 行内公式之间为什么"点得进去"：空白在**公式 widget 外面**，由段落自己命中给偏移（不是这条链）。
- **修法**：`envCellHitAt` 先算环境的**外接盒**（`envInkBox`，由**行带 / 列带**并出来），
  点不在盒内（放宽 4px）⇒ 返回 `null`，落到普通落点（含"公式之前/之后"）。
  ★ 盒子不能只由**格子矩形**并 —— 空格子的矩形是**零高填充垫**，整表全空时并集是一根细线
  （第一版这么写，被 `env_click_test` ⑫ 与 `env_cell_frame_test` 当场抓红）。
- **守卫**：`two_env_click_test` 新增「点两个环境**中间**的空白 ⇒ 不许被吸进任何一格」
  （改前红：caret 落在前一格末尾）。

### 9.8 ★★ 空格子的竖条：高度取整条行带 ⇒ 看着"卡在两行之间"

- **实测**（用户的 `20261103矩阵测试.md` 第 1 行，行内、字号 16）：
  有字格 `(0,0)` 竖条 `2.5..16.0`（13.5 高）；空行格 `(2,0)` 竖条 `38.4..57.6`（**19.2 高 = 整条行带**）。
  行带是 19.2 一格、行与行首尾相接 ⇒ 竖条上下都顶到行界、还压到下一行字形 ⇒ 看起来"不上不下"。
- **根因**：2026-10-19 为了让"竖条与格框不分离"，空格子直接把 `envBox`（=整条行带）当竖条。
- **修法**：改用与其它格子**同一把尺子** —— `caretBarRect(localRowBox: envBox)`（行盒内缩 `kCaretInset`）
  ⇒ 高度与有字格一致、四周留缝、仍在同一行里。**契约变更**：`env_row_band_test` ⑭ 原来断言
  "竖条与框同顶同高"，改成"竖条在框内、不画满、也不短于 0.6 倍"。
- **守卫**：`env_cell_frame_test` 新增「空格子的竖条不许画满整条行带」。

### 9.9 拖选"扩多了"：实测没扩，**同一个根因**

- 编辑器**没有**"跨行 ⇒ 整行选择"这条规则；矩阵在源码里也只占一行。
- 按用户描述复现（起点 = 第一行第一列左缘外 3px，终点 = 最后一行最后一列右缘外 3px，没到 `+`）：
  `SEL 16..47`，复制出来正是 `$\begin{bmatrix}a&b&&&&\\c&d&&&&\\&&&&&\\&&3&&&\end{bmatrix}$` —— 只带第一个矩阵。
- ⇒ "扩多了"就是 §9.7 那条：终点一旦越过 `+`，被"最近格"吸进**第二个环境**。边界检查补上后应一起消失。

### 9.10 ★★ 环境外落点：与普通符号**同一条判据**（2026-11-03 晚收口）

> 用户追问："为什么环境外的定义会受矩阵管制？行列式之间不就应该像普通数学语言之间那样
> 能自然插入光标吗？"—— 对。**规则不该有第二套**，是兜底链断了。

- **实测（改前）**：两个贴着的行间矩阵，点中间的空隙：

  | y | 落点 |
  |---|---|
  | 2 / 12 / 40 / 46（行内高度） | 54 / 59（第二个矩阵的格子里）—— 还算"中间" |
  | **18 / 22 / 24 / 26 / 34（行与行之间）** | **0 = 块首** ← 用户"点不到" |

- **根因**：`envCellHitAt` 拒收（盒外 ⇒ null）之后落到 `glyphlessLanding`，它在
  **横向在字形并集内、纵向错开**时返回 `null` ⇒ `doc_view` 返回 null ⇒ 页面兜底到块首。
  而它的候选里**没有"环境"这个对象**（只认结构盒＋字形并集）。
- **修法**：新增 `env_cells.envNearestEdge`（按**横向距离**选最近的环境边界，纵向不参与），
  `doc_view` 在环境格/字形都落空时用它 ⇒ 返回该环境 `\begin` 之前 / `\end` 之后（用**环境序号**
  在源 tex 上取，避免渲染偏移错位）。+ 环境**序号**口径沿用 `envIx`。
  ⇒ 至此"点在空白 ⇒ 就近落到最近的对象边界"对**普通符号与环境是同一条**，不再有"环境外"这个特殊概念。
- **守卫**：`two_env_click_test`「点两个环境中间」改成断言落点 ∈
  `[前一个 endEnd, 后一个 beginStart]`（改前红：0 / 前一格末）。

### 9.11 ★★ 高亮与选区统一：**装饰属于它所在的对象**（2026-11-03 晚收口）

> 用户追问："为什么高亮和选区的判定在可高亮的东西上都不统一？"—— 因为高亮不是第二套判据，
> 而是**把字符区间映射成矩形**；而括号/分数线这些**装饰没有字符**，只能"猜归属"。

- **实测（改前）**：选区到 `+`（`SEL 16..61`，载荷也只到 `+`），但高亮 16 块里有两块
  `216.9..227.6` = **第二个矩阵的左括号**（其格子左缘 227.6）⇒ 视觉像"扩进右边矩阵"。
- **根因**：`selectionBands` 的兜底「**没有归属的盒，跟最近的有主盒走**」（2026-10-20 为修
  "个别块漏底"加的）—— 它按**位置/顺序**跟队，会**跨对象**。
- **修法**：装饰按**所属环境**判 —— 环境里**可见字符（原子）全在选区内** ⇒ 定界符算选中；
  否则不涂。实现：组 → 环境（`srcStart` 落在哪个 `bodyStart..bodyEnd`）、每环境矩形由有主盒并出、
  定界符按方向归属（`]`/`)`/`}` 归左、`[`/`(`/`{` 归右，距离 ≤ 30px），
  并在"邻居兜底"里**跳过**已按环境判过的定界符。空环境（无原子）退回"选区碰到源码区间"。
- **守卫**：`test/render/selection_env_bands_test.dart`(2) ——「选中'第一个矩阵 + 加号' ⇒ 第二个矩阵的
  括号不许涂」（**改前红**：`[` 被涂）、「整段全选 ⇒ 两个矩阵的括号都要涂」。

### 9.3 表批 B 还没做的部分

**参差行补空**（复制不补、粘的时候按最大列数补空）、**光标在 `&` / `\begin` 上算最近格**
（`cellNear` 已能兜，但"光标停在 `&` 上"的落点语义还没单独定过）。
**已知边界**：空环境（一个原子都没有的矩阵）没有"可见字符"，高亮用"选区碰到源码区间"兜；
`‖` / `|` 这类双向定界符按"左"归（贴得最近的那个环境）。
