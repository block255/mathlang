## 二、今晚钉死的口径（新增）

1. **行内主行竖条 = 行盒中心**：文字侧 `_caretInset = (行盒 − 1.25em)/2` ⇒ 竖条就是居中于行盒；
   行内公式长在这一行里 ⇒ 单行段的**段落盒中心**就是它（多行段退回旧行为）。
   h 仍是 `字号 × 1.25`（U3）；**行内 vs 行间的高矮差是设计内的**，不要"顺手统一"。
2. **块边界刻度与竖条必须错开**（`kTickGap = 3`）：刻度是"边界提示"，竖条是"插入点"，
   两者不许同 x —— 同 x 时淡色刻度会把深色光标盖成淡色。
3. **Enter 的落点不许手算**：问行表（`blankRunAfter` + `blankRowStart`），
   与渲染同一条判据；手算 `at+2` 会落到"段落分隔符"（零高、不是行）上。
4. **让位前先确认对方会画**：空行让给块之前，先用 `blockShowsCaret` 问一次 ——
   否则"空行让位、块也不画"⇒ 两处都不画。

## 三、⚠️ 未收口（下一次开工第一件）

**"公式之前 / 之后"那两格的几何是错的**：竖条按

```
x = 块的盒子外缘（±(caretWidth+1.5)）
y = 单行块 ⇒ 锚点在公式里的基线（at.dy）
```

也就是**"块盒 × 公式基线"**，既不是"块边界"的语义位置，也不是"空行行首"。
于是屏幕上会同时出现：**块边缘一根淡色刻度 + 公式基线一根条 + 空行行首一根条**
（用户原话：**"出现了一个刻度，两个光标"**）。

**正解（甲，待用户点头）**：
- "公式之前 / 之后"这两格**由"行"来画**（空行槽 / 相邻段落），画在**行首 + 那一行的行盒**；
- **块不再画这两格的竖条**，只保留那根刻度（刻度画在块外缘，语义正确）；
- 这**推翻 2026-10-24 批 23 的"共享格让给块"**，所以要用户拍板。

### 8.7 方法教训四条里的第四条
