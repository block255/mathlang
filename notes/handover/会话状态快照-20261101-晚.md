## 二、今晚钉死的口径（新增）

1. **行内主行竖条 = 行盒中心**：文字侧 `_caretInset = (行盒 − 1.25em)/2` ⇒ 竖条就是居中于行盒；
   行内公式长在这一行里 ⇒ 单行段的**段落盒中心**就是它（多行段退回旧行为）。
   h 仍是 `字号 × 1.25`（U3）；**行内 vs 行间的高矮差是设计内的**，不要"顺手统一"。
2. **块边界刻度与竖条必须错开**（`kTickGap = 3`）：刻度是"边界提示"，竖条是"插入点"，
   两者不许同 x —— 同 x 时淡色刻度会把深色光标盖成淡色。
3. **Enter 的落点不许手算**：问行表（`blankRunAfter` + `blankRowStart`），
   与渲染同一条判据；手算 `at+2` 会落到"段落分隔符"（零高、不是行）上。
4. **让位前先确认对方会画**：空行让给块之前，先用 `blockShowsCaret` 问一次 ——
   否则"空行让位、块也不画"⇒ 两处都不画。

## 九、★★ 21:0x–22:0x 第三批：围栏 / 空块 / 删除边界（用户逐条验过：1、2、4 无误，3 修后无误）

### 9.1 现场的起点：用户在 `f'(0)=0` 后面踩到的两件事

1. 点击/`→` 之后**光标消失**，再打一个字**整段崩成裸源码**（反馈 22）；
2. 页面中间有一条**缝里的光标**（"这是什么鬼位置"），按退格**删不掉**（反馈 10 ＋ 新复现）。

### 9.2 三个根因

**① 光标落在"围栏字符"上**（`2eb95f4`）

行内公式早就有口径「跨 `$` 边界进公式，**且光标不落在 `$` 上**」，**行间块一直没有**。
于是 `→` / `←` / "点块前那段空白" 三处都会停在 `$$` 的第一个 `$` 上。
在那一格打字 ⇒ `$$` 变成 `w$$` / `$w$` ⇒ 那一行不再以 `$$` 开头 ⇒
**后面所有块的配对整体错位** ⇒ 一串 `[公式不完整]` ＋ 裸源码。

⇒ 新增两个概念的**分工**（这是本批最该记住的口径）：

| 概念 | 是谁 | 可以含围栏字符吗 |
|---|---|---|
| **认领范围**（`acceptFrom` / `acceptTo`） | 谁**画**这根光标 | ✅ 可以（`→` 可能路过） |
| **落点 / 插入点** | 光标停在哪、打字插在哪 | ❌ **绝对不行** |

落地：`displayTexStartAt()` **一个函数给三处用**（`→` 进块、`←` 出块、点击段距），判据不会漂。
顺带修掉 **F15**（行间块 tex 末尾按 `→` 算回同一格 = "按了没反应"）。

**② "只有间距"的公式块是**第三种状态**（`4d129f4`，用户拍板「甲」）

现场（用户当场复现）：空行 → 点「行间公式」→ 空块（虚线小框）→ **打一个空格** ⇒ 变鬼。

```
空的（`text.trim().isEmpty`）  →  虚线小框，占一行高      ✅ 合法
有内容                        →  公式，有行              ✅ 合法
只有间距（`\ ` `\quad` …）      →  **什么都没有、0 高**     ❌ 第三种状态
```

`\ ` 从哪来：`edit_view` 里"数学段按空格 ⇒ 插 `\ `"（2026-10-17 拍板）⇒ **一个空格就能触发**。
渲染盒实测 `Size(1000, 0)`（宽有、高 0）⇒ ① 没有行 ⇒ 光标卡在缝里；② 套 `FittedBox` ⇒
`min(w/1000, 0/0)` = **NaN** ⇒ 一个像素都画不出；③ `smartBackspace` 在 `rel==0` 时返回 `none` ⇒ **删不掉**。

⇒ 判据从"真的一无所有"扩成「**没有任何会画墨迹的东西**」（`isInklessTex`）
⇒ 只剩间距的块**照样画虚线小框**（可见、占一行、光标在框里），并且**块里任何位置按 ⌫ ⇒ 整块回收**。

★ 用户原话：**「甲这个不叫代价，只能说叫把鬼抓出来了；抓出来的鬼我删掉不就行了」**
★ 另一句同样重要：**「行间的空格能承接光标是正确的，要不然我打空格之后打了空格的地方不是变死区了吗」**
　⇒ 所以不能把"有空格"当成"没有内容"（那会让空格变成死区）。**抓鬼 ≠ 取消空格的位置**。

**③ 删空块时多吃了一个换行**（`2aae524`）

`reclaimEmptiedMath`（2026-10-18 的"删空即连定界符一起删"）里有一句
`if (a > 0 && doc[a-1] == '\n') a -= 1;` ⇒ 把**上一行的行尾**和**块后面那一行**缝在一起：

- 后面是分割符 ⇒ `只能f'(0)=0---`（两行粘一行，用户第三张图）；
- 后面**紧贴另一个块** ⇒ `…上一行文字$$` ⇒ 那个 `$$` 跑到行中间、不再是围栏
  ⇒ 后面全部错位 ⇒ 裸源码（用户第二张图）。

⇒ 块占的是**自己的行**：删掉它只该少一行，**不许动别人的行尾**。只吃块**后面**那个换行。

### 9.5 教训（第五条）

**我一度把"乱码"和"鬼块"混成一个病。** 用户的纠正是准的：
「那个 `f'(0)=0` 后面乱码的 bug **跟 `\ ` 空格没有关系**，你看清楚它后面是什么」。
真因是"插入点落在围栏上"（①），`\ ` 只是同一个位置上的另一件事（②）。
**两个病在同一个像素上叠加时，特别容易被我缝成一个故事。**
手法：先分别说清"如果只有 A 会怎样、只有 B 会怎样"，再看它们是不是同一个位置。
