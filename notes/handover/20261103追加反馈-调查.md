## 1. 公式尾退格：一次删光整段

**实测**（`$f^{\prime}$(`，光标在末尾）：

```
① 退格 ⇒ 「$f^{\prime}$\n」 光标=12      ← 删掉 `(`
② 退格 ⇒ 「\n」            光标=0       ← 整段公式 + 空壳一次收走
③ 退格 ⇒ 「\n」            光标=0
行首 Enter ⇒ 「\n\n」 光标=1
```

**纯函数证据**（`smartEditAt`，同一份 tex）：

| 光标 | 计划 |
|---|---|
| at=10（`\prime` 之后） | `[4,10)` ⇒ 删 `\prime`（留 `^{}` 空槽，合理） |
| at=11（收尾 `$` 之前） | **`[1,11)`** ⇒ 删整个内容 |
| at=12（收尾 `$` 之后） | **`[1,11)`** ⇒ 同上 |

⇒ 公式**尾**（`closeEnd`）的退格给的是"整个内容"，不是"最后一个对象"；随后 `delete_reclaim`
（删空数学段 ⇒ 连定界符一起删）把空壳也收走 ⇒ 观感是"一次退格整段消失"。

**用户看到的三件事**：
- "整段消失" = 上面这条；
- "光标落到下面一个空行" = buffer 只剩 `\n`，再按 Enter 就走到 §2 那条落点问题；
- "`f` 一撇向上跳" = 删掉 `(` 后**行盒变矮**（`(` 的上下缘比 `f'` 高），公式随行盒居中 ⇒ 上移几像素 ——
  属排版副作用，**不是状态错**（要不要抹平是另一件事）。

## 2. Enter 之后"下两行" + 两种通道落到不同行

**实测**（`≠0`，光标在行末）：

```
Enter ⇒ 「≠0\n\n」 光标=3      ← 两个换行之间那一格
在该光标粘 a ⇒ 「≠0\n\na\n」   ← 文本通道**跳过**了分隔符，落到下一行
```

- 一次 Enter 在行末**只补一个 `\n`**（`_enterPayload`：`c==le && !nextHasText ⇒ '\n'`），
  加上 `ensureDocumentEol` 补的那个 ⇒ 缓冲里两个 `\n` ⇒ 视觉上"下两行"。
- 落点在 `c+1` = **两个换行之间**，而那一格是**段落分隔符**（零高度、"不是位置"）。
- ⇒ "打 `a` 落一处、插 `α` 落另一处" = 文本通道会 `skipParagraphSeparator` 跳过它，
  而符号面板走 `applySymbolInsert`/`planInsert`，**不保证**跳过（这条待再量一次）。

历史：2026-11-01 的 F13 只把**空行串分支**的落点改成"问行表"（`blankRunAfter` + `blankRowStart`），
**主分支仍是 `c+1`** —— 就是这里。

## 3. 指数套指数 / 下标套下标被禁

**实测**（`$x^{y}$`，光标在 `y` 之后、`}` 之前）：按 `6` / `Shift+6` ⇒ **文档一个字符都不变**（`^` 被吞）。

两条路，同一处判据太粗：

| 路径 | 代码 | 现在的判据 |
|---|---|---|
| 打字 | `auto_expand.atScriptContentEnd`（`auto_expand.dart:183`） | 光标在**任何**脚本槽末尾 ⇒ 吞掉 `^`/`_` |
| 面板 / 快捷键 | `script_nest.scriptInsertWouldNest` ①（`script_nest.dart:29`） | 最内层槽是**同种**脚本 ⇒ 拒 |

而 **`x^{y^{2}}` 是合法的**（基座 = `y`）；真正非法的只有"空槽里再套"（`x^{q}` 没有基座那种）。
⇒ 原意（禁空槽套娃）被放大成了"禁一切脚本套娃"。

修法方向：两条判据都补一句"**槽里光标前有可见原子**才允许"（等价于 `x^{y|}` 放行、`x^{|}` 仍吞/拒）。

## 4. 空行行首打空格 ⇒ 光标消失

**实测**（`甲\n\n乙`）：

```
空行行首 光标=2 竖条=null
打 3 个空格 ⇒ 「甲\n   \n乙」 光标=5 竖条=null
```

- `blank_runs.blankRunFrom` 的判空行：`buf.substring(o, end).trim().isNotEmpty ⇒ break`
  —— 注释原话"**只有空格的行也算空行**"。
- 于是含空格的行仍被当成"空行串"的一员 ⇒ 渲染成**空行槽**（`_BlankSlot`，不排版）⇒
  空行槽只在"光标 == 该行行首"时画竖条（`offs` 里只有行首偏移）⇒ 行内位置**没有竖条**。
- 用户目标（**用空格手动对齐、画符号示意图**）因此做不了：空格既不参与排版，光标也不跟随。

口径二选一（**需拍板**）：
- **甲**：**只有真正为空（长度为 0）的行**才走空行槽；含空格的行 = 普通段落（空格有宽度、光标按它推进）。
  —— 改动集中在 `blankRunFrom` 的判据 + 受影响的版面高度用例；对齐能力立刻回来。
- **乙**：空行槽支持"行内位点"（自己按"空格数 × 空格宽"推进 x 并画竖条）—— 不动空行模型，但要自己造排版。

## 7. "幽灵残留"找到了：**行内空壳留下的 `$$`**

用户 2026-11-03 23:1x 补充："重新打一遍复现不出来；能复现的那份文档，是我**删过一次 f 撇之后**变成这样的"。

**先排除文件本身**：`test_data\ascll删除下跳.md` 字节实测 —— 23 字节、**无 CR**、无行尾空白、LF 6 个，
内容就是 `a\n\n$f^{\prime}$(x)\n\na\n` ⇒ **"污染"不在文件里**。

**在运行时状态里，实测（`DocView` + `smartEditAt`）**：

```
起手：a\n\n$f^{\prime}$(x)\n\na\n     光标=15（`$` 之后、`(x)` 之前）
退格：计划 [4,14) = 只删 `f^{\prime}`（一个对象，符合 §3.2）
结果：a\n\n$$(x)\n\na\n            ← ★ `$` 与 `$` 相邻 = 行首 `$$`
inlineDoubleDollarLines 报的行号：[]  ← ★ 没报！因为 `$$` 在**行首**，被判成"合法的行间围栏"
再按 Enter：a\n\n$\n\n$(x)\n\na\n     ← `$$` 被劈成两行
```

⇒ **幽灵 = 行内公式被删空后留下的 `$$`，而它正好在行首 ⇒ 被块模型当成行间围栏**：
- 那一页从此按"行间块"排版（后面的 `(x)` 与下一行都被吸进去）⇒ 光标/行的对应整体错位 ⇒
  用户看到的"删完跳到下一行""行首 Enter 退行时不时出问题"；
- 再按 Enter 会把 `$$` 劈开 ⇒ 越弄越乱；
- 重新打一遍不会有这个 `$$` ⇒ 复现不出来 —— 与用户描述完全吻合。

为什么没收：`delete_reclaim` 按 2026-11-03 §七 收窄过的口径**不回收行内空段**
（"行间空白算空、行内不算"）⇒ 行内公式删空后**定界符留着**。

### 7.1 修法候选（需拍板）

1. **★ 行内空段若会造出 `$$` ⇒ 必须连定界符一起收**（给 §七 的"行内不算空回收"开一个例外：
   **相邻两个 `$` 会拼成 `$$` 时必须收**）。这条最像"根治"，也只影响这一种形状；
2. `$$` 出现在**行首但后面还有内容**（`$$(x)`）时，不该被当成行间围栏 —— 判据可以再加一条
   "围栏行必须**整行**只有 `$$`"（`BlockMarkers.isMathFence` 已经是"整行"，但 `math_spans` 的
   `_atLineStart` 只看行首）⇒ 两处口径要对齐；
3. Enter 落点问行表（§2 那条）。

## 8. "光标能停的地方"与"字插进去的地方"为什么不统一（2026-11-03 23:3x 量）

### 8.1 现状：两层各有判据

| | 判据在哪 |
|---|---|
| **光标** | 点击 / 方向键那一路：`math_nav.skipParagraphSeparator`（跳过段间距那一格）、`blankRowStart`（哪几个空行才是行）、`buildCaretSites`（数学里的合法位点） |
| **插入** | `render/insert_guard.planInsert`：**17 处 `why=` 挪位分支**（落点会被挪离光标） |

### 8.2 把 17 条逐条分类的结果（**推翻了"大多数是兜非法光标"这个猜测**）

| 类 | 条数 | 例子 |
|---|---|---|
| **载荷 / 结构语义**（光标合法，但插进去会破坏结构） | **15** | 载荷自带 `$` 不许插进公式内部 · 多行载荷落在围栏行 ⇒ 挪到围栏行之后 · 块级载荷落在行首标记行 ⇒ 吸到行首 · 分页符是原子（3 条）· `\sqrt[…]` 次数里不许落结构 · 括号对必须同层 · **`neutralPoint` 语法粘合挪位**（这条恰好是"光标画哪 = 打字插哪"的**实现**，注释原话） |
| 定界符内部那两格（"tex 末尾 / 收尾 `$` 之后"） | 2 | 挪进公式 / 落块之后 —— 但 §3.3 已定"两者是同一根像素、都算**可达位点**" ⇒ 属语义，不是兜底 |
| **纯粹"兜非法光标"** | **0** | —— |

⇒ **结论（改判我上一轮的判断）**：插入层没有"兜非法光标"的规则。
"光标与插入不统一"的根因**不在插入层**，而在**光标层缺校验**：
`setCaret` 的出口没有统一吸附，而 **Enter 是手算 `c+1`**（`edit_view.dart:496`）⇒ 只有这里能把光标送进"不该去"的那一格。

⇒ "一位点模型"的具体动作（不是删规则）：
1. **光标层**：所有 `setCaret` 出口统一过一遍"吸附到最近合法位点"（现在只有点击/方向键过）；
2. **Enter 落点问行表**（`blankRunAfter` + `blankRowStart`，与 2026-11-01 F13 同一手段）；
3. **插入层**：17 条一条都不删，但**每条都要上状态栏**（原则 5：静默失败必须可见）。

### 8.3 顺带：#3 是**三处**同源判据，要一起改

| # | 位置 | 现在的判据 |
|---|---|---|
| 1 | `auto_expand.atScriptContentEnd` | 光标在**任何**脚本槽末尾 ⇒ 吞掉 `^`/`_` |
| 2 | `script_nest.scriptInsertWouldNest` ① | 最内层槽是**同种**脚本 ⇒ 拒 |
| 3 | **`insert_guard`「插入点落在指数/下标的末尾 ⇒ 挪到对象之后」** | 纯脚本载荷落在脚本内容末尾 ⇒ **搬出脚本**（理由同前两条："在脚本里再嵌一层空脚本会解析失败"） |

三处都只看了"槽是同种脚本 / 在槽末尾"，**都没看槽里光标前有没有基座** ⇒
合法的 `x^{y^{2}}` 被三处一起挡死。改法同一条：**空槽才挡，有基座就放行**。
