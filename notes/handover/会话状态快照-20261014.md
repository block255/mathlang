## 六、环境与 API 事实（新增，避免重复踩）

1. ★★ **Chrome 遮挡判定会让 CDP 点击静默失效**：浮窗浏览器被别的窗口盖住 → `document.visibilityState === 'hidden'`
   → 不产帧、不处理指针，**现象和"按钮坏了"一模一样**。
   处置：交互前先确认可见；`browser_dock window state=minimized` → 再 `normal` 可把窗口提回前台。
   → **结论：本项目的关键验证尽量搬到 widget 测试**（帧是同步的、可复现），浏览器只当"肉眼看一眼"。
2. **`RenderParagraph` 没有 `computeLineMetrics()`**（那是 `TextPainter` 的私有能力）；
   取行盒要用 `getBoxesForSelection(..., boxHeightStyle: ui.BoxHeightStyle.includeLineSpacingMiddle)`。
3. **`getOffsetForCaret` 不能当"行号"用**：同一行内它会随字符 / 占位符抖动。
4. **错误钩子里不能在 paint 期同步 `setState`**（会再抛 `Build scheduled during frame`，打断帧管线，之后点击全失效）；
   要在帧末刷新。
5. **`addPersistentFrameCallback` 比 `WidgetsBinding` 自己的 `drawFrame` 注册得晚** →
   在它里面 `setState` 只对**下一帧**生效。要"同一帧内标脏"必须用 `scheduleFrameCallback`（transient）。
6. **flutter_math_fork 的 `Math` 会把 `Line(key: GlobalKey)` 记忆化** → 同一个 widget 实例不能放树的两个位置。
7. 受限沙箱下 `flutter` / `dart` 的任何命令都会失败（用管道拉子进程）→ **构建与测试需要完整访问权限**，
   约定把这类命令**攒到阶段节点一起跑**。环境变量重定向到 `_cache\*` 仍是必要条件。

## 十、操作纪律（每条都是踩出来的）

1. ★ **交互前先确认浏览器可见**（`visibilityState !== 'hidden'`），否则点击静默失效。
2. ★ **release 基准 / 性能数据必须先预热**，且第一轮要用内部自洽性筛一遍。
3. ★ **每次点击前重新取坐标**（工具栏 `Wrap` 会因文字变长而重排）。
4. ★ **语义树一开，CDP 坐标点击会退化成"点元素中心"** → 注入
   `flt-semantics, flt-semantics-container, flt-semantics-host { pointer-events: none !important; }` 后可读又可点；
   **热重启后语义树要重新启用**。
5. **报告要能被自动化读回就别用 `SelectableText`**（内容不进语义树）；用 `Text`。
6. **删文件前先打印解析后的绝对路径并核对**（本仓约定）。
