## 六、★ 环境与 API 事实（新增，避免重复踩）

1. ★★ **镜像输入框装原始文本 → 插入符位置永远对不上**（原始 `$...$` 与视觉文本不同构）。
   ★★ **但正解不是 `setCaretRect`** —— 2026-10-14 晚读引擎源码实测：**`TextInput.setCaretRect` 在 Web 上是空函数**
   （`// No-op: not supported on this platform.`）。Web 上真正可用的只有三条杠杆：
   `setEditingState`（`element.value` + `setSelectionRange`）、
   `setEditableSizeAndTransform`（`element.style.{width,height,transform}`）、
   `setStyle/updateStyle`（CSS 字体）。
   → 做法：**平台元素里什么都不装**（插入符 = 元素原点）、**把元素摆到光标的精确 x**。
2. ★★ **零宽 `WidgetSpan` 照样占 1 个码元** —— 会破坏依赖段落坐标的映射。
3. ★ **`\cursor` 在文本模式（`\text{}` 内）完全不被接受**（6 种写法全 ParseException）。
   处置：把 `\text{}` **拆成两半**，光标落在中间。
4. ★ **`\cursor{}` 的颜色 = `options.color` = 公式文字色**（不是主题色）→ 裸注入会得到黑光标。
5. ★ **`\sqrt[n]{body}` 的渲染顺序与源码顺序相反**（KaTeX 节点是 `[body, index]`）。
6. ★ **数学字形会画出 Math 根盒之外**（单个 `x`：根盒 7px 高、字形盒 16px）；且 `Rect.contains` **下边界是开区间**
   → "必须在边界内"这类判据会**静默误杀**真原子。
7. ★ **父 widget 的 post-frame 回调早于子 widget 的** → "帧末收集子节点信息"第一帧必然拿不到数据。
8. ★ **自动化输入**：`browser_dock type` 直接插文本（**能**验证文本通道）；
   `browser_dock key` 只发原始按键（不产生 DOM 文本输入）但**能**到 Flutter 的 `onKeyEvent`。
   ★ **IME 组合态现在可以自动验**：设 `textarea.value` + 派发 `compositionstart/update/end` + `input`
   （引擎 `composition_aware_mixin.dart` 就是这么读的）。
9. **CanvasKit 会刷 `Shader compilation error` 并丢白帧**（点击/移动鼠标/打字时偶发，动一下鼠标恢复）；
   控制台特征是**每个着色器都报 `(unknown error)`** → 更像本机 WebGL 路径不稳。
10. 受限沙箱下 `flutter` / `dart` 的任何命令都会失败 → **构建与测试需要完整访问权限**，攒到阶段节点一起跑。
11. ★★ **`debugPrint` 在 Flutter Web 上走浏览器控制台，不进 `run.log`** → 探针要用 `browser_dock console` 读
    （第一次读 `run.log` 得到 0 行，差点误判成"事件没送到"）。
12. ★★ **`visibilityState === 'hidden'` 时 Flutter Web 停止出帧** → `await endOfFrame` 会**永远挂住**。
    做性能基准 / 等待渲染前必须先确认页面可见（操作纪律第一条）。
13. ★★ **`Title` widget 在 Web 上直接写 `document.title`**（引擎 `platform_dispatcher.dart`）
    → **CanvasKit 下唯一零成本、100% 精确的读数通道**。★ 截图 OCR 会把 203 读成 208，别拿它下判断。
14. ★ **细线在压缩截图里会消失**：光标 2×8 px 被 JPEG 压成灰蓝，识图模型与窄颜色窗口**都报"没有"**。
    像素级验证要用程序扫，并**先扫全图校准阈值**。
15. ★ **`mounted` 在 `dispose()` 期间仍然是 `true`** → `dispose()` 里若触发监听回调再
    `setState`，会撞 `_lifecycleState != defunct` 断言。**先摘监听，再 dispose 控制器**。

   ② 开无障碍语义树 `flt-semantics-placeholder.click()`（注意：**会切换文本输入策略**，测输入层时别开）。

## 十一、★ 性能基线（2026-10-14 实测 · 跨平台同一把尺子）

**测法**：演示页「基准(20字)」按钮（`spike/s3_edit/`），在样本 `kEditSample` 上插 20 个字，
用 `FrameTiming` 采每帧的 `build`（Dart 工作量）与 `raster`（像素活），报 p50/p95 + **采到的帧数**。

**环境必须一致才可比：1434×900 视口、`devicePixelRatio = 1.0`、页面可见。**

| | build p50 | build p95 | raster p50 | raster p95 | 一帧合计 p50 |
|---|---|---|---|---|---|
| debug web（DDC/JS） | 6.3 | 13.4 | 8.4 | 10.5 | **14.7 ms** |
| release web（dart2js -O4） | **2.2** | **5.0** | 9.0 | 10.7 | **11.2 ms** |
| 收益 | **2.9×** | 2.7× | ≈1（噪声内） | ≈1 | **1.3×**（余量 2 → 5.5 ms） |

**三条结论（回答"各平台手感"的地基）**：
1. 一帧 = **build（随构建模式/平台变 → 我们代码的成本）** + **raster（与构建模式无关，由显示器缩放与窗口尺寸决定）**
2. 本机屏幕缩放 **150%** → `dpr1.5` 时像素量 ×2.25 → 光栅化 9.0 → 17.2 ms，**完全由像素量解释**。
   → **换 100% 缩放的显示器比换平台的影响还大**
3. release web 的 **build 快 ~3×** 是 **DDC→dart2js** 的收益（**不是** JS→AOT）；
   AOT（Android/Windows）还能再快，**待 Android 实测**（同一个按钮直接跑同一段基准即可）
