## 六、★ 环境与 API 事实（新增，避免重复踩）

1. ★★ **镜像输入框装原始文本 → 插入符位置永远对不上**（原始 `$...$` 与视觉文本不同构）。
   正解：`TextInputConnection.setCaretRect(Rect)`（SDK 已确认存在，`EditableText._updateCaretRectIfNeeded` 就是这么干的）
   → **自实现 `TextInputClient`**，把我们的光标矩形告诉平台；组合中间态自己画在光标处。
2. ★★ **零宽 `WidgetSpan` 照样占 1 个码元** —— 会破坏依赖段落坐标的映射（本轮最大的坑）。
3. ★ **`\cursor` 在文本模式（`\text{}` 内）完全不被接受**（6 种写法全 ParseException）。
   处置：把 `\text{}` **拆成两半**，光标落在中间。
4. ★ **`\cursor{}` 的颜色 = `options.color` = 公式文字色**（不是主题色）→ 裸注入会得到黑光标。
5. ★ **`\sqrt[n]{body}` 的渲染顺序与源码顺序相反**（KaTeX 节点是 `[body, index]`）。
6. ★ **数学字形会画出 Math 根盒之外**（单个 `x`：根盒 7px 高、字形盒 16px）；且 `Rect.contains` **下边界是开区间**
   → "必须在边界内"这类判据会**静默误杀**真原子。
7. ★ **父 widget 的 post-frame 回调早于子 widget 的** → "帧末收集子节点信息"第一帧必然拿不到数据。
8. ★ **自动化输入的两条硬限制**：`browser_dock type` 直接插文本（不合成按键）；`browser_dock key` 只发原始按键
   （不产生 DOM 文本输入）→ 字符类编辑效果只能靠真人键盘验。
9. **CanvasKit 会刷 `Shader compilation error` 并丢白帧**（点击/移动鼠标/打字时偶发，动一下鼠标恢复）；
   控制台特征是**每个着色器都报 `(unknown error)`** → 更像本机 WebGL 路径不稳。待做：先按"去掉透明 TextField"再 release 复核。
10. 受限沙箱下 `flutter` / `dart` 的任何命令都会失败 → **构建与测试需要完整访问权限**，攒到阶段节点一起跑。

## 十、操作纪律（每条都是踩出来的）

1. ★ **交互前先确认浏览器可见**（`visibilityState !== 'hidden'`），否则点击静默失效；
   `window state=minimized` → `normal` 可提回前台。
2. ★ **每次点击前重新取坐标**（工具栏 `Wrap` 会重排）；点击后**再补一张截图**（鼠标/键盘类操作的
   截图可能晚一帧，本轮因此误判过一次"聚焦失败"）。
3. ★ **CanvasKit 下文字不进 DOM** → `browser_dock_wait text=` 永远超时；读界面只能靠截图或语义树。
4. ★ **出问题先写探针打数据**（临时测试文件 + `print`，用完即删）——本轮 6 个探针各在一轮内定位根因。
5. ★ **凡"两个序列必须一一对应"的映射，测试要逐项断言**，不能抽查（S1 的三验命中骗了我们一整天）。
6. ★ **凡"为显示而注入"的东西，都要检查它会不会改变数据映射**（零宽占位符的教训）。
7. **报告要能被自动化读回就别用 `SelectableText`**；用 `Text`。
8. **删文件前先打印解析后的绝对路径并核对**（本仓约定）。
