## 六、★ 环境与 API 事实（新增，避免重复踩）

1. ★★ **镜像输入框装原始文本 → 插入符位置永远对不上**（原始 `$...$` 与视觉文本不同构）。
   ★★ **但正解不是 `setCaretRect`** —— 2026-10-14 晚读引擎源码实测：**`TextInput.setCaretRect` 在 Web 上是空函数**
   （`// No-op: not supported on this platform.`）。Web 上真正可用的只有三条杠杆：
   `setEditingState`（`element.value` + `setSelectionRange`）、
   `setEditableSizeAndTransform`（`element.style.{width,height,transform}`）、
   `setStyle/updateStyle`（CSS 字体）。
   → 做法：**平台元素里什么都不装**（插入符 = 元素原点）、**把元素摆到光标的精确 x**。
2. ★★ **零宽 `WidgetSpan` 照样占 1 个码元** —— 会破坏依赖段落坐标的映射。
3. ★ **`\cursor` 在文本模式（`\text{}` 内）完全不被接受**（6 种写法全 ParseException）。
   处置：把 `\text{}` **拆成两半**，光标落在中间。
4. ★ **`\cursor{}` 的颜色 = `options.color` = 公式文字色**（不是主题色）→ 裸注入会得到黑光标。
5. ★ **`\sqrt[n]{body}` 的渲染顺序与源码顺序相反**（KaTeX 节点是 `[body, index]`）。
6. ★ **数学字形会画出 Math 根盒之外**（单个 `x`：根盒 7px 高、字形盒 16px）；且 `Rect.contains` **下边界是开区间**
   → "必须在边界内"这类判据会**静默误杀**真原子。
7. ★ **父 widget 的 post-frame 回调早于子 widget 的** → "帧末收集子节点信息"第一帧必然拿不到数据。
8. ★ **自动化输入**：`browser_dock type` 直接插文本（**能**验证文本通道）；
   `browser_dock key` 只发原始按键（不产生 DOM 文本输入）但**能**到 Flutter 的 `onKeyEvent`。
   ★ **IME 组合态现在可以自动验**：设 `textarea.value` + 派发 `compositionstart/update/end` + `input`
   （引擎 `composition_aware_mixin.dart` 就是这么读的）。

## 十一、★ 性能基线（2026-10-14 实测 · 跨平台同一把尺子）

**测法**：演示页「基准(20字)」按钮（`spike/s3_edit/`），在样本 `kEditSample` 上插 20 个字，
用 `FrameTiming` 采每帧的 `build`（Dart 工作量）与 `raster`（像素活），报 p50/p95 + **采到的帧数**。

**环境必须一致才可比：1434×900 视口、`devicePixelRatio = 1.0`、页面可见。**

| | build p50 | build p95 | raster p50 | raster p95 | 一帧合计 p50 |
|---|---|---|---|---|---|
| debug web（DDC/JS） | 6.3 | 13.4 | 8.4 | 10.5 | **14.7 ms** |
| release web（dart2js -O4） | **2.2** | **5.0** | 9.0 | 10.7 | **11.2 ms** |
| 收益 | **2.9×** | 2.7× | ≈1（噪声内） | ≈1 | **1.3×**（余量 2 → 5.5 ms） |

**三条结论（回答"各平台手感"的地基）**：
1. 一帧 = **build（随构建模式/平台变 → 我们代码的成本）** + **raster（与构建模式无关，由显示器缩放与窗口尺寸决定）**
2. 本机屏幕缩放 **150%** → `dpr1.5` 时像素量 ×2.25 → 光栅化 9.0 → 17.2 ms，**完全由像素量解释**。
   → **换 100% 缩放的显示器比换平台的影响还大**
3. release web 的 **build 快 ~3×** 是 **DDC→dart2js** 的收益（**不是** JS→AOT）；
   AOT（Android/Windows）还能再快，**待 Android 实测**（同一个按钮直接跑同一段基准即可）

## 环境与卡点（2026-10-18，**接手必读**）

### 1. Windows 端怎么跑（**2026-10-18 起不再需要管理员**）

**日常三件套**（`scripts\` 下，都免提权）：

| 目的 | 命令 / 双击 |
|---|---|
| **开发实例 + 热重载** | `scripts\dev.cmd`（= `dev_windows.ps1`；`-Device web` 走 Web） |
| **正式形态** | `scripts\build_exe.ps1` → `dist\v<版本>\` |
| **桌面/开始菜单快捷方式** | `scripts\make_shortcut.ps1 -Dev`（写桌面目录 ⇒ 沙箱外，需用户自己跑或助手用完整权限） |

- **热重载**：向 `scripts\cmd.txt` 写一个字符 `r`（`R` 热重启 / `x` 完全重启 / `q` 退出）；
  桥把状态写进 `scripts\state.json`（`phase` + `vmService`），日志在 `scripts\run.log`。
- **管理员只在一种情况下还需要**：`.plugin_symlinks` 缺失且你没跑 `ensure_plugin_links.ps1`
  —— 而 `dev.cmd` / `build_exe.ps1` 都会自动先跑它（用 **junction**，零特权）。
- **旧的 `run_windows.ps1`** 仍可用（直接 `flutter run -d windows`），但不再需要管理员。
- **别用 `Start-Process` 启动 GUI**：子进程继承 stdout ⇒ 命令一直挂着；要用 `cmd /c start "" /D <目录> <exe>`。
- **为什么以前必须管理员**：`flutter build windows` 要给插件建**符号链接**；本机虽然开了「开发人员模式」
  （`AllowDevelopmentWithoutDevLicense=1`），但**令牌没有** `SeCreateSymbolicLinkPrivilege`
  （`whoami /priv` 无此项，**普通窗口也一样**）⇒ `Link.create` 必失败（实测 `errno 1314`，
  Dart 没带 `ALLOW_UNPRIVILEGED_CREATE`）。
  ★★ **2026-10-18 更正（实测推翻旧记录）**：`flutter_tools` **不会**每次删 `.plugin_symlinks` ——
  `flutter_plugins.dart:1272` 是 `if (link.existsSync()) continue;`、调用处 `force=false`
  ⇒ **只有链接缺失时才需要建**。所以：**非管理员构建现在就能跑**（实测 97.9 s 成功）；
  `flutter clean` 之后用 **junction**（零特权，`Link.existsSync()` 认它）补即可，
  见《开发日志\2026-10-18开发循环与自测通道.md》。
  ⇒ **不再需要"每次开管理员终端重编"**。
- **判新旧别看 exe**：debug 构建的 Dart 代码在 `build\windows\x64\runner\Debug\data\flutter_assets\kernel_blob.bin`，
  `mathlang.exe` 的时间戳**不会变**。改了 Dart 必须重编再用（本会话被这个坑咬过三次）。
- **SmartScreen**：exe 未签名 ⇒ 首次启动弹「Windows 已保护你的电脑」，点「更多信息 → 仍要运行」；
  正式发布必须**签名**（S5/发布清单）。

### 2. 用电脑操作插件驱动本应用（探索结论）
- **UIA 只看得到窗口外壳**（`Window / FLUTTERVIEW / TitleBar / 三个系统按钮`，`FLUTTERVIEW` 子节点 0）；
  `ensureSemantics()`（已挪到首帧后、已重编验证）之后**仍然如此** —— 引擎侧
  `accessibility_bridge.cc: Failed to update ui::AXTree, error: 17 …` ⇒ **这条不通，别再投**。
  ★★ **替代通道（已跑通）**：调试版 exe 的 **Dart VM service**，普通 HTTP GET 就能调 RPC
  （`getVM` / `ext.flutter.debugDumpSemanticsTreeInTraversalOrder` / `debugDumpRenderTree` /
  `ext.flutter.inspector.screenshot` / `getInstances` + `evaluate`）
  ⇒ **自家界面的自动化验收走 VM service**；UIA 只用于系统原生对话框。
- **原生对话框是通的**：系统「保存文档」里 `文件名(N):` 编辑框、`保存(S)` 按钮都在 UIA 里
  ⇒ 这条可以走 `computer_find` + `message settext` + `pattern invoke`（纯静默、不抢前台）。
- **血的教训**：`key` 分开发送会**卡住修饰键**——发过 `Ctrl down` 若 `Ctrl up` 落到别的窗口，
  用户那边滚轮就变成页面缩放。⇒ **优先 `pattern > message > 坐标`**；一定要发组合键就**同一个进程原子发完**，
  事后用 `GetAsyncKeyState` 复核。
- `window=activate` 会把窗口**摆进槽位并改几何** ⇒ 之前算的比例坐标全部作废，要么重取，要么改用 `message`。
