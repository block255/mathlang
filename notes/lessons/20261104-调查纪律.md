## 〇、一句话

**"讨论清楚" 只保证口径讲清楚了，不保证事实坐实了。**
讨论产出的是**假设表**；只有在"装配层能走到的终态"上拿到**布尔结论**，假设才变成事实。

## 一、事实：七条假设的下场（复盘用，别只看结论）

## 二、六条纪律

### ① 结论分色：**已实测** / **仅推演**

- **判据**：一条结论要写进方案依据，必须能指出"哪个命令/哪行测试/哪个 `文件:行` 量到了它"。给不出的一律标"推演"。
- **这次的反例**：假设 1。推演本身没错，错在**推演的终点不是真实终点**——它停在"纯函数输出的计划"，没走到"编辑面把计划落到缓冲区之后"。
- **落地**：调查稿每条结论后面加标记；方案表只允许引用"已实测"。推演可以作为"待验证方向"，但不能当成"根因"。

### ② 测量对象分开命名：**用户所见 / 上报值 / 缓冲区语义**

三者是三个不同的东西，**不许互相代言**：

| 名字 | 是什么 | 谁在看 |
|---|---|---|
| **竖条 / 版面** | 真正画出来的 `Container`（宽 1.5）与 `MathCaretPainter.rect`、每个空行槽/单元盒的矩形 | **用户** |
| **上报值** | `DocView.onCaretRect`（喂给 IME 与滚动跟随） | 输入法 |
| **缓冲区语义** | `buf` / `caret` / `isParagraphSeparator` / 合法位点集 | 引擎 |

- **这次的反例**：假设 2 —— 用"上报值"的差异去解释"用户所见"的现象。
- **落地**：报告里每个数字都要带对象名（"竖条 y" / "上报矩形" / "caret 偏移"），不许只写"光标位置"。

### ③ 判据本体 > 记忆简写

- **判据**：只要仓库里有现成判据（`isParagraphSeparator` / `blankRowStart` / `mathRegionAt` / `BlockMarkers.isMathFence`…），就**跑它**，不许用"`\n\n` 的第二个就是分隔符"这种简写。
- **这次的反例**：假设 3。简写漏掉了"**文末空行不是分隔符**"这一条，而文件头第一段就写着。
- **落地**：探针第一段永远先把"语义位置"打印出来（`indexOf` / `isParagraphSeparator` / 行区间），**不手数索引**。

### ④ 先固定复现件，再定根因

- **判据**：动手推根因之前，必须先拿到**能复现的原始件**：原始文件**路径**（或会话 JSON）+ 光标偏移 + 触发序列。重建的"等价文档"**只能用来证伪，不能用来定根因**。
- **这次的反例**：前四轮探针都拿 `test_data` 里那份 **23 字节** .md 当现场；真实现场是**开发版会话文件**里那份 **22 字符**、**4 个尾换行**、`caret=18` 的未命名文档（`dist\v<版本>\mathlang-session.json`，含 `text` / `caret` / `anchor` / `savedText`）。文本不同 ⇒ 前四轮的"实测"都测在另一份文档上。
- **落地**：
  - 未保存文档的现象，**先读会话文件**（`text` + `caret` + `title` + `savedText`）——"关掉再开还复现"通常就是它；
  - 重建件与真实件的差异（多一个尾换行、少一行字）必须**逐字 diff** 出来并写在调查稿里。

### ⑤ "幽灵 / 污染"类结论必须过**两条独立路径同答案**的实验

- **判据**：凡是"同一份文本、行为却不同"的说法，必须做：**同一最终 buffer、两条历史（新加载 vs 就地操作出来）、同一套动作、逐字比 trace**，最后给一个布尔（`MATCH=true/false`）。给不出布尔的，一律降级为"假设"。
- **这次的正例**：这个实验一跑，假设 1 与假设 2 同时被判死（`MATCH=true`，连整棵树的 runtimeType 直方图都一样）。
- **落地**：差分脚本模板见 §四。

### ⑥ 延迟命名

- **判据**：现象先用编号（"A5"）描述；**根因坐实之后**才起名。
- **这次的反例**：把 A1 叫成"幽灵"之后，后面的每条证据都被往"幽灵"上解释（`$$`、过期的盒、页污染），连 A5 也被并进同一个叙事。
- **落地**：交接/台账里"幽灵"这类词只允许出现在**已定性的条目**上。

## 三、两条可复用的取证范式

### 3.1 差分 trace（对付"历史依赖/状态污染"）

```
同一最终 buffer ─┬─ 路径 A：新加载（mount with buffer + caret）
                 └─ 路径 B：就地操作出来（真按键，走 _applyEdit / _commitText）
两条路都跑同一套动作（Enter → ⌫ → 打字 → Enter），每步记：
  缓冲区（转义后逐字）· caret · 竖条矩形 · 上报矩形 · 整棵树 runtimeType 直方图
⇒ 结论只允许是 MATCH=true / false，外加第一处不同的那一步
```

要点：动作要用**真按键/真文本通道**（`sendKeyEvent` / `testTextInput.updateEditingValue`），不要直接改缓冲区——否则又变成"手工应用计划"。

### 3.2 语义位置表（对付"索引靠手数"）

探针开头固定打印一份表，后面所有数字都引用它：

```
doc.length · 每个关键字符的下标（indexOf）· 每一行的 [ls, le) ·
每个候选位点的 isParagraphSeparator · blankRowStart
```

## 四、交付前自查（调查稿写完，逐条打勾）

1. 每条结论都标了 **已实测 / 仅推演**？推演的有没有被写进方案依据？
2. 每个数字都带了**对象名**（竖条 / 上报矩形 / 缓冲区）？
3. 有没有哪条判据是**手写简写**而不是跑仓库里的本体？
4. 复现件是**原始件**（路径 / 会话 JSON）还是我重建的等价物？差异 diff 过吗？
5. "同一文本行为不同"这类结论，有没有做过**两条独立路径**的差分，并给出布尔？
6. 有没有哪个名字（"幽灵""污染""回归"）是**根因没坐实**就起的？
