## 二、这轮立的三条口径（都写进了设计稿或代码注释）

1. **墨迹优先**（批 33）：命中层里，"看不见的带子"不许抢走**看得见的墨迹**。
   ★ 附带一条好问题：`$\frac{a}{b}$` 的最左墨迹从 x=1.92 起、确实在 4px 带里 ——
   原来那两条"内侧 0/2px ⇒ 段首"的期望**没翻**，是因为采样点的 y 恰好在空白处。
   所以新守卫改成"取**最左字形盒中心**去点"，直接钉判据本身。
2. **只画参数内容、自己不画东西的包装 ⇒ 透明**（批 36）：
   `\text` / `\textbf` / `\mathrm` / `\textcolor` … 不构成"一层空位"，不配"进入/退出"。
   判据在代码里**早就有**（`math_nav._kFontOnlyCommands`，方向键一直当它透明），
   这轮只是把 ⌫ 接上。
3. **可见容器照旧"只跳不删"**（`\frac` / `\sqrt` / 环境 / `\left…\right`）：
   它们画了分数线 / 根号 / 括号 —— 看得见边界才是"一层空位"。

## 三、三条方法论教训（比修好的 bug 更值钱）

1. **判"坏没坏"要用真引擎，不要用自己写的结构检查器**。
   批 34 我先写了个正则检查器（花括号 / `\left\right` / `\text` 缺参数）—— **一个都没抓到**，
   因为坏法是"命令名被劈成 `\ext`"，不在这几类里。换成 `Math.tex(onErrorFallback:)` 立刻现形。
2. **复现要用"真文档 + 真按键"**。
   批 34/35 的关键一步是**读应用自己写的 session 文件**（`dist\v1.0.0\mathlang-session.json`）
   拿到用户当时那份原文，再用 `sendKeyEvent` 走真实按键路径 —— 手搓样本复现不出上下文。
3. **判"不是同一个根因"之前，先确认测的场景就是用户点的那一处**。
   我曾判"④ 不是配对"——**判据是对的**（孤立测 `\frac{1}{M}` 永远绿），**场景取窄了**：
   他点的是"带 `\text{ 时 }` 的那一整块里的分式"，那块整份配对失败。

★ 另外两条操作性的：
- 探针里**必须先避开连击判定**（`_onTapReport` 用 `DateTime.now()` + 6px 判连击）——
  逐像素连点会被算成双击/三击，表现为"选区"或"落点跑到别处"；做法是相邻采样点相距 ≥7px。
- PowerShell 里写 Dart 用例：`${...}` / `$var` 会被 PS 先吃掉 ⇒ 用 `write` 工具落文件，别用 here-string 拼。
