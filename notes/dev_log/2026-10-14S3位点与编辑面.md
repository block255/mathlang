## 四、★ 今天最值钱的 8 条经验

### 1. ★★ 警惕"**为了显示而注入的东西**"反噬数据映射
"点击 → 光标"的换算本来是纯几何问题，却被**我们自己为了显示光标插入的零宽 `WidgetSpan`** 破坏了：
它在段落里**照样占 1 个码元**（只是不占宽度）→ 段落坐标比映射表多一格 → **整体偏 1，且偏移量随光标当时的位置漂移**
→ 用户看到的现象是"**点哪儿都没规律**"。
**可推广的检查**：凡是为渲染而注入的占位/标记/包装，都要问一句"它会不会改变数据映射所依赖的那套坐标？"

### 2. ★★ "抽查通过"不等于"正确"，**失效还可能是静默的**
S1 对"点屏幕 → 源偏移"做过"**三验命中**"，但那是**在一个公式上**验的。
今天换 6 个样本一测：**5 个失效**（叶盒数与原子数不等），而失效的表现只是"**点了没反应**"（返回 null，不报错）。
→ 现在 `test/render/leaf_boxes_test.dart` 把它写成 **9 个公式 × 3 条断言**（数量一致 + 命中可靠 + **逐盒逐原子**验证左右边界）。
**可推广**：凡"两个序列必须一一对应"的映射，测试要**逐项断言**，不能抽查。

### 3. ★★ 引擎的边界假设必须**实测**，不能读文档/读注释
今天又推翻 4 条（详见 §三），其中两条直接来自"想当然"：
- "真原子的矩形必然落在 Math 控件边界内" —— **假**。数学字形本来就画出根盒之外
  （单个 `x`：根盒才 7px 高，字形盒 16px 高）；而且 `Rect.contains` 的**下边界是开区间**，压在边界上的分母盒也被误杀
- "`\cursor` 是引擎内置命令，哪儿都能用" —— **假**。文本模式里必炸

### 4. ★★ 自动化**能验管道、验不了手感**
| 工具 | 实际行为 | 能验 |
|---|---|---|
| `browser_dock type` | 直接插入文本（CDP `Input.insertText`） | 文本通道 ✓ ／ 键事件 ✗ |
| `browser_dock key` | 只发原始按键，**不产生 DOM 文本输入** | 功能键到达 ✓ ／ 打字换行 ✗ |

→ **字符类编辑效果（打字、`Enter` 换行、IME 组合）只能靠真人键盘验**；
而"坐标 → 偏移""位点表""结构删除"这类**纯计算该搬进 widget 测试**（本轮 66 条新测试里绝大多数是这类）。

### 5. ★★ 架构层的负面结论：**镜像输入框装原始文本，插入符永远对不上**
镜像框里是**原始 md+LaTeX**（含 `$...$`），而屏幕上是**渲染后的视觉文本** —— 两者**不同构**，
所以镜像框自己的插入符/下划线位置由它自己的排版决定，**摆到哪都对不上**（用户截图：黑下划线在公式下方、蓝光标在公式里）。
→ 正解是 `TextInputConnection.setCaretRect()`（SDK 已确认存在，`EditableText` 就是这么干的）：
**自己实现 `TextInputClient`，把我们的光标矩形告诉平台**。
**可推广**：凡"用另一个控件代理输入"，先问"它的内部坐标系和我的视觉坐标系同构吗？"

### 6. ★ 父 widget 的 post-frame 回调**早于**子 widget 的
想在"帧末收集子节点信息再统一计算"，**第一帧一定拿不到数据**（父 `build()` 里注册的回调，
在框架挂载子节点**之前**就注册了）。表现为"首帧数据为空"，第二帧才正常。
→ 要么接受晚一帧，要么把收集挪到下一帧再算。

### 7. ★ 排障先写**探针**，别猜
今天 6 个探针（位点表、盒序↔原子序、叶盒过滤、列表项点击、`\text` 注入、光标矩形），
**每一个都在一轮之内定位了根因**。反面对照：两次"先猜再改"都白改了一轮。
探针的形态：**一个临时测试文件，把关键数据 `print` 出来**，用完立刻删（今天删了 6 个）。

### 8. ★ 没有 git 的代价开始显现

→ **建议把建仓库提前到 S3 收工前**（哪怕只 `git init` + 首次提交），大改才有退路。
→ ✅ **当天已建**：仓库根 = **项目根** `projects\mathlang\`（**不是 `app\`** —— 本项目要把 `notes\` 一起管起来，

## 四之二、★ 晚间续摊：输入层重做又添的 7 条（2026-10-14 晚）

白天收工时定的方案是"自实现 `TextInputClient` + `setCaretRect`"。晚上动手前**先读了一遍引擎源码**，
结果第一条就被推翻 —— 这批经验几乎全是**"先验通路、再写代码"**的胜利。

### 9. ★★★ 定方案前**先读源码**：`setCaretRect` 在 Web 上是**空函数**
```dart
class TextInputSetCaretRect extends TextInputCommand {
  void run(HybridTextEditing textEditing) {
    // No-op: not supported on this platform.
  }
}
```
SDK 的 Dart 侧注释也只说它是给 macOS 放重音候选菜单用的。
→ **要是按原计划写，就是白写一遍**（而且会以为"接了没效果"是别的原因）。
→ 读完源码才拿到真正可用的三条杠杆：`setEditingState` / `setEditableSizeAndTransform` / `setStyle`。
→ 顺带把做法从"把光标矩形告诉平台"改成"**把平台元素摆到光标的精确 x**"（元素里什么都不装）。

### 10. ★★ 探针的**通路**必须先验证：`debugPrint` 在 Web 上不进 `run.log`
加了探针、让用户打了一遍中文，去读 `run.log` → **0 行**。
差一点得出"事件根本没送到 Dart"的错误结论 —— 实际上 Flutter Web 的 `print`/`debugPrint`
走**浏览器控制台**（`web-server` 设备不会转发到终端）。
→ 教训：**探针要先用一次已知会触发的事件验证"我能读到它"**，再拿它做判断。
（读法：`browser_dock console`。）

### 11. ★★★ "基线代表什么"这种语义错误，一行就能丢掉用户输入
用户报"汉字和中文标点输入后消失，英文正常"。控制台探针给出铁证：
```
① {text: hao'de'hao'de, composing: 0..14} → 组合中，不写缓冲区
② {text: 好的好的,       composing: 0..4 } → 组合中，不写缓冲区   ← Chrome 选字**先把拼音换成候选词、但仍标组合中**
③ {text: 好的好的,       composing: none } → 提交路径 {edit: none, willInsert: }  ← 提交的词被自己吃掉
```
根因：我在 ② 把"基线 `_platformText`"更新成了**平台当下的文本**；而基线的正确含义是
「**缓冲区对应的那份平台文本**」（组合串从来没进过缓冲区，所以它也不该进基线）。
→ 教训：**diff 的"旧值"必须是"我的数据结构里对应的那份"，不是"对方此刻拿着的那份"** —— 两者在中间态下不同。

### 12. ★★ `mounted` 在 `dispose()` 期间**仍然是 `true`**
`dispose()` → `controller.dispose()` → `detach()` → `notifyListeners()` → 监听器 `setState()`
→ 断言 `_lifecycleState != defunct` 炸掉，**175 条里 166 条跟着挂**（连锁）。
→ 修法：**先摘监听，再 dispose 控制器**；并加 `_alive` 标志兜底。
→ `mounted` 挡不住这一类，别拿它当万能保险。

### 13. ★★ 测性能要**核对环境**：`browser_dock resize` 会改变 `devicePixelRatio`
第一轮对比得出"**release 的光栅化比 debug 慢 2 倍**"—— 反直觉但数据很像真的。
继续查才发现：debug 那次是在 `dpr=1.0` 下测的，release 那次是 `dpr=1.5`
（本机屏幕缩放 150%）→ 像素量 **2.25 倍** → 光栅化 9.0 → 17.2 ms，**完全由像素量解释**。
拉齐环境重测：**光栅化基本没变，Dart 侧的 build 快了 2.9×**。
→ 教训：**跨测量对比必须核对 DPR 与像素量**，否则会把环境差异写成代码结论。
→ 附带结论：**光栅化是"环境成本"（显示器缩放/窗口尺寸），构建模式几乎不影响它** ——
换台 100% 缩放的显示器，比换平台省得还多。

### 14. ★★ 等待要用**可验证**的方式：`await endOfFrame` 在页面隐藏时会**永远挂住**
基准跑到第 2 个字就不动了、单次 2007 ms。查 `document.visibilityState` → **`hidden`**：
Flutter Web 在页面不可见时**停止出帧**，于是 `endOfFrame` 永不完成。
→ 改成固定节拍（`Future.delayed`），并**同时上报"采到多少帧"** —— 让坏测量**可见**，
而不是悄悄给一个假数字（第一版还因为"等 2 帧"把 33 ms 的 vsync 等待算进了"延迟"）。

### 15. ★ 合成组合事件可以**驱动**引擎 → IME 链路能自动验
`flutter_web_sdk/.../composition_aware_mixin.dart` 读的是
`compositionstart/update/end` + `input`，并且 `composingBase ??= extentOffset - composingText.length`。
→ 手动设 `textarea.value` + 派发这几个事件，引擎就会把组合态发给 Dart。
→ **"IME 只能靠真人键盘验"这条旧结论作废**（剩下只有"候选框位置"必须真人看，因为那是操作系统画的窗口，截图里没有）。

### 16. ★ 细线在压缩截图里会**消失**
光标只有 2×8 px，JPEG 压缩后变成灰蓝（`rgb(90,115,145)`）。
识图模型说"没有光标"，我写的窄颜色窗口也说"0 个像素" —— **两次误判**。
后来**先扫全图校准阈值**才捞到那 11 个像素。
→ 像素级验证要用程序扫，并且**先校准**；别用肉眼 + 压缩截图 + 识图模型下"有/没有"的判断。
