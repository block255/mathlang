## 一、结论先说：管理员只需要**一次**，而且现在已经被拆掉了

| 探针 | 观测 | 结论 |
|---|---|---|
| 非管理员会话直接 `flutter build windows --debug` | `√ Built ...mathlang.exe`，**97.9 s**；`IsInRole(Administrator) = False` | **不需要管理员** |
| 读 flutter_tools 源码 `flutter_plugins.dart:1255 _createPlatformPluginSymlinks` | `if (link.existsSync()) { continue; }`；调用处 `project.dart:445 refreshPluginsList(...)` **没传 `force`** | **不是"每次删了重建"**，只有缺失时才建 |
| dart 探针 `Link.createSync`（开发者模式已开 `AllowDevelopmentWithoutDevLicense=1`） | `FileSystemException: Cannot create link ... (OS Error: 客户端没有所需的特权。, errno = 1314)` | Dart **没带** `SYMBOLIC_LINK_FLAG_ALLOW_UNPRIVILEGED_CREATE` ⇒ **开发者模式救不了**；唯一出路是"令牌里有权限"或"链接已存在" |
| 目录联接兜底 `New-Item -ItemType Junction`（**零特权**） | dart:io 看到 `Link.existsSync()=true`、`typeSync(noFollow)=link`、`targetSync` 正常 | ⇒ **`flutter clean` 之后也能重建**，不需要管理员 |

**为什么以前必须管理员**：第一次构建要建 `windows\flutter\ephemeral\.plugin_symlinks\<插件名>`，
那一刻确实缺权限 ⇒ 必须提权。建好之后，只要它不被删，后续所有构建都是普通权限。

### ⚠️ 更正交接快照
> 快照「环境与卡点 §1」写的是：「`flutter_tools` 每次构建还会先删 `.plugin_symlinks` 再重建 ⇒ 预建 junction 无效」。
> **这条是错的**（源码 `force=false` + 实测构建后链接原样保留）。正确表述：
> **只有当 `.plugin_symlinks/<插件名>` 缺失时才需要建链接**；`flutter clean` / 改 `pubspec` 引入新插件 / 换 pub 缓存目录，
> 才会重新触发 ⇒ 用 `scripts\ensure_plugin_links.ps1`（junction）兜底即可。

## 二、热重载通道：Windows 桌面端也能"文件指令驱动"

| 步骤 | 实测 |
|---|---|
| `flutter run -d windows`（`cwd = app\`） | 启动 + 同步 **25.1 s**，VM service 打印在 stdout |
| 向该进程 stdin 写一行 `r` | `Performing hot reload... Reloaded 0 libraries in 854 ms` |
| 窗口信息（`computer_window`） | 标题 `mathlang`、类 `FLUTTER_RUNNER_WIN32_WINDOW`、1920×1080、`integrity: Low` |

⇒ 把 `scripts\hotreload_bridge.js` 的 `-d web-server` 参数化之后，**改完一行 Dart 代码 = 我写一个字符**，
你屏幕上那个窗口原地变新版（内容、滚动、光标都保留），不需要关窗、不需要重启、不弹 UAC。

> 与 Web 的差别：Web 桥要 `--web-port`；桌面不需要。`x`（完全重启）在改 `pubspec` / `assets` 之后仍然需要。

## 三、自动化通道实测（决定"后期测试"怎么打）

### 3.1 UIA 对本应用是瞎的（复验）
`computer_find` 在 mathlang 窗口里只拿到 **8 个元素**：`Window` / `Pane:FLUTTERVIEW` / `TitleBar` / 系统菜单 /
`Minimize` / `Maximize` / `Close` —— **画布内部一无所获**（引擎侧 AXTree 更新失败，见快照）。
⇒ 插件**不能**像对原生程序那样"找按钮 → invoke"。

### 3.2 但 Flutter 自己的语义树**完整可读**（这是测试主力）
```
curl.exe -s "http://127.0.0.1:<port>/<auth>=/ext.flutter.debugDumpSemanticsTreeInTraversalOrder?isolateId=<iso>"
```
能读到：每个按钮的 `label` / `tooltip` / `Rect`；数学原子各成节点（`x` `2` `+` `1` 分别有 label）；
文档块文本；状态栏 `共 1 页 · 200 字符 · 光标 0 · 0 次编辑`。
⇒ **界面状态可以被断言**，而且零点击、零截图、不打扰用户。
⇒ 顺带说明：**S4-e 的可访问性比预想的好**（按钮全都带 label/tooltip），这块的工作量应下调。

### 3.3 两个必须记住的坑
1. **PowerShell 的 `Invoke-RestMethod` 打 VM service 会 403**（`curl.exe` 打同一个 URL 是 200）⇒ 一律用 `curl.exe`。
2. **`evaluate`（表达式求值）不可用**：`code 113 "No compilation service available; cannot evaluate from source."`
   ⇒ **不能**靠"注入一段 Dart 代码"来点按钮/读字段；能用的只有 `getVM` / `getIsolate` / 扩展 RPC（semantics、render tree、inspector）。
   （`getInstances` + `getObject` 这类纯读取仍然可用。）

### 3.4 定向消息注入：**鼠标有效、字符无效**（本轮新发现，零特权、不抢前台）
对 `FLUTTERVIEW`（hwnd 657554）`PostMessage`：
- **`WM_LBUTTONDOWN` + `WM_LBUTTONUP`（lParam = y<<16|x）⇒ 生效**：光标从 0 跳到 201，前台窗口**未变**；
  坐标是客户区物理像素（视口 1898×1024，逻辑 1265×683，×1.5）。
- **`WM_CHAR` ⇒ 不可靠**：① 发 `'a'` 后立刻读状态仍是 `200 字符 / 光标 0`；② 随后一次鼠标点击让状态变成
  `201 字符 / 光标 201` —— **无法确认这 1 个字符是迟到的 `'a'`，还是点击落在空格子造成的别的变化**；
  ③ 再单独发 `'b'`，状态 `201 → 201` **明确无效**。
  ⇒ 结论：**字符消息不能作为打字通道**（Flutter 只在视图有焦点时收字符，而抢焦点正是我们要避免的）。

⇒ **可以静默点击任意位置**（用语义树的 `Rect × dpr + 客户区原点` 算屏幕/客户区坐标），
   但**不能静默打字**。要验"打字/输入法"必须走真实键鼠（`interact` 档 + 信任）——那会抢前台。

### 3.5 截图：`computer_see` 的 `PrintWindow` 能截到我们的画面
实测 `source: printwindow` 得到完整文档画面（不是黑屏）⇒ 可以作为"看画面"的兜底
（更干净的路子仍是 VM service 的 `ext.flutter.inspector.screenshot`）。

## 四、由此定的分工（后期测试怎么打）

| 要做的事 | 用谁 |
|---|---|
| 读界面状态 / 断言（页数、字符数、光标、按钮位置、数学原子） | **VM service 语义树**（一条 curl） |
| 精确点击任意位置（不抢前台、不打扰你） | **`PostMessage` 鼠标**（坐标 = 语义树 Rect × dpr） |
| 打字 / 中文输入法 / 快捷键 / 拖选 / 滚轮 | **电脑操作插件 `interact`**（要授权；唯一能验 IME 的路） |
| 打开 / 保存 / 选目录 等**系统原生对话框** | **插件 `computer_find` + `message setvalue` + `pattern invoke`**（静默） |
| 窗口标题 / 几何 / 最小化最大化 / 多屏 | **插件 `window`**（`set_bounds` 不抢前台） |
| 看画面 | 优先 VM service 截图；兜底 `computer_see` |
| 改代码 → 生效 | **热重载桥**（`r`） |

★ 如果后期发现"静默打字"是刚需，还有一个**可选**方案：调试版加一个**测试钩子扩展**
（`ext.mathlang.test.tap/type/read`，用 `assert` 或 `kDebugMode` 门控，release 不编译进去）——
它能让自动化完全不碰系统输入队列。代价是应用里多一段测试专用代码，**要不要做由用户定**。

### 4.1 可复用的最小闭环（详细命令见操作指南）

```
computer_window {filter:mathlang}  → handle
run.log 里抓 VM service URL        → getVM → isolateId
curl 语义树                        → 基线（页数 / 字符数 / 光标 / 目标按钮 Rect）
Rect × dpr + 客户区原点            → PostMessage down/up
curl 语义树                        → 断言变化
要改代码 ⇒ scripts\cmd.txt 写 'r'  → 热重载后重来
```
⇒ 这一套是**后期自动测试的默认姿势**：读用语义树、点用消息、看用截图、改码用热重载。

### 5.1 这一批踩出来的四个坑（都会再咬人）

1. **`.ps1` 没有 UTF-8 BOM ⇒ 中文注释会吞掉下一行**：PowerShell 5.1 按 ANSI 读无 BOM 脚本，
   一行以多字节汉字结尾的注释会把换行吃掉 ⇒ 下一行赋值语句**变成注释的一部分**（本次表现为
   `$dsTop` 是 `$null`，`LinearGradientBrush` 报 "找不到 4 个参数的重载"）。**所有 `.ps1` 必须带 BOM**。
2. **`main.cpp` 里的中文注释 ⇒ `C4819` ⇒ 构建直接失败**：Flutter 的 Windows runner 把警告当错误，
   MSVC 用代码页 936 读 UTF-8 源文件就报"包含不能表示的字符"。**runner 的 C++ 源码保持纯 ASCII**，
   中文标题用 `L"\u6570\u8bed\u5f15\u64ce"` 转义（`Runner.rc` 有 `#pragma code_page(65001)`，那边可以写中文）。
3. **`Start-Process` 启动 GUI 程序会让命令一直挂着**：子进程继承了 stdout 管道，工具侧等不到 EOF。
   要"脱手启动"用 `cmd /c start "" /D <目录> <exe>`。
4. **桌面/开始菜单快捷方式要写到沙箱外**：`%USERPROFILE%\Desktop` 不在工作区授权内 ⇒
   `make_shortcut.ps1` 必须由用户自己跑，或让助手用完整访问权限跑。
