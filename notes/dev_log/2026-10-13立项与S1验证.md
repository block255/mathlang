## 踩到的坑（已解决，值得记）

1. **包入口文件名 ≠ 包名**：`flutter_math_fork` 的库文件是 `lib/flutter_math.dart`，所以必须写
   `import 'package:flutter_math_fork/flutter_math.dart';`
   写成 `flutter_math_fork.dart` 会让 `Math` / `SelectableMath` / `MathStyle` 全部报"未定义"（编译期才发现）。
2. **沙箱边界（重要，影响所有后续开发）**：本机受限沙箱下，`flutter` 与 `dart` 的**任何命令**都会失败
   （`CreateFile failed 5` / `ProcessException: 拒绝访问`），因为它们用**管道**拉起子进程（git、分析服务器、gradle）。
   - 环境变量重定向（PUB_CACHE / TEMP / LOCALAPPDATA / GRADLE_USER_HOME + `FLUTTER_SUPPRESS_ANALYTICS`）是**必要但不充分**条件
   - `dart analyze` 也不例外（它会拉起 analysis_server）
   - 另：`dart` CLI 的遥测路径写死 `%APPDATA%\.dart-tool\`，`FLUTTER_SUPPRESS_ANALYTICS` 对它无效；把 `APPDATA` 重定向进工作区可绕过（但要跑分析仍会被管道挡住）
   → **结论：开发本项目的会话建议直接使用完整访问权限**，否则每条 flutter 命令都要单独放行

# 同日 23:00 · ③ 走路线 (b) 完成：零 src 依赖的"点屏幕 → 源偏移"

**结论：三处抽查全部命中预测值，**混排公式的点击定位真的可用了**（光标落进被点的位点，视觉取证：光标在根号内）。**

| 点击位置 | 命中叶盒 | 可见原子 | 源偏移 | 实测 |
|---|---|---|---|---|
| 分子 `a` | #0 x=2..10 | `a` [6,7) | 16+6 | **22** ✅ |
| 分母 `b` | #1 x=4..15 y=15..29 | `b` [9,10) | 16+9 | **25** ✅ |
| `√2` 里的 `2` | #3 x=56..66 | `2` [18,19) | 16+19 | **35** ✅ |

**做法**：渲染侧遍历 `Math` 的渲染子树收"叶盒"；结构侧用**自写的「可见原子扫描器」**把 tex 词法化成 (可见原子, 源区间)；两侧按同一次序 zip（引擎保证 `children` 顺序 = 光标访问顺序）；取命中盒左/右边界。

**两个必须过滤的"假叶盒"**：① 根号分隔符（`localToGlobal` 尺寸失真、且 AST 里不是子节点）→ 用"必须在控件边界内"滤掉；② 我们自己注入的 `\cursor{}` 光标条（宽 1.5px）→ 用"宽度 ≥ 2px"滤掉。

**引擎坑（重要）**：`GreenNode.getRange(pos)` 返回 `TextRange(start: pos+1, end: pos+capturedCursor)`，`capturedCursor = editingWidth - 1` → **单字符叶子区间是 `[pos+1, pos)`（反的）**；而且 `range`/`caretPositions` 是**渲染空间**坐标（只覆盖渲染出的原子，**不含 `\frac{}`/`^`/`_`**）——实测 `\frac{a}{b}=\sqrt{2}` 给出 `[2,3) [4,5) [6,7) [8,9)`，**不是源码下标**。→ **源偏移必须自己词法化**。

**测试配方（本轮最有价值的操作经验）**：**语义树一开，CDP 坐标点击就失效**——Flutter 语义 DOM 覆盖层把点击退化成"点该元素中心"（点三处不同位置返回同一个局部坐标 (32.8,12.1) = 公式段中心，害我误判很久）。解决：注入
`flt-semantics, flt-semantics-container, flt-semantics-host { pointer-events: none !important; }`
→ **语义树可读 + 坐标点击精确**，两者兼得。

# 同日 23:06 · ④ release 复测：打字延迟 8 ms/帧，架构承诺在产品形态下成立

**做法**：`flutter build web --release --no-web-resources-cdn`（canvaskit 自带、完全离线；73.6 s，`main.dart.js` 2.9 MB）→ **新写的 `scripts/serve_web.js`**（极简静态服务器，57136）→ 浏览器跑同一套探针。

| 项 | debug | **release** | 倍数 |
|---|---|---|---|
| 10 行含公式 | 173 ms | **65 ms** | 2.7× |
| 25 行含公式（≈A4 一页） | 334 ms | **160 ms** | 2.1× |
| 100 行含公式 | 998 ms | **559 ms** | 1.8× |
| 100 行纯文字 | 130 ms | **97 ms** | 1.3× |
| **⑤ 单公式重绘（打字延迟）** | 28 ms | **8 ms** | 3.5× |

- ★ **8 ms/帧 < 16.7 ms（60Hz 一帧预算）** → "只重绘变化的那一个公式"这条架构承诺**在产品形态下成立**。
- **页级预算 ≈160 ms**（A4 一页 25 行，一次性可缓存）；**100 行 559 ms → 一帧渲染整篇仍不可行**，按页渲染是必需的。

**踩到的方法学坑（重要）**：
1. release 下**第一次** ④ 测量给出 `100行含公式=1202ms / 100行纯文字=9320ms` —— **纯文字比含公式还慢 15 倍，明显不可能**；**复测即恢复正常** → **release 基准必须先预热再取数**，且要先用"内部自洽性"（单调性/纯文字应远快于含公式）筛一遍。
2. 曾怀疑"后台标签 rAF 节流"造成 1000 ms 级假数据 → **实测 rAF 间隔 4 ms（~250 fps），无节流**，排除。
3. **状态栏文字变长会让工具栏 Wrap 重排**，开关坐标随之平移 → 盲点坐标会点到隔壁按钮（本次连点两次"面板：上标"，把缓冲区 51→63）。**每次点击前重新取坐标**。
4. 新增资产：`scripts/serve_web.js`（可复用的 release 预览服务器：`node serve_web.js <端口>`）。
