## 一、上午：把"打地鼠"钉死

### 1. 之前三天为什么会打地鼠

10-25 ~ 10-27 共 13 个提交，全在"光标落在哪 / 分页在哪儿"之间来回，同一片返工 ≥5 次。
回头看，根因只有一条：**同一件事有两套口径**。

| 症状 | 当时以为 | 真相 |
|---|---|---|
| 连按 Enter 不长高 | "空行没占排版" | 高度表说"文末每个空行都是一行"（`n × 行高`），行表却 `skip(1)` 掉第一个 ⇒ 两套口径 |
| Enter 第一下光标不动 | "光标没跟上" | 同上：光标落在一格"行表里没有、高度表里有"的位置 |
| 用户"光标在这儿、字却低一截" | "字体度量问题" | 光标少了**行内内缩 3.6**（(27.2 − 20)/2） |
| 光标落在"文末那行上面的间距处" | 我以为要"扫全篇找空行" | **文末下一行一直是常驻行**（旧提交注释里就写着 `= buf.length`），我推翻了已定结论 |

### 2. 转折点：用户写了"只读基准"

用户亲自写了 `notes/design/只读基准.txt`（**AI 只读**，只有他能改），7 条纯行为描述。
从那一刻起，规格的权威顺序变了：

```
只读基准（用户）  >  行与段-空行基准.md（规格+实测，每条标出处）  >  handover（历史事实）
```

我做的第一件事是**对账**：把 7 条逐条对到代码/探针上，每条标 `〔用户〕/〔实测〕/〔推断〕`
——**我推断的不得冒充基准**。这一步直接消掉了后面所有的扯皮。

### 3. 结果：一把尺子 + 一次改一批

```
行顶 y = 槽顶 + 段间距 + k × 38.4 + 行内内缩 3.6
行盒 27.2（字号 16 × 行距 1.7）· 段间距 11.2（字号 × 0.7）· 一行 38.4
```

八项改动一次做完、只跑一次 analyze + 全量 + 构建 ⇒ **一次没返工**（落点那三次是**我的推断错**，
不是模型冲突）。**教训：发现"两套口径"就是发现 bug；先统一口径，再谈手感。**

### 4. 下午的延续：段间距不是位置

用户手测发现"两段之间的**段间距**能当容器行把光标放进去"。查证：

```
A⏎⏎B：分隔符那一格被画在 126.2 = 上一行行盒底(122.8) + 3.6
        而下一段真实行顶在 133.8      ⇒ 差 11.2 = 段距
```

根因不是渲染错，是**我 10-26 立的那条全域守卫写错了**：
「每个**偏移**至少有一根光标」——它逼着渲染层给"零高度的段落分隔符"编一个 y。

改成「每个**视觉行**一个光标 + 分隔符那一格一根都不许有」之后，同一个现象**自然消失**。
**教训：不许用实现迁就一条错的断言。**

## 二、下午：发布链的四次打脸（这次是"实测 vs 我的假设"）

这一段的性质是**环境事实**（Windows/MSIX 的行为），每一次我都是"想当然 → 被实测打回"。

| # | 我的假设 | 实测打脸 | 真正的修法 |
|---|---|---|---|
| 1 | `runFullTrust` ⇒ 联网不受限，检查更新能通 | 用户点检查更新报"网络不可用"（但他网是好的） | 不是网络：hosts 把 `api.github.com` 劫持到 `127.0.0.1`（S302 加速工具），工具没应答就拒连。**顺带把"失败原因"从一句"网络不可用"改成具体原因** |
| 2 | 下载进度弹窗里写"走的是本机加速通道" | 那是**写死的文案**，没开工具时它照样这么说 | 改成真探测：`InternetAddress.lookup` 得到 loopback ⇒「本机加速工具」，否则⇒「正在尝试连接 GitHub」 |
| 3 | MSIX 允许"边跑边装"（所以设计了"更新完→立即重启"） | `0x80073D02`：**资源正在使用，需要关闭 MathLang.Editor** | 改成**外挂小助手**：主程序退出 → 小助手装 → 起新版；"更新完成"弹窗改到**下次启动** |
| 3b | 用 `Process.start(powershell, detached)` 起小助手就行 | 脚本写出来了却**一次都没跑**（无 result/log）；控制台手跑同一个脚本立刻成功 | **MSIX 的 Job 会杀掉我们的子进程** ⇒ 改成 `explorer.exe <cmd>` 中转（父是 explorer，不在我们 Job 里）。代价：闪一下黑窗 |
| 3c | `powershell -File x.ps1 -WaitPid $pid` 能传 PID | `-File` 的实参**不做变量展开**，`$pid` 是字面量 ⇒ 参数绑定报错、脚本一行没跑 | 脚本**不带任何参数**，自己睡 2.5 s |
| 4 | 设置写入 `%APPDATA%\mathlang\` 就"出包"了（卸载不丢） | 真实 APPDATA 文件**不存在**，字节全在 `Packages\<包族名>\LocalCache\Roaming\` ⇒ **MSIX 连 %APPDATA% 也虚拟化** | 改成 `%USERPROFILE%\mathlang\`（配置根下的自定义文件夹，不在虚拟化名单）＋ 老数据自动迁移 ＋ `describe()` 回头校验文件真的存在 |

**这一段的教训（和上午正好互补）：**
- 上午的错是"**模型没定清**"⇒ 解法是**先立基准、再改代码**；
- 下午的错是"**我拿假设当事实**"⇒ 解法是**先量一下再说**（一条命令就能量的东西，别推理）。

## 四、留给后面的三条

1. **C1 的"首次安装"分支仍未验**：本机证书早已在信任库，永远走"零 UAC"那条。
   要么找一台干净机器，要么按 handover 里的命令删证书再装一次（应当只弹**一次** UAC）。
2. **更新时闪一下黑窗**：这是 explorer→cmd→powershell 那条链的代价。若以后嫌难看，
   可换成 `wscript.exe` + 隐藏的 `.vbs`（同样挂在 explorer 名下，但无控制台）。
3. **`pack_msix.ps1` / 任何 `.ps1` 改完必须复查 BOM**（前 3 字节 = 239,187,191）：
   这一天又踩了一次（`edit` 会把 BOM 吞掉）。
