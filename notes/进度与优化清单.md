## 3. 这个阶段的节奏（与开发守则 §六 配套）

1. **你报现象**（越具体越好：点了哪里、期望什么、实际什么、能不能稳定复现）；
2. **我先定位根因**（写探针、看数据，不做表面修补；不靠猜）；
3. **对齐修法**（改什么 / 影响面 / 怎么验收），你说"可以"；
4. **一批实现 → 一次验证**（`analyze` + 全量测试 + 改前必红的变异证据）；
5. **收尾三件套**：设计稿回写 → 交接快照 → 提交。

★ 优先级判据：**"影响每天都用" > "影响偶尔用" > "纯观感"**。
★ 一次只动一处**语义**：同一份语义如果有两条写入路径，必须走同一个判据（本仓已经栽过三次）。

## 6. 优化候选（按"影响每天都用"排序）

1. **性能**：Windows 上的 AOT 真实数字（用现成的 `FrameTiming` 基准）；长文档（>5 页）打字帧率；分页耗时（现在全量测量）
2. **可访问性 / 键盘流**：面板与快捷栏的 `Tab` 循环 + 回车插入（现在只能点）
3. **移动端**：软键盘、快捷栏底部、fit-width 缩放
4. **手感细节**：光标两侧竖直中心那 3px 偏差（文本侧行盒居中 vs 数学侧基线摆）
5. **视觉**：页边距/页眉的最终配色与字号（等试用反馈）
6. **工程**：`flutter test` 里"量几何"必须装真实字体（已有 `test/support/math_fonts.dart`，新测试别忘）
